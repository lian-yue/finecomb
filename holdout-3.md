This record lists all 97 samples of held-out round 3, so they can be looked up later by ID, component or root-cause facet. The summary numbers are in the main README under [How coverage is validated](https://github.com/lian-yue/finecomb#how-coverage-is-validated).

## What this round is

- Test date: 2026-09-25.
- Skill under test: the English skill `skills/finecomb/`, as it stood after the six new root-cause facets and the five new questions in existing facets were added, and before the round 3 fixes listed in the "Where the gap was fixed" column.
- Held-out samples: 97 vulnerabilities in 9 groups, none of them used to write the skill. Each sample's ID and event name was searched for in the skill directory, in the records under `validation/`, and in the notes of earlier test rounds and of the other round 3 groups; none appeared. Where a product name did appear, it appeared only for another root cause. No sample is from the Linux kernel or nginx. 93 samples are open source; 4 are closed source (the Microsoft SAS token, Hugging Face namespace reuse, Google Pixel Markup and Windows tcpip.sys).
- Four groups are facet-targeted (48 samples). Each picks two samples per facet whose root cause belongs to that facet, to check that the facet still leads to the root cause in a new domain:
  - New root-cause facets: "Who can loosen a restriction", "Authority beyond the job", "Choosing after seeing", "Shared state across trust levels", "Which candidate a name resolves to", "Values that must not be guessable".
  - New questions in existing facets: the new question in each of "Interpreting failures and special values" (special values sent by the other side), "Binding and context" (reads by position or at an assumed fixed offset), "Multiple representations of the same fact" (escaper and interpreter split input the same way), "Protocol and format conversion" (incremental change or full replacement), "Old valid versions accepted again" (grants already issued after an authoritative change).
  - Facets with few samples, part A: "What a limit is bound to", "Completeness of equivalence checks", "Conservation and invariants", "Data layout assumptions", "Lifetime of referenced names", "Observable differences", "Old valid versions accepted again".
  - Facets with few samples, part B: "What is shown versus what is used", "Which attributes survive a move", "Leftovers after cancellation and interruption", "Transformations after validation", "Whether declared controls actually take effect", "The attacker's perspective".
- Five groups are domains (49 samples): mobile apps and mobile frameworks; OS kernels other than Linux; authorization and business logic in web applications; denial of service and resource exhaustion; open-source embedded systems, bootloaders and stacks.
- Because the facet-targeted samples were picked for their facet, a hit there shows that the facet holds in another domain and language. It is not an unbiased coverage rate. The domain groups are the less biased test.
- Root causes: each group was covered by one read-only research agent working from patches, official advisories and credible post-mortems. Each root cause is one sentence at the patch or advisory level, with no exploitation steps. The Sources column lists the advisory IDs and the links the agent actually read.
- One vulnerability, CVE-2023-25821 (Nextcloud Server reshares), was picked by two groups: facets with few samples part B, and authorization and business logic in web applications. Both judged it a hit. It is counted once, under part B, and its line was removed from the web group's samples file.
- Reproduction data is in `samples/held-out-3-<group>.jsonl`, one file per group; the file names are in the statistics table.

## Judging rules

- Only the "Question to ask" column of the root-cause facets (`facets.md`) and the "Checkpoint", "How to check" and "What counts as a problem" columns of the tables in `dimensions/`, `specialties/`, `targets/`, `questions.md` and `lang-*.md` are used.
- No "Real cases", "Historical cases" or other case column is used, and neither is `history/`. The "How it has been broken before" column of the baseline table "Mapping known attack mechanisms" was treated as a case column and not used.
- Hit: following one row's question leads straight into the root cause.
- Hit (weak): existing rows do reach the root cause, but the wording is indirect and the reviewer has to recognize it. Still counted as a hit.
- Partial: the rows only point in the right direction; the reviewer still has to take another step alone.
- Missed: no row leads to the root cause.
- Facet reached: in the facet-targeted groups, each sample also records whether the target facet's own question (in "New questions in existing facets", the new question) is what reaches the root cause: yes, only via other rows, or no. It is written at the end of "Rows hit or gap at the time".
- For every partial result the gap is named by layer: facet, checkpoint, domain or language table, or wording and routing.
- Row names in "Rows hit or gap at the time" are the names at test time. Row names in "Where the gap was fixed" are the names in the current English skill (`skills/finecomb/references/`). They are written as file plus facet or checkpoint name: `facets` is `facets.md`, `dimensions N` is `dimensions/N-*.md`, `specialties 4.N` is `specialties/4.N-*.md`, `questions 2.N` is `questions.md`, `targets` is `targets/`, `lang-*` is the language table, and `baseline` is `baseline.md`.
- "Where the gap was fixed" is filled for every partial and weak result. For a plain hit it is `—`, or `— (later strengthened: …)` when a row that led to it was later reworded.

## Problems found in the skill

- Incident and product names still sit inside "What counts as a problem" cells, which the judging rules count. A sample can then match a case written in a criteria cell, and those events can no longer be used as held-out samples. Checked on 2026-09-25 after the round 3 fixes; they have not yet been moved to `history/` or a case column:
  - specialties 4.4: "Domain separation and purpose separation" (CVE-2012-2459), "Completeness of verification" (CVE-2014-0092, CVE-2014-1266), "Misuse of signing interfaces" (CVE-2022-50237), "Oracles and observable differences" (ROBOT, Lucky13 CVE-2013-0169, CRIME and BREACH), "Custom schemes and proof structure" (Frozen Heart).
  - specialties 4.44: "Under-constrained circuits" (a 2026 Zcash Orchard incident), "Challenges and transcripts" (Frozen Heart), "Trusted setup and parameters" (CVE-2019-7167).
  - specialties 4.45: "Supply accounting for shielded pools" (Zcash).
  - lang-c-cpp: "Process entry assumptions" (PwnKit).
  - The facets with few samples part B group also found BitForge CVE-2023-33241 in specialties 4.4 "Parameters supplied by the other party", PuTTY CVE-2024-31497 in specialties 4.4 "Randomness and unpredictability", and CVE-2010-5139 and CVE-2018-17144 in specialties 4.45 "Supply and double-spend checks". The round 3 fixes removed those.
- The baseline table "Mapping known attack mechanisms" has a "How it has been broken before" column. It works like a case column, but the judging spec did not say whether it counts. This round treated it as a case column and did not use it.
