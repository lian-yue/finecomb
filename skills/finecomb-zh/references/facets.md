# 根因面

根因面是从真实漏洞的根因里归纳出的、与领域和语言无关的追问。同一个面在内核、Web 服务器、密码学库、智能合约、业务系统里反复出现，只是换了外形。[通用维度](dimensions.md)按质量属性组织，[专项](specialties.md)按目标类型组织，都可能让一个跨领域的根因落在缝隙里；这里把根因单独拉出来，**对每个对象都过一遍**。

用法：

- 在[逐对象追问](questions.md)之后，对每个入口、验证点、共享状态、缓冲区、解析循环、状态转换、外部交互，逐个面问一遍。一个面对某个对象不适用时，在覆盖记录里写明依据。
- 每个面的「详细判据」列指向具体的检查行；这里只写要问的问题和它为什么容易漏。
- 「真实案例」只用来说明这个面长什么样，不是清单；同一面在别的领域照样成立。
- 找到的问题按面归类，也能反过来检查：一个面在整次审查里一次都没被认真问过，就是覆盖缺口。
- 这份清单用真实漏洞做过命中测试（nginx、Linux 内核、OpenSSL、OpenSSH、glibc、主流框架与企业设备、链上与零知识证明事件），每个没命中的根因都已归纳成这里的一个面。新遇到的漏洞按同样方法对照：找不到对应的面，就说明要补面。
