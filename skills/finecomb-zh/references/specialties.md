# 四、按目标类型追加的专项

以下各节补充特定对象的检查点，按[事实基线](baseline.md)选择。通用判据通过链接复用，检查状态只在[报告](report.md#五证据等级与报告格式)中记录一次。

## 4.1 网络与连接

适用：任何建立、持有或复用连接的代码——客户端、服务端、代理、名字解析、传输层封装。

| 检查点 | 什么算问题 |
| --- | --- |
| **超时分层** | 建连、握手、读写、空闲和整体等待是否符合契约；攻击者能否占住资源且无法取消、回收或施加背压，不能仅因长连接没有总时限就判为缺陷 |
| 时限传播 | 上游的剩余时限有没有转成连接的读写截止时间；取消之后连接真的会断吗，还是只是函数返回了 |
| 连接归属 | 谁负责关闭；错误路径上关了吗；返回给调用方之后归谁 |
| 半关闭 | 只关写方向的语义；对端半关后本端还能不能读 |
| 连接泄漏 | 重试时旧连接有没有关；池化连接的归还路径覆盖所有出口了吗 |
| 连接池 | 上限、空闲回收、健康检查、复用前的可用性判断；池满时是阻塞、新建还是报错 |
| 重连与退避 | 有没有退避；退避有没有上限和**抖动**；重试次数与操作幂等性的关系 |
| **流结束与超时的区分** | 对端正常关闭 / 读超时 / 网络错误 / 连接被重置，是否被区分并分别处理——混为一谈会把正常关闭当故障重试 |
| 短读短写 | 只读到一部分就当读完；写返回的字节数没检查；该读满的地方用了单次读 |
| 地址族 | 双栈、并发尝试与回退、某一族不可用时的行为 |
| 名字解析 | 解析超时、负结果缓存、有效期来源、系统解析路径的关系；解析结果的顺序与轮转 |
| 自实现名字解析 | 自己实现解析器或名字服务时：事务 ID 与源端口是否随机；应答是否与问题段匹配；是否检查应答的权威范围（防投毒）；截断后是否改用可靠传输；别名链的长度与环；有效期的上下限钳制 |
| 传输层安全 | 最低协议版本、**证书校验有没有被关掉**、服务器名指示、应用层协议协商、会话复用、根证书更新、证书过期告警 |
| 多跳与代理链 | 错误归属、超时叠加、认证信息传递、失败回退 |
| 地址复用与绑定 | 地址/端口复用选项、绑定失败的处理、端口耗尽 |
| 保活与假死 | 传输层保活与应用层心跳；对端假死多久能发现 |
| 背压 | 读得慢时写端会怎样；发送缓冲无界吗——见[20](dimensions.md#20-资源上界与背压) |
| 并发使用 | 同一连接能不能并发读写；契约写了吗 |
| 外部服务契约 | 速率限制与配额、重试预算、幂等键、对方的错误语义有没有被正确解读 |
| **出站目的地** | 目的地址来自外部数据却只查了超时和证书——见[4.21](#421-出站请求与服务端请求伪造) |
| **取消后的连接状态** | 请求发出后、读完响应前被取消或超时，连接是否直接丢弃；还回池里的连接若残留未读响应，下一个请求（可能是别的用户）会读到上一个请求的结果 |
| 中途升级加密 | STARTTLS 这类先明文后加密的协议：升级前缓冲的明文命令是否在升级后丢弃；升级失败或对端不支持时是否拒绝继续，而不是退回明文。更一般地，安全层（TLS 握手、认证、加密通道）建立之前收到的任何数据，是否会被当成安全层里的数据处理 |

## 4.2 协议与帧解析

适用：任何自己解析线上字节、维护协议状态的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 消息边界 | 粘包 / 分包；一次读到半个帧、两个半帧怎么办 |
| **与另一解析器并存** | 自己和上游 / 下游对长度、分块、换行的理解不一致 → 请求走私——见[4.14](#414-服务端请求处理与中间件) |
| **必须理解的未知项** | 发送方标为「关键」或「必须理解」的扩展、头部参数、选项（如证书的关键扩展、JWS 的 `crit`、协议里的关键控制项），接收方不认识或没实现时只是忽略、照常接受；发送方要求的约束就此失效，而且和严格实现的判断不一致 |
| **最大帧长** | 由对端声明的长度字段驱动分配却没有上限 → 远端可打爆内存 |
| 非法输入 | 非法帧、非法状态转移、保留位、未知类型——是断开、跳过还是崩溃 |
| 状态机 | 协议状态转移是否完整——见[12](dimensions.md#12-状态机与状态转移) |
| 压缩与扩展 | 解压放大（小输入解出巨大输出）有没有上限 |
| 编码 | 文本编码校验、非法码点、掩码处理 |
| 分片与乱序 | 分片重组的上限与超时；乱序 / 重复的处理 |
| 控制消息 | 心跳、关闭等控制消息的优先级与大小限制 |
| 版本协商 | 不兼容版本的处理；降级协商能不能被攻击者强制 |

## 4.3 解码不受信任的外部数据

适用：任何吃外部文件、外部响应、用户上传的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **长度字段驱动的分配** | 直接按输入里的长度分配，长度来自不可信来源 → 内存放大 |
| 解压/解码放大 | 总输出字节、条目数、嵌套深度和累计处理量是否受限；单条限制能否被多层归档或流式输入绕过 |
| 超时 | 解码有没有整体时限 |
| 格式混淆 | 靠扩展名或声明的类型判断格式，而不是靠内容 |
| **处理器由请求选择** | 走哪个解析器、处理器由请求可控的属性（内容类型、扩展名、参数）决定时，换一种表示能不能跳过做净化或限制的那条路径，而后面的使用点照样到达 |
| 外部实体与引用 | 解析器会不会去取外部引用（本地文件、远程地址）——出站目的地见[4.21](#421-出站请求与服务端请求伪造) |
| 部分解码 | 解码失败时已经产生的副作用 |
| 重复出现的结构 | 格式规定只出现一次的段、块、头、字段重复出现时：拒绝、整体替换，还是只覆盖了一部分状态，让本该配对的缓冲与计数、指针与长度来自不同实例 |
| 对象合并与原型污染 | 外部对象的特殊属性能否经合并、按路径赋值或复制修改共享的原型、类或全局对象（如 JavaScript 的原型链，Python 经 `__class__`、`__init__.__globals__` 的属性链），继而影响权限、配置或后续请求 |
| 多格式与重复字段 | 同一字节能被不同解析器解释为不同对象时，校验和使用是否采用一致的格式、字段优先级和非法输入处理 |
| 依赖的解码器 | 第三方解码库的已知漏洞与危险特性是否禁用 |
| **解码变成执行** | 反序列化执行代码、解码器读本地或出网——见[4.22](#422-子进程动态执行与解码器副作用) |

## 4.4 加密与凭据

适用：任何使用或实现密码学的代码——加密、消息认证、哈希、签名、密钥交换、证书与令牌、秘密共享、承诺、多方计算与门限签名、默克尔证明及各类证明、远程证明，以及碰密钥、令牌、口令的代码。检查点按「面」组织，不按算法分类，对所有算法和构造都适用；零知识电路另见[4.44](#444-零知识证明与电路)。

| 检查点 | 什么算问题 |
| --- | --- |
| **算法与构造** | 用了已废弃或弱的算法（安全用途仍用 MD5、SHA-1：2012 年 Flame 利用 MD5 碰撞伪造代码签名证书，2017 年 SHAttered 给出 SHA-1 碰撞）；工作模式不当（ECB、不带认证的 CBC 或 CTR）；只加密不认证，或自己拼「加密 + MAC」时不是先加密后认证、MAC 没覆盖 IV 与头部；用 `H(密钥 ‖ 消息)` 做认证会被长度扩展，应使用 HMAC 或专门的密钥哈希；安全完整性校验用了非密码学哈希，非秘密的校验和不能替代消息认证或签名；常见 AEAD 不承诺密钥，同一密文可在两把密钥下都解密成功，多接收方、举报、去重场景需要承诺型方案 |
| **随机性与不可预测** | 密钥、令牌、盐、签名随机数是否来自密码学随机源；随机源失败是否被忽略；ECDSA、Schnorr、DSA 的签名随机数重用、带偏差、长度泄漏都能恢复私钥（PuTTY CVE-2024-31497 的 P-521 随机数高 9 位恒为 0，约 60 个签名即可恢复私钥；Minerva、TPM-FAIL 通过时间泄漏随机数长度），应按 RFC 6979 确定性生成或使用可靠随机源；密钥生成过程有无结构缺陷（ROCA） |
| **确定性随机数的输入** | 派生签名随机数的输入与签名方程实际用的值（截断或取模后的消息整数、公钥、上下文）不是同一个，或不能一一还原；类型转换、符号、截断、非规范编码让两个不同的签名值得到同一个随机数；签名函数接受任意类型的消息而不拒绝。用了 RFC 6979 不等于安全，要核对派生输入 |
| **唯一性与一次性** | IV、一次性数是否满足所用算法的唯一性或不可预测性要求；并发、重启、多实例、恢复备份、计数回绕是否导致重用；GCM、ChaCha20-Poly1305 重用一次性数不仅泄漏明文，还能让攻击者伪造消息（2016 年扫描发现上百台 HTTPS 服务器重复 GCM 一次性数）；随机一次性数的碰撞上限与同一密钥的使用上限、换钥时机；「只能用一次」的值（挑战、一次性数、nullifier、key image）是否真的只能有一个合法取值 |
| **按位置引用的授权操作** | 被签名、审批或排队的操作按下标、位置、序号或「当前值」指定对象，而不是按身份；在另一条链、另一个账户或状态变化后执行时，会不会落到另一个对象上；有意允许跨链、跨账户或延后执行的操作，执行时是否核对对象身份 |
| **绑定与上下文** | 签名、MAC、附加认证数据、证明、密钥派生是否覆盖实际使用的字段、操作、租户、接收方、方向、协议用途与版本；规范化歧义、跨用途复用或未签字段是否改变执行含义；握手是否绑定完整的协商记录（防降级、拼接和未知密钥共享）；共享密钥是否再经 KDF 并混入双方身份与协议上下文；证书、令牌、证明报告通过验证后，结果是否绑定到这一次会话与用途 |
| **域分离与用途分离** | 同一密钥用于多种用途或两个通信方向；派生密钥时缺少用途标签；同一哈希或签名用于多个场景时，输入里有没有用途前缀，防止一个场景的结果被拿到另一个场景使用；默克尔树的叶节点与内部节点是否用不同前缀（否则可伪造第二原像），奇数节点复制最后一个的规则会不会让不同集合得到同一个根（比特币 CVE-2012-2459） |
| **规范形式与可延展** | 对结构化数据签名或取哈希前是否先转成唯一的规范形式，签名方与验证方的规则是否一致；签名、密钥、曲线点、证书的编码是否严格（严格 DER、低 s 值、数值小于群阶、压缩与非压缩点）；同一个值的多种合法写法会不会被当成不同的交易、记录或标识；签名、证明本身能否被变换成另一个同样有效的值，因而不能当唯一标识或防重放键 |
| **验证的完备性** | 验签、验证书链、验令牌、验证明时每一项是否都查：签名、链、有效期、基本约束、密钥用途、名称约束、主机名、签发者、受众、算法由谁决定、标为关键或必须理解的扩展与头部参数（见[4.2](#42-协议与帧解析)「必须理解的未知项」）；多项检查写同一个结果时，后面的成功不能把前面的失败改回成功；WebAuthn 的依赖方标识、来源与挑战新鲜度；验证函数的错误路径会不会被当成成功（Apple「goto fail」CVE-2014-1266、GnuTLS CVE-2014-0092），返回值是否被正确使用；外部给的公钥和曲线点是否校验在曲线上、在正确的素数阶子群里，全零共享密钥与无穷远点是否拒绝；辅因子不为 1 的曲线（如 ed25519）上，同一秘密能否构造出多个都能通过验证的等价点（Monero 2017）；吊销检查失败时是放行还是拒绝 |
| **对方提供的参数** | 协议对方、多方计算参与方、令牌头给出的算法、密钥、模数、曲线和群参数，是否经过校验或附带并验证了正确性证明（缺少对 Paillier 模数的证明时，恶意参与方可在十几次签名内窃取他人的密钥分片：BitForge CVE-2023-33241）；令牌里的 `alg`、`kid`、`jku`、`x5u` 是否只能从可信集合里选 |
| **签名接口的误用** | 签名函数能否接收调用方单独传入的公钥（Ed25519 同一私钥配不同公钥签同一消息会泄漏私钥，2022 年多个库受影响，如 CVE-2022-50237）；BLS 聚合签名是否要求公钥的持有证明（防流氓公钥）；多方签名的随机数承诺与并发会话；验签的是消息还是预先算好的哈希，哈希算法是否与签名绑定 |
| **预言机与可观测差异** | 解密、验签、口令比较、解包失败时，错误类型、耗时、响应长度能否区分失败原因（填充预言机、Bleichenbacher 攻击及 2017 年的 ROBOT、Lucky13 CVE-2013-0169）；错误信息泄漏「哪一步失败」；攻击者可控的数据和秘密一起压缩后再加密，密文长度会泄漏秘密（CRIME、BREACH 一类）；流式解密是否在认证通过前就把明文交给调用方 |
| **恒定时间与侧信道** | 密钥、认证码、令牌用了会短路的比较；依赖秘密的分支、内存访问、除法（KyberSlash 2024：多个 ML-KEM 实现里依赖秘密的除法泄漏密钥）、提前返回；编译器优化是否破坏恒定时间；查表实现在共享 CPU 上的缓存泄漏；嵌入式设备的功耗与电磁分析；电压或时钟毛刺让检查被跳过，RSA-CRT 签名出错会泄漏私钥，签名后是否校验结果 |
| **密钥派生与口令** | 口令直接当密钥用（缺密钥派生）；派生参数过弱；派生是否使用专门的 KDF 并带盐与用途标签；口令哈希的算法与代价参数是否足够、能否升级，每个口令独立的盐；函数有输入长度上限（如 bcrypt 只看前 72 字节）时超出部分是否被静默丢弃，拼接多个字段再派生时前面的字段够长会把后面的口令挤出去（Okta 2024） |
| 密钥生命周期与托管 | 密钥生成、存储、使用、轮换、撤销和销毁是否闭合；旧密钥的接受期限和轮换失败行为是否明确；信封加密的分层与轮换后旧数据的重新加密；HSM、智能卡、TPM 的接口（如 PKCS#11）是否允许把密钥导出或包装成可导出形式；密钥材料未经授权导出，或以明文进入不受保护的存储、传输和对象表示 |
| 凭据暴露 | 源码、版本库历史（按授权读取）、配置、样例、日志、错误、镜像层、缓存键或崩溃转储中是否含有效机密；发现后只记录脱敏位置与影响，不传播原值，删除副本也不等于凭据已撤销 |
| 内存中的秘密 | 秘密用完后是否清零，编译器会不会删掉清零；会不会被换页到磁盘，写进崩溃转储、核心转储或调试快照 |
| 协议状态与重放 | 握手消息乱序、重复、跳过时是否拒绝；记录序号与回绕后的换钥；会话恢复、0-RTT 数据能否被重放；长期密钥泄漏后过去的会话是否安全（前向安全） |
| **自定义方案与证明结构** | 自研或组合的密码协议、证明系统有没有安全分析和专门审计，实现是否与论文或规范逐项一致；交互式证明变成非交互时（Fiat–Shamir），每个挑战派生之前，证明者已经发出的每一个值（承诺、声称的求值结果、由证明者自选的子挑战）以及全部公开输入和参数是否都进了哈希（缺项可伪造证明，2022 年多个实现中的 Frozen Heart 问题）；秘密共享的份额编号唯一且不为零、份额可验证；承诺的绑定性与隐藏性；门限与多方计算能否识别作恶方；范围证明的上下界，储备证明是否包含全部负债与负余额，工作量证明是否校验了目标值与完整头部，可验证随机函数与可验证延迟函数的验证 |
| 密码学敏捷与后量子 | 算法、密钥长度、参数能否在不改协议的前提下替换；需要长期保密的数据是否面临「现在截获、将来解密」的风险；后量子算法解封装失败时的隐式拒绝；与传统算法混合使用时两把密钥的组合方式 |
| 远程证明 | TPM 或可信执行环境的证明报告：签名链、度量值允许列表、新鲜度（随机数）、平台安全版本是否仍受支持；证明通过后发放的秘密是否绑定到这次证明 |
| **发给客户端的秘密** | 前端打包产物、移动应用、桌面安装包、公开的配置接口里是否带着服务端密钥或高权限令牌；发到用户设备上的东西就不算秘密 |
| 经命令行传秘密 | 秘密是否作为命令行参数传给子进程，被同机其他用户从进程列表看到，或进入 shell 历史与审计日志 |

## 4.5 认证、会话与令牌

适用：任何验证身份、维护登录态、签发或校验令牌的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 凭据强度 | 口令策略；常见口令拦截；**长度上限是否被设得过低**；有没有禁止粘贴 |
| 凭据存储 | 口令哈希算法与参数是否足够；有没有加盐；能不能升级参数 |
| 多因子 | 有没有；绕过路径（记住设备、找回流程、备用码） |
| **暴力破解防护** | 登录尝试限制、锁定策略；锁定本身会不会被用来打人（拿别人账号刷锁） |
| 账号枚举 | 登录 / 找回 / 注册的响应（措辞、状态、耗时）能不能区分账号存不存在 |
| 账号恢复 | 找回流程的强度是不是弱于登录；恢复令牌的有效期与一次性 |
| 敏感身份变更 | 修改口令、邮箱、多因子和绑定外部身份时，是否验证当前控制权；恢复后旧会话和旧恢复凭据是否按契约失效 |
| 外部身份绑定 | 是否使用可信签发方与稳定主体标识定位账号；未经验证的邮箱或同名账号是否导致自动合并、错误绑定或接管 |
| 会话生命周期 | 创建、续期、过期、失效；空闲超时与绝对超时都有吗 |
| 会话固定 | 认证成功后有没有换新的会话标识 |
| 并发会话 | 允许几个；一处登出是否影响其它；能不能看到活跃会话 |
| 令牌作用域 | 权限范围是否最小化；令牌能不能被用于超出预期的操作或受众 |
| **撤销** | 有没有撤销机制；撤销后多久生效；无状态令牌怎么撤销 |
| 刷新令牌 | 有没有轮换；被盗用能不能检测（重放检测） |
| 存储与传输 | 存在哪、怎么传；有没有出现在地址、日志、前端可读存储、缓存里 |
| Cookie 边界 | Secure、HttpOnly、SameSite、Domain 和 Path 是否符合会话用途；同名 Cookie、子域写入和退出时删除范围是否改变实际选中的会话 |
| 绑定 | 令牌绑不绑定客户端、设备、地址；不绑定的后果 |
| 校验完整性 | 签名算法有没有被输入决定；受众、签发方、有效期、用途都校验了吗 |
| 验签密钥选择 | `kid` 等标识是否只在可信密钥集合中查找；令牌携带的密钥、证书或远程密钥地址是否被直接信任或用于任意文件和网络访问 |
| 委托授权协议 | 用了 OAuth、OpenID Connect、SAML 或质询式认证时，按[4.46](#446-联合身份与单点登录)逐项检查 |
| **一次性码** | 短信、邮件、动态口令的验证码：尝试次数是否按账号和按码计数，而不只按会话或来源地址（换会话、换地址就能重来）；有效期与时间窗是否短；用过或被新码替代后是否作废；是否绑定到这一次登录或操作 |
| 推送批准 | 推送式多因子能否被反复触发轰炸用户；批准页面是否显示足以辨认的请求来源，是否要求输入屏幕上的数字（号码匹配）；连续拒绝后是否告警 |
| 按邮箱域名授予身份 | 「邮箱属于某域名就自动加入组织或获得权限」是否以已验证的邮箱为准；邮箱地址的解析（引号、注释、编码字、多个 @）在校验方与投递方是否一致 |
| **登录后跳转** | 认证成功后的回跳地址来自请求参数且未限制 → 把令牌送到别处——见[4.18](#418-用户界面与可访问性) |
| 时钟偏移 | 过期判断对时钟偏移的容忍度；容忍窗口有多大 |

## 4.6 缓存与存储

适用：任何保存数据并再取回的代码。通用维度已覆盖大部分（[23](dimensions.md#23-事务原子性与一致性) [24](dimensions.md#24-编解码与持久化格式) [25](dimensions.md#25-崩溃与恢复) [26](dimensions.md#26-发布升级迁移与回滚) [20](dimensions.md#20-资源上界与背压)），这里只列特有的。

| 检查点 | 什么算问题 |
| --- | --- |
| 淘汰策略 | 承诺的淘汰顺序和实现真的一致吗；读会不会改变淘汰顺序 |
| 穿透 / 击穿 / 雪崩（查不存在的键、热点键过期、大量键同时过期） | 未命中会不会全部打到下游；同一键并发未命中有没有合并；过期时间要不要抖动 |
| 失效传播 | 多副本 / 多实例之间怎么失效；有没有一致性承诺——见[23](dimensions.md#23-事务原子性与一致性) |
| 命中率可观测 | 有没有暴露命中率；是精确还是采样 |
| 预热与冷启动 | 重启后多久恢复到可用命中率 |
| 负结果缓存 | 「不存在」缓不缓存；缓多久 |
| 缓存键与隔离 | 是否包含决定响应的租户、主体、权限或表示维度；负结果、共享对象池和错误响应是否串到其他请求；不能把凭据原文当键；由多个变长字段拼成的键是否有长度前缀或分隔 |
| 原子发布 | 是临时文件加原子替换还是直写；落盘同步覆盖到了吗——见[25](dimensions.md#25-崩溃与恢复) |
| 回收与压实 | 垃圾回收、压实、过期清理与并发的读、回填、提升交错时，是否删除了仍被引用或正在写入的数据；回收中途停止后的状态能否识别；空间是否真的释放 |
| 删除与复活 | 删除之后，并发的读回填、复制、提升或重放是否让已删条目复活；有没有墓碑或版本比较挡住 |

## 4.7 数据库与查询

适用：任何通过查询语言访问数据存储的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **N+1** | 循环里逐条查询 |
| 索引使用 | 查询能不能用上索引；有没有全表扫描；索引与实际查询模式是否匹配；有没有没人用的索引 |
| **分页稳定性** | 偏移分页在并发写入时会漏或重；有没有用稳定游标 |
| 结果集大小 | 没有上限的查询；一次拉回全表；流式读取还是全量载入 |
| 长事务与锁 | 事务里做慢操作（网络调用、大计算）；锁的范围与时长；死锁与重试 |
| 批量 | 批大小；一次提交太多导致回滚代价大、日志膨胀 |
| 连接池 | 上限、超时、泄漏、与并发度和数据库上限的匹配 |
| 查询注入 | 数据值是否参数化；表名、列名、排序表达式等不能参数化的结构是否使用允许列表；ORM 原始查询、NoSQL 操作符与搜索表达式是否仍接收任意输入；必须手工转义时，见[4.17](#417-模板与文本输出)「多字节编码下的转义」 |
| **驱动模拟参数化** | 驱动或 ORM 在某些模式下（简单查询协议、模拟预处理、客户端插值）把参数内联成语句文本；这时安全取决于驱动生成的字面量：负数、特殊浮点、数组、自定义类型是否都生成自带边界的字面量；这种模式是否默认开启、能否被配置打开 |
| **连接串与驱动参数** | 数据库连接串、DSN 或驱动参数由外部或低权限输入决定时，驱动特性（初始化脚本、加载本地文件、自动反序列化、自定义套接字工厂）能否执行脚本、读本地文件或连到任意主机；连接目标是否受允许列表约束（出站见[4.21](#421-出站请求与服务端请求伪造)） |
| 数据层权限 | 数据库账号是否拥有超出职责的权限；使用行级策略或连接级租户上下文时，复用连接是否会残留上一请求的身份 |
| 迁移 | 可逆吗；会不会锁表；大表加列 / 加索引 / 改类型的策略；和代码发布的先后顺序 |
| 空值与默认 | 存储层空值与语言空值的映射；默认值放在哪一层 |
| 时间与时区 | 存储的时间类型带不带时区；写入和读取用的时区一致吗 |
| 读写分离 | 从副本读会不会读到旧数据；读己之写能不能保证 |
| 方言与隐式行为 | 空值的三值逻辑、隐式类型转换、排序规则与尾部空格比较、非严格模式下的截断、默认隔离级别在不同数据库间不同；具体见[附录 A 的 SQL 一节](lang-sql.md) |
| **外部对象当查询条件** | 请求里的对象或键值被直接展开成过滤条件（ORM 的关键字参数、`where` 对象、搜索表达式），攻击者能按口令哈希、令牌、关联表字段过滤，逐字符试出看不到的数据 |
| 目录与其它查询语言 | LDAP 过滤器与 DN 的转义规则不同，是否各用各的；XPath、XQuery、搜索引擎查询语法是否参数化或按允许列表构造 |

## 4.8 文件系统与路径

适用：任何直接操作文件与目录的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 路径构造 | 最终访问对象是否仍在允许根目录内；绝对路径、上跳、编码差异和仅比较字符串前缀是否能绕过约束 |
| 链接与检查后替换 | 符号链接、硬链接、挂载或父目录在校验后被替换时，实际读写或删除是否越界；仅做一次路径规范化不保证后续对象不变 |
| 原子替换 | 按实际系统、文件系统和语言 API 核对；跨目录不必然失去原子性，同目录也不是跨平台保证（POSIX `rename` 与 Windows 的替换语义不同，各语言的封装也不一样）。跨文件系统限制及断电持久性另行判断；例如 [Go os.Rename](https://pkg.go.dev/os#Rename) 明示平台差异 |
| 临时文件 | 命名可预测吗（可被抢占）；创建时的权限；失败路径上删了吗 |
| 目录遍历 | 遍历顺序不保证；遍历期间目录被增删会怎样 |
| 大目录 | 条目数很多时的列举代价；有没有分片 |
| 文件锁 | 建议锁还是强制锁；跨平台语义差异；进程崩溃后会不会自动释放 |
| 空间与配额 | 写之前检不检查空间；写失败后的清理 |
| 权限与属主 | 创建时的权限；继承的属主；权限掩码影响 |
| 路径长度与字符 | 长度上限、非法字符、保留名、大小写、规范化形式；Windows 的备用数据流（`name::$DATA`）、8.3 短文件名、末尾的点和空格会让扩展名检查与黑名单失效 |
| **上传与外来文件** | 类型与大小校验；存储位置是否可执行；文件名是否重写；下载时的内容类型与处置头 |
| 归档解包 | 每个条目的最终路径、链接目标和文件类型是否受限；嵌套归档、重复名称或链接条目能否覆盖根目录外或已有可信文件 |
| 上传发布与下载 | 校验和处理完成前文件是否已可访问；分片合并和续传是否校验属主；下载链接是否绑定资源、操作和有效期，用户内容是否能在可信站点上下文执行 |
| 观察与通知 | 文件变更监听的可靠性（事件丢失、重复、批量）；有没有兜底轮询 |

## 4.9 事件、发布订阅与观察者

适用：**进程内**任何有回调、监听、订阅、通知的代码。跨进程的见[4.10](#410-消息队列与异步任务)。

| 检查点 | 什么算问题 |
| --- | --- |
| 订阅生命周期 | 取消订阅的路径；取消之后还会不会收到；重复取消；忘记取消导致泄漏 |
| **慢订阅者** | 一个订阅者卡住会不会拖住发布者或其它订阅者；缓冲无界吗 |
| 投递语义 | 至多一次 / 至少一次，承诺了吗、实现符合吗 |
| 顺序 | 承诺不承诺顺序；多订阅者之间呢 |
| 回调执行上下文 | 在发布者的执行流里跑还是另起；**持锁时调用回调吗**（见[18](dimensions.md#18-并发与内存模型)） |
| 回调崩溃 | 一个订阅者崩溃会不会带崩发布者 |
| 重入 | 回调里再订阅 / 取消订阅 / 发布会怎样 |
| 丢事件 | 满了之后丢最老还是最新还是阻塞；丢了有没有告知 |
| 关闭 | 关闭时在途事件怎么办；订阅者怎么知道 |

## 4.10 消息队列与异步任务

适用：任何跨进程投递消息或提交后台任务的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **投递语义与幂等** | 至少一次投递下，消费端幂等吗；幂等键从哪来——见[23](dimensions.md#23-事务原子性与一致性) |
| 顺序 | 有没有顺序保证；分区内有序还是全局有序；重试会不会打乱顺序 |
| 位点提交 | 先提交位点还是先处理；崩溃后从哪继续；会不会漏或重 |
| **死信与毒丸** | 反复失败的消息去哪；有没有死信队列与告警；一条坏消息会不会卡住整个消费 |
| 积压 | 积压怎么观测；积压时的降级策略；能不能扩容消费 |
| 消费者组与再平衡 | 再平衡期间的重复消费与处理中断 |
| 消息大小与演进 | 大小上限；新增字段旧消费者能不能读——见[4.16](#416-数据模型与生成契约) |
| 优雅停止 | 停止时正在处理的消息怎么办；会不会丢 |
| 延迟与重试队列 | 延迟消息的精度；重试队列会不会无限循环 |
| 事务性发送 | 「本地状态改了但消息没发出去」怎么办；有没有发件箱模式 |
| 消息身份与授权 | 生产者、主题、租户和目标资源是否可信；消费和人工重放时是否按当前权限检查，不能只信消息内自报的身份 |
| 长流程与编排 | 运行多天的工作流、Saga、编排实例遇到代码升级时能否继续；补偿步骤是否幂等；卡住的实例怎么发现和处理 |

## 4.11 定时与调度

适用：任何按时间触发执行的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **重叠执行** | 上一次还没跑完下一次又触发；允许重叠吗；不允许靠什么保证 |
| 错过的执行 | 停机期间错过的要不要补；补多少次；补的时候会不会打爆下游 |
| **分布式单实例** | 多副本会不会同时跑；靠什么保证只有一个执行；持锁者崩溃后多久释放 |
| 时区与夏令时 | 表达式在时区切换 / 夏令时那天会跑两次还是不跑 |
| 抖动 | 整点惊群；有没有加抖动 |
| 长任务 | 单次执行超过触发周期会怎样 |
| 失败与重试 | 失败了这一轮补不补；重试会不会和下一轮撞 |
| 可观测 | 上次执行时间、耗时、结果、下次预定时间能不能看到 |
| 手动触发 | 能不能手动触发；手动与自动会不会并发 |
| 停止与排空 | 关闭时正在跑的任务怎么办 |

使用分布式锁、租约或选主时，继续检查[4.25](#425-分布式协调与租约)。

## 4.12 依赖装配与服务生命周期

适用：任何组装组件、管理启动停止的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 启动顺序 | 依赖顺序是显式的还是碰巧的；循环依赖 |
| 启动失败 | 启动到一半失败，已经起来的怎么回收 |
| **停止顺序** | 是不是启动的逆序；有没有超时；超时之后强制结束还是挂着 |
| 就绪与健康 | 「起来了」和「能服务了」是不是一回事；健康检查查的是什么 |
| 单例与作用域 | 谁持有、谁释放；同一依赖被建了两份 |
| 后台任务归属 | 每个后台任务属于哪个组件，停止时谁负责等它 |
| 配置注入 | 配置在装配时校验还是运行时才炸 |
| 延迟初始化 | 懒加载的并发安全与失败重试 |

## 4.14 服务端请求处理与中间件

适用：任何接收外部请求并分发处理的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 中间件顺序 | 顺序有没有写明；崩溃恢复、日志、认证、授权、限流的相对位置 |
| 请求体上限 | 没有大小限制 |
| 超时 | 各阶段限时、取消和背压是否符合请求类型，处理函数是否遵守请求的取消；长连接的判断见[4.1](#41-网络与连接) |
| 优雅关闭 | 关闭的等待与超时；在途请求与长连接 |
| 错误映射 | 内部错误怎么变成对外状态；有没有把内部信息泄漏出去 |
| 头部处理 | 注入、重复、大小写、逐跳字段的转发、来源地址的信任 |
| **Host 头** | Host 参与生成绝对 URL、重置邮件、路由时能不能被调用方控制 |
| **跨站请求伪造** | 会话凭证会随浏览器请求自动带上时，跨站能不能触发改状态的入口；只靠「同站」够不够、有没有令牌或自定义头 |
| 跨源访问（CORS） | 是否精确核对允许的来源、方法、头与凭据设置；反射任意来源、错误匹配子域或只检查预检请求是否扩大访问；CORS 不能替代服务端授权或 CSRF 防护 |
| **请求走私与缓存投毒** | 代理与后端对长度、分块、协议转换、路径或头的解释是否一致；影响响应的输入被缓存键遗漏，或敏感响应被按公开静态资源缓存 |
| **WebSocket 与长连接** | 握手时来源与身份是否有效；建立后每条消息是否有权限和体积限制，会话过期、撤销和租户切换是否使旧连接失效 |
| 流式响应 | 刷新时机、客户端取消、背压 |
| 路由 | 路径匹配的歧义、尾部斜杠、大小写、上跳 |
| 代理信任 | 转发身份、来源地址、协议或客户端证书的头是否仅来自可信代理；后端直连或入口路由变化是否绕过网关检查 |
| 并发限制与限流 | 每个处理路径的并发有没有上限；限流按什么维度；超限的响应 |
| 只监听本机的服务 | 只绑定回环地址不等于只有可信调用方：浏览器里的网页可经 DNS 重绑和跨站请求访问；本机其它用户也能连。是否校验 Host、来源与调用者身份 |
| 授权位置 | 权限检查在中间件还是处理函数；有没有路径绕过——见[28](dimensions.md#28-授权与访问控制) |
| **安全响应头** | HSTS、内容安全策略、X-Content-Type-Options、Referrer-Policy、嵌入防护（frame-ancestors）是否按页面用途设置；Cookie 属性见[4.5](#45-认证会话与令牌) |
| HTTP 缓存语义 | Cache-Control、Vary、ETag 与条件请求是否正确；带身份的响应是否被标成可共享缓存；路径混淆能否让敏感页面按静态资源被缓存（缓存欺骗）；请求能否让本不该缓存的动态响应带上可缓存的头，从而污染共享缓存 |
| GraphQL | 查询深度与复杂度上限；别名与批量查询造成的放大；内省是否对外开放；字段级授权（见[28](dimensions.md#28-授权与访问控制)） |
| gRPC 与其它 RPC | 消息大小上限；截止时间是否向下传递；反射服务和健康检查是否对外暴露；错误状态的映射是否泄漏内部信息 |
| **接口清单** | 对外可达的接口、旧版本、已废弃接口和调试接口有没有清单；不在清单里的「影子接口」是否仍在服务，是否绕过了新版本加上的检查 |
| 请求方法 | 授权、CSRF 校验是否只挂在部分方法上（只查 GET、POST，HEAD 或未知方法照样进处理函数）；是否接受 `X-HTTP-Method-Override` 这类改写方法的头或参数 |
| 跨站泄漏与请求来源 | 跨站页面能否通过加载结果、耗时、帧数、错误事件推断用户状态；是否用 `Sec-Fetch-*` 请求头拒绝不该跨站加载的请求，用 COOP、CORP 限制窗口与资源被跨源访问；JSONP 是否已关闭 |

## 4.17 模板与文本输出

## 4.21 出站请求与服务端请求伪造

适用：任何按外部数据（请求参数、已存记录、配置、重定向、webhook、回调地址）去发起出站连接或请求的代码。只管连接池、超时和证书的见[4.1](#41-网络与连接)；入站来源地址见[4.14](#414-服务端请求处理与中间件)；解析器去拉外部实体见[4.3](#43-解码不受信任的外部数据)。

| 检查点 | 什么算问题 |
| --- | --- |
| **目的地谁说了算** | 核对 URL、主机、IP 和端口的实际可控方；低信任输入经配置、存储或重定向进入出站路径后被误当可信 |
| **协议限制** | 允许目标职责不需要的 `file:`、`gopher:`、`dict:`、`unix:` 或自定义 scheme；协议切换绕过了已要求的访问限制 |
| **重定向链中的凭据** | 跨主机重定向时剥掉的认证头、Cookie、代理认证，之后再跳回同一主机或原主机时是否被恢复；剥离判断以原始请求为准还是以上一跳为准；测试是否覆盖三跳以上的链 |
| **跟随重定向** | 第一次请求在白名单内，重定向之后到了内网或换了协议；跳数没有上限 |
| **先解析再连的时间差** | 白名单检查的是主机名，真正连接时又解析了一次 → DNS 重绑 |
| **白名单绕过** | 十进制 / 八进制 IP、IPv6 映射 IPv4、`@` 用户信息、同形字、末尾点、开放重定向链 |
| **内网与元数据** | 能否违反目标访问策略连接回环、链路本地、私网、云元数据或容器网关；对本就提供代理能力的组件，核对实际调用方的限制职责 |
| **出站带出的身份** | 会不会把对内凭证、Cookie、源站令牌带到用户指定的地址 |
| **响应当可信输入** | 把出站响应体再当模板、查询、跳转地址或命令 |
| 超时与体积 | 出站也能被慢上游或超大响应拖死——超时见[4.1](#41-网络与连接)，放大见[20](dimensions.md#20-资源上界与背压) |

入站 Webhook 的身份和重放检查见[4.24](#424-webhook-与外部事件)。

## 4.22 子进程、动态执行与解码器副作用

适用：任何拉起子进程、调用解释器、eval、把数据反序列化成对象图、加载插件，或让日志 / 模板框架解释查找表达式的代码。解析放大与外部实体见[4.3](#43-解码不受信任的外部数据)。

| 检查点 | 什么算问题 |
| --- | --- |
| **调用方式** | 走了 shell 拼接；即使用参数数组，参数仍能变成选项或另一个文件路径 |
| **环境继承** | 不可信方能否控制子进程继承的 `PATH`、加载器或调试变量、工作目录，进而改变实际执行的程序与代码 |
| **描述符泄漏** | 父进程的密钥文件、套接字被子进程继承 |
| **身份与降权** | 以过高权限执行外部程序；失败时权限没落回来 |
| **对象图反序列化** | 把不可信字节当成语言对象解开 → 构造器 / 回调 / gadget 被执行。这和「解析炸弹」不是一类 |
| **解码器副作用** | 图片 / 文档 / 媒体库读本地路径、出网、执行内嵌配置——出网见[4.21](#421-出站请求与服务端请求伪造) |
| **日志与查找表达式** | 不可信消息触发查找、加载类或执行表达式，使普通记录动作变成文件、网络或代码执行 |
| **插件与原生库** | 加载路径或类名来自外部输入 |
| **输出再解释** | 子进程或解码器的输出又被当成命令、标记语言或下一次输入 |
| **Windows 命令行重组** | Windows 上参数数组会被拼回一整条命令行，由被调程序自己再拆；目标是 `.bat`、`.cmd` 时一定经过 `cmd.exe`，按参数数组转义仍能注入命令 |
| **字符集转换改写参数** | 宽字符参数、路径转成本地代码页时，系统做近似映射（全角引号变 `"`、软连字符变 `-`、`¥` 变 `\`）；校验在转换之前，执行看到的是转换之后 |

## 4.23 安全审计日志

适用：需要追溯敏感访问、权限变更、危险操作或安全事件的应用及其记录组件。普通日志性能见[4.13](#413-日志指标与追踪)，隐私约束见[30](dimensions.md#30-隐私数据治理与合规)。

| 检查点 | 什么算问题 |
| --- | --- |
| 事件范围 | 所需的认证失败、授权拒绝、敏感数据访问、权限与配置变更、导出删除等事件缺失；通用日志级别或采样意外关闭必需记录 |
| 身份与关联 | 缺少可信主体、代理主体、租户、动作、对象、事件时间、结果与关联标识；把请求自报身份或可伪造来源当成已验证身份 |
| 结果真实性 | 操作提交前就记成功，或异步执行只有接收记录、没有最终结果；记录不能区分尝试、拒绝、部分完成和完成 |
| 完整性与访问 | 业务身份可任意改删记录；传输、归档或查询缺少访问限制，篡改和异常缺口无法发现 |
| 写入失败 | 磁盘满、队列满、断网或记录服务失败后静默丢失；阻塞、拒绝业务或降级的选择没有契约与告警，补送产生无界积压 |
| 注入与数据最小化 | 外部字段伪造新事件、覆盖保留字段，或记录完整令牌、口令和敏感载荷；展示与导出再次解释日志内容 |
| 留存与处置 | 保留期、访问责任和删除权限不明确；告警无法关联到可调查的事件，日志停写或审计配置被关闭无人得知 |

记录内容和强度应按实际风险确定，可核对 [OWASP Logging Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html)。

## 4.24 Webhook 与外部事件

适用：接收外部回调、签名通知或由第三方事件驱动业务变更的代码。出站回调地址见[4.21](#421-出站请求与服务端请求伪造)，消息投递见[4.10](#410-消息队列与异步任务)。

| 检查点 | 什么算问题 |
| --- | --- |
| 验证对象 | 按协议要求的原始字节或规范化表示验签；中间件改写内容、重复字段或验证后再解析导致执行对象与已签对象不同 |
| 可信来源 | 验签密钥来自可信配置并绑定正确发送方；不能由消息自带密钥替代。来源 IP 限制不能单独证明消息真实 |
| 重放与并发 | 时间窗口之外的事件是否拒绝；事件身份是否绑定发送方、租户和用途，去重检查与业务状态修改是否原子；仅有时间戳不能阻止窗口内重放 |
| 业务绑定 | 合法事件能否被用于别的租户、订单、资源或操作；状态变更是否仍检查当前业务前提 |
| 乱序与重复 | 旧事件是否覆盖新状态；重复投递、人工重放和补发是否重复扣费、发放或通知 |
| 确认时机 | 返回成功前是否已可靠保存或处理；处理中崩溃、响应丢失或下游失败后能否按约定恢复 |
| 对账与缺失 | 对协议允许丢失或延迟的事件，是否有权威状态核对或补偿入口；不能仅凭客户端成功跳转认定外部操作已完成 |

## 4.25 分布式协调与租约

适用：依赖多节点、分布式锁、租约、选主或复制来保证写入和任务唯一性的代码。事务与一致性承诺见[23](dimensions.md#23-事务原子性与一致性)。

| 检查点 | 什么算问题 |
| --- | --- |
| 故障假设 | 网络分区、长暂停、时钟偏移、消息延迟和重复是否在承诺内；不能用单进程锁推导多节点安全 |
| 过期持有者 | 租约过期或主节点切换后，旧持有者恢复时是否还能写；需要排除旧写入时，存储端是否校验递增的隔离令牌（fencing token）或等价条件 |
| 续租与释放 | 续租失败是否停止依赖租约的操作；释放和重试是否核对持有者身份，旧持有者能否删掉新租约 |
| 决策与提交 | 节点收到超时但提交结果未知时，重试是否重复执行；版本号、任期或条件写入是否覆盖实际资源变更 |
| 分区恢复 | 多个节点同时自认有权执行时如何拒绝冲突；旧快照、落后副本和重放消息是否破坏已经确认的结果 |

## 4.26 大模型与工具调用

适用：把大模型用于检索、生成、代理执行或工具编排的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 指令与外部内容 | 用户任务、检索文档、网页、附件、工具描述和返回值是否分清来源；外部内容中的指令能否改变任务、工具权限或数据去向 |
| 执行层授权 | 工具入口是否独立校验用户、租户、操作、参数和资源范围；仅靠提示词或另一个模型判断权限，或模型输出可直接扩大工具权限 |
| 读取与输出边界 | 检索、会话记忆、向量库与缓存是否按主体隔离；发送给模型供应商或工具的数据是否超出授权，输出中的地址和代码是否被直接执行 |
| 批准与实际动作 | 需要批准的操作是否绑定最终参数、目标和内容；批准后替换参数、多次重试或工具串联是否扩大范围 |
| 调用预算与记录 | 工具循环、递归调用、模型计费和外部操作是否有预算、取消与结果记录；不能因模型说已完成就把工具失败记录成成功 |
| **提示词里的秘密** | 系统提示词、工具描述里有没有密钥、内部地址或不该公开的规则；能否被用户套出来；安全不能依赖提示词保密 |
| 输出可靠性 | 模型的回答、引用和计算结果是否被当成事实直接使用；有没有来源核对、置信度或人工确认 |
| 模型与数据来源 | 模型文件、微调数据、检索语料的来源与完整性；外部可写的语料能否被投毒，影响后续回答 |
| 回归评测 | 提示词、模型版本、检索配置改动后，有没有固定的评测集验证行为没有退化 |
| **输出渲染外发** | 模型输出按 Markdown 或 HTML 渲染时，图片、引用式链接、链接预览会不会自动请求外部地址，把上下文里的数据放在地址里带走；内容安全策略允许的域名本身能否转发请求 |
| **改写自身约束** | 代理能否写入决定自己权限的文件或设置（自动批准开关、工具白名单、钩子、项目配置）；这类写入是否必须经人确认（通用判据见[28](dimensions.md#28-授权与访问控制)「派生身份的权限上限」） |
| 持久记忆 | 外部内容能否写进长期记忆、用户画像或共享知识库，在以后的会话或别的用户那里继续生效；记忆条目有没有来源、主体和有效期 |
| 工具定义与来源 | 工具的描述、参数说明在批准后能否变化；同名工具能否遮蔽另一个服务器的工具；定义变化后是否要求重新批准 |
| 代理持有的凭据 | 代理或工具服务器调用下游时，用的是按用户和用途收窄的凭据，还是把收到的令牌原样转发，或用自己的高权限身份办事；凭据能否被模型读到 |
| 代理之间的消息 | 其它代理、子代理、工作流节点的输出是否按外部内容对待；消息是否带可核对的发送方身份 |

相关防护可参考 [OWASP LLM Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)，具体授权仍由执行层保证。

## 4.27 解释器、编译器与虚拟机

适用：实现一门语言、表达式、查询语言、模板语言、正则引擎或字节码虚拟机的代码；执行不可信源码时尤其要查。调用 eval 的一方见[4.22](#422-子进程动态执行与解码器副作用)。

| 检查点 | 什么算问题 |
| --- | --- |
| 语义依据 | 对照的规范、参考实现和版本是什么；偏离处有没有记录；与参考实现有没有差分对照 |
| **计量覆盖** | 步数、时间、内存、深度、输出大小的预算是否覆盖所有语法结构和内建函数；内建函数（重复、拼接、排序、正则、大数运算、字符串增长、集合展开）能否在一次调用内绕过计量 |
| 编译期成本 | 词法、语法、类型检查、优化和宏展开本身对恶意源码是否有界（深嵌套、超长标识符、指数级推导或展开） |
| **宿主边界** | 脚本能否拿到宿主对象、原型或反射入口；借给脚本的输入能否被脚本改写；脚本返回后能否仍持有宿主引用；回调重入宿主时的状态；异常对象、错误堆栈的处理钩子、回调参数能否把宿主对象带进脚本 |
| **进程级状态** | 受信模式或沙箱里的脚本能否改写宿主进程的全局状态（环境变量、工作目录、区域设置、信号处理、已加载的模块、全局配置）；这些改动会不会在脚本结束后留下，被宿主以自己的权限使用（启动子进程、加载库、解析路径） |
| 用户回调 | 引擎调用脚本提供的比较器、访问器、迭代器时：回调结果不一致、抛错、修改正在处理的集合，或再次进入引擎，会怎样 |
| 优化等价 | 常量折叠、内联、类型特化、死代码消除是否保持语义（NaN、负零、整数溢出、求值顺序、副作用、异常时机） |
| 运行状态隔离 | 多次执行或多租户共用引擎时，全局对象、缓存、原型、寄存器和池化对象是否清干净；上一段脚本的数据能否被下一段读到 |
| 值的转换 | 数值、字符串、空值在宿主与脚本之间转换时的宽度、精度、编码与身份（跨语言时见[4.32](#432-跨语言边界与本地扩展)） |
| 错误与定位 | 语法和运行时错误是否带准确位置；错误对象是否泄漏宿主内部信息；经公开入口传入的源码能否触发引擎内部崩溃 |
| 中断与取消 | 长时间运行的脚本能否被外部中断；中断后引擎是否仍可用 |
| 编译缓存 | 缓存键是否包含源码、版本、选项与宿主能力；不同权限上下文是否共用了编译结果 |
| 确定性 | 同一源码与输入是否得到同一结果；随机数、时间、迭代顺序能否控制 |
| 计时精度与侧信道 | 脚本能否拿到高精度计时器或共享内存，借此做推测执行等侧信道；多租户共用进程时是否需要进程隔离 |
| **推测优化的前提** | 按类型、形状、长度特化或删掉检查之后，回调（取值器、`valueOf`、代理、析构）或别的执行流改了对象，优化代码是否仍照旧假设执行；前提失效时有没有去优化或重新检查 |
| **范围分析与检查消除** | 由类型推导或范围分析删掉的边界检查、溢出检查，推导本身对不对（整数回绕、负零、NaN、长度可变）；推导错一处就变成越界读写 |
| **内部哨兵值外泄** | 引擎内部表示「空洞」「未初始化」「无异常」的特殊值，能否经异常、迭代、序列化或错误路径交到脚本手里 |
| 回收与原始引用 | 分配、回收或整理可能发生的点前后，原始指针和未登记的句柄是否仍被使用；分代或增量回收的写屏障有没有漏写 |

## 4.28 隧道、代理与网络数据面

适用：转发他人流量、实现代理协议、VPN 或虚拟网卡、透明代理、NAT、负载均衡，或修改系统路由与名字解析设置的代码。连接层见[4.1](#41-网络与连接)，出站目的地策略见[4.21](#421-出站请求与服务端请求伪造)。

| 检查点 | 什么算问题 |
| --- | --- |
| **自身流量成环** | 本进程的出站连接和名字解析会不会被自己的捕获规则再次接管；靠什么排除（标记、绑定接口、路由例外），排除失效时会怎样 |
| 排除依据被借用 | 让自身流量绕开捕获或策略的依据（运行 UID、cgroup、防火墙标记、源端口、绑定接口），被管控的进程或工作负载能否自己取得，从而绕开整套隔离 |
| **泄漏** | 名字解析、IPv6、本地组播、直连例外是否绕过隧道；隧道未就绪或重连期间是否短暂明文直连 |
| 失效方向 | 隧道断开、配置加载失败、进程崩溃时，流量是被拦下还是回落直连；与产品承诺是否一致（见[29](dimensions.md#29-失效安全与危险操作)） |
| **系统状态残留** | 改过的路由、名字解析设置、防火墙规则、虚拟网卡在崩溃或强杀后是否残留；下次启动能否识别并清理上次的残留；清理会不会误删别人的规则 |
| **开放中继与反射放大** | 未认证者能否把服务当成开放代理、开放解析器或中继；无连接协议在验证源地址前，是否回送比请求大的数据 |
| 流表与映射 | 连接跟踪、NAT 映射、假地址映射有没有上界、超时和回收；表满时怎样；映射被复用导致串流 |
| 分片、MTU 与封装开销 | 封装后超过路径 MTU；分片重组的上界；路径 MTU 探测报文被丢时形成黑洞 |
| 每包成本 | 每个包的分配、系统调用、加锁；突发流量和小包洪水下的吞吐与延迟 |
| 认证与重放 | 代理协议的认证是否绑定会话与方向；握手能否被重放；多用户时流量与配额是否隔离 |
| 协议识别与抗探测 | 仅当目标承诺抗识别时检查：未认证的探测能否认出服务；握手指纹、包长与时序特征；认证失败时的响应是否暴露服务身份 |
| 分流规则 | 按规则分流或拦截时见[4.29](#429-规则与策略匹配) |
| 实时媒体与中继 | WebRTC 等实时通信的中继（TURN）能否被当成开放代理访问内网；ICE 候选是否泄漏内网地址；中继凭据的有效期与范围 |

## 4.29 规则与策略匹配

适用：按规则表放行、拦截、路由、限流、授权或做特征匹配的代码，例如防火墙、访问控制列表、分流规则、WAF、告警规则。

| 检查点 | 什么算问题 |
| --- | --- |
| 匹配语义 | 第一条命中、最长匹配、按优先级数字还是全部求值；是否写明，实现是否一致 |
| **默认动作** | 没有规则命中时是允许还是拒绝；是否符合安全目标 |
| 遮蔽与冲突 | 被前面规则完全遮住、永远不会命中的规则；互相冲突的规则如何裁决 |
| **先归一化再匹配** | 大小写、末尾点、国际化域名编码、IPv4 映射的 IPv6、路径编码、Unicode 规范化在匹配前是否统一；匹配用的表示和实际使用的表示是否相同（见[27](dimensions.md#27-安全与信任边界)） |
| **边界** | 域名后缀是否按标签边界匹配（`example.com` 不应命中 `badexample.com`）；通配符能否跨层级；CIDR 包含关系与端口区间的开闭 |
| 正则与模式 | 缺锚点；多行模式下锚点语义变化；方言差异；回溯成本（见[20](dimensions.md#20-资源上界与背压)） |
| 规模 | 规则上万条时的构建时间、内存与匹配成本；增量更新是否要全量重建 |
| 更新原子性 | 更新规则表时，匹配方看到的是完整的旧表或完整的新表，还是半张表 |
| 可解释 | 能不能查到某个请求命中了哪条规则 |

## 4.30 操作系统接口、系统调用与描述符

适用：直接调用系统调用或内核接口（套接字选项、netlink、ioctl、设备文件）、平台原生 API，或持有原始文件描述符、句柄的代码。跨语言调用见[4.32](#432-跨语言边界与本地扩展)，平台差异见[38](dimensions.md#38-可移植性与构建上下文)。

| 检查点 | 什么算问题 |
| --- | --- |
| **描述符归属** | 原始描述符或句柄被包装成对象后由谁关闭；包装对象被回收时会不会顺手关掉；描述符号被复用后误关了别人的描述符 |
| **跨边界传递的句柄与能力** | 通过进程间通信或消息交给或接自低信任进程（沙箱、渲染进程、客户机、插件）的句柄、能力或共享内存引用，是否确认指向预期对象、只带最小权限；逻辑错误、复用、竞态或对方构造的消息，能否让错误的或权限过大的句柄越过隔离被使用 |
| 中断与重试 | 被信号中断、暂时不可用、只完成一部分的调用，是否按接口约定重试；把它们当成最终失败，或无限重试 |
| 错误码语义 | 错误码只在失败时有效，会被后续调用覆盖；「已存在」「不存在」「权限不足」这类预期状态与真正的故障是否分开处理（见[13](dimensions.md#13-错误处理与失败语义)「失败被后续步骤覆盖」） |
| 结构布局与长度 | 与内核或系统库交换的结构体布局、对齐、字节序、长度字段；读取内核返回的变长消息时是否校验长度 |
| 阻塞模式与继承 | 阻塞与非阻塞模式被意外切换；子进程继承了不该继承的描述符（执行时关闭标志） |
| 线程绑定状态 | 网络命名空间、线程局部的系统状态、界面主线程要求；调用落在了错误的线程上 |
| 特权 | 需要特权的调用失败时的提示与降级；特权操作完成后是否降权（见[4.22](#422-子进程动态执行与解码器副作用)） |
| 信号 | 信号处理函数里只能做异步信号安全的操作；信号掩码与多线程 |
| 资源上限 | 描述符、锁定内存、进程数等上限从哪来；接近上限时怎样 |
| **重复读取不可信内存** | 从用户态、共享内存或另一进程的缓冲区把同一数据读两次，校验用第一次、使用用第二次（double fetch），中间被对方改掉 |

## 4.31 代码生成器与编译期工具

适用：从 schema、IDL、模板或源码生成代码与配置的工具，以及构建期执行的宏、插件和注解处理器。使用生成产物的一方见[39](dimensions.md#39-生成产物与工具链)，数据契约见[4.16](#416-数据模型与生成契约)。

| 检查点 | 什么算问题 |
| --- | --- |
| **输入转义** | schema 或模板里的名字、注释、默认值进入生成代码前是否转义；能否注入代码、提前结束注释或字符串 |
| 名字映射 | 与目标语言的关键字、内置名、其它生成名冲突时怎么处理；映射是否稳定、可逆 |
| 输出确定性 | 同一输入是否生成逐字节相同的产物；是否依赖无序容器、时间戳、绝对路径或环境变量 |
| 输入形状覆盖 | 可选、递归、空集合、深嵌套、联合类型等形状生成的代码能否编译、行为是否正确 |
| 孤儿产物 | 输入删除或改名后旧产物是否清理；清理是否只删自己生成的文件 |
| 生成器版本 | 产物是否记录生成器版本；升级生成器后的差异是否能审 |
| 构建期执行 | 生成器、宏或插件在构建时能访问什么（网络、文件、环境变量）；是否信任它的输入 |
| 验证 | 生成规则或配置契约有没有测试；产物快照是否覆盖有代表性的输入 |

## 4.32 跨语言边界与本地扩展

适用：多种语言混合的仓库，以及通过外部函数接口、本地扩展、嵌入式运行时、WebAssembly、子进程、进程间通信或共享 schema 跨语言协作的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| 边界清单 | 列出每个跨语言边界和方向：谁调谁、数据怎么传、内存和资源归谁 |
| **类型映射** | 整数宽度与符号、浮点、布尔、空值、字符串编码（UTF-8、UTF-16、以 NUL 结尾）、时间与时区、枚举未知值，在两侧是否一致 |
| **内存与生命周期** | 跨边界的指针或缓冲由谁释放、用哪个分配器释放；有垃圾回收的一侧把内存交给本地代码后，内存是否可能被移动或回收；本地代码是否偷偷保存了回调或指针 |
| **错误与异常跨界** | 异常或 panic 能否穿过边界（很多组合是未定义行为或直接终止进程）；错误码与异常如何互转，是否丢了上下文 |
| 并发与线程 | 全局解释器锁的获取与释放；回调在哪个线程执行；本地代码的线程安全假设与宿主是否一致 |
| 构建与分发 | 本地扩展的编译器、ABI、平台矩阵；预编译二进制的来源与校验（见[36](dimensions.md#36-供应链与制品完整性)）；运行时查找库的搜索路径能否被劫持 |
| 定义同源 | 两侧的数据定义是否由同一份 schema 生成；手写的两份定义是否对得上（见[4.16](#416-数据模型与生成契约)、[5](dimensions.md#5-关联与影响面)） |
| 信任方向 | 内存不安全的一侧处理不可信输入时，出错会不会破坏内存安全一侧的保证 |
| 贯通测试 | 边界两侧有没有贯通的测试，还是两侧各自对着替身测试（见[41](dimensions.md#41-测试质量)「替身偏差」） |

## 4.33 构建脚本、持续集成与基础设施即代码

适用：构建脚本与打包配置、持续集成与发布工作流、容器镜像定义、部署清单、基础设施即代码。供应链总体见[36](dimensions.md#36-供应链与制品完整性)，运行环境见[34](dimensions.md#34-运行环境与部署契约)。

| 检查点 | 什么算问题 |
| --- | --- |
| **工作流注入** | 事件里的字段（标题、分支名、提交信息、评论）被直接拼进脚本或命令 |
| **特权触发器** | 在拥有密钥或写权限的上下文里检出并运行外部贡献者的代码 |
| 令牌权限 | 工作流令牌与云凭据的默认权限是否收窄到最小；有没有改用短期凭据 |
| 第三方步骤固定 | 引用的外部动作、镜像、脚本是否固定到不可变的摘要，而不是可移动的标签或分支 |
| 秘密暴露 | 秘密是否进入日志、制品、镜像层、缓存，或对外部贡献者可见的上下文 |
| 镜像 | 以最高权限运行；基础镜像没有固定；构建时把凭据写进镜像层；下载文件不校验 |
| 部署清单 | 特权容器、挂载宿主目录、使用宿主网络、没有资源限制、没有健康检查、使用默认服务账号 |
| 基础设施权限与暴露 | 公开的存储桶、对全网开放的安全组、过宽的角色；状态文件里的秘密 |
| 漂移与可复现 | 声明与真实环境是否一致；手工改动会被下次应用覆盖，或反过来覆盖声明 |
| 脚本健壮性 | 构建脚本出错时是否中止（Shell 细节见[附录 A](lang-shell.md)）；并行构建的顺序依赖；清理步骤的删除范围 |
| 自托管执行器 | 公开仓库的工作流是否跑在自托管执行器上；执行器是否每个任务用完即弃，还是会被外部提交留下后门、读到后续任务的秘密 |

## 4.34 可发布的库、SDK 与包

适用：作为包、库、SDK、插件或共享库被他人安装、引用或链接的单元。

| 检查点 | 什么算问题 |
| --- | --- |
| 公开面 | 实际导出的符号、入口、子路径是否就是打算公开的；内部实现能否被外部直接引用 |
| **破坏性变更** | 公开接口、二进制接口、默认行为、错误类型的变更是否与版本号承诺一致；有没有差异检查 |
| 独立构建 | 脱离仓库工作区与本地覆盖后能否构建和测试（见[38](dimensions.md#38-可移植性与构建上下文)） |
| 声明与实际 | 声明的最低运行时、平台、依赖范围与代码实际要求一致；依赖范围太宽会引入没测过的版本，太窄会与使用方冲突 |
| 发布内容 | 包里是否夹带测试数据、秘密、本地路径、构建缓存；需要的文件是否都在 |
| 安装与加载期行为 | 安装、导入或加载时是否执行代码、联网或改全局状态 |
| 对宿主的礼貌 | 是否修改进程级全局（默认客户端、日志配置、信号处理、环境变量、全局随机种子）；是否直接退出进程（见[13](dimensions.md#13-错误处理与失败语义)、[37](dimensions.md#37-互操作性与共存)） |
| 类型与元数据 | 类型声明、许可证、仓库地址、弃用标记是否齐全准确 |
| 多副本并存 | 同一个库的两个版本或两种模块格式同时加载时，全局状态和类型判断是否分裂 |
| 漏洞接收与支持范围 | 是否写明漏洞报告渠道、受支持的版本和修复时限；修复后是否发布安全公告并标明受影响版本 |

## 4.35 客户端应用、扩展与自动更新

适用：桌面、移动端、浏览器扩展、常驻客户端等运行在用户设备上的应用。界面本身见[4.18](#418-用户界面与可访问性)。

| 检查点 | 什么算问题 |
| --- | --- |
| **自动更新** | 更新包是否签名并在安装前验证；更新通道能否被降级或替换；更新失败能否回退 |
| **外部唤起** | 自定义协议、深链接、导出的组件、进程间接口能否被其它应用或网页调用；传入参数是否校验，会不会被当成程序自己的命令行开关 |
| **交给系统打开的地址** | 把对端、网页或模型给的地址交给系统默认程序打开（`open`、`start`、`xdg-open`、`shell.openExternal`）前，是否限定为 `https:` 等预期协议，并避免经过命令解释器 |
| **下载来源标记** | 下载、解包、另存，或从邮件、聊天里取出的文件，是否把系统的来源标记（Windows 的 Mark-of-the-Web、macOS 的隔离属性）带到新文件上；解包产物、临时副本、快捷方式漏标，系统就不再警告或检查签名 |
| **完整性覆盖范围** | 代码签名与完整性校验是否覆盖运行时会加载并执行的全部文件（快照、旁挂数据、插件、脚本、配置），还是只签了主程序；没被覆盖的文件能否被本地改写 |
| 扩展的消息来源 | 内容脚本发来的消息是否按不可信输入处理；`externally_connectable` 和外部消息处理是否限定来源；网页能否借扩展的高权限接口发请求或读数据 |
| 扩展的权限与暴露资源 | 主机权限是否收窄到必需的站点；`web_accessible_resources` 是否最少（这些资源能被网页探测和嵌入）；是否加载远程代码 |
| 桌面框架的进程间调用 | 主进程处理渲染进程消息时是否核对发送方页面；预加载脚本是否把整个进程间通信对象或 Node 接口暴露给网页；导航和新窗口是否受限；打包时是否关掉不需要的熔断开关（见[4.47](#447-本机特权组件与本地提权)） |
| **本机控制面** | 本机端口、本地套接字、命名管道是否只对预期主体开放；网页能否经 localhost 或 DNS 重绑访问（见[4.14](#414-服务端请求处理与中间件)） |
| 本地秘密 | 令牌与密钥是存在系统凭据库，还是明文文件；备份与同步会不会带出去 |
| 内嵌网页 | 内嵌浏览器组件暴露给网页的本地接口；加载内容的来源；导航限制 |
| 权限 | 申请的系统权限是否最小；权限被拒后的行为 |
| 生命周期 | 被系统挂起、杀掉、因内存不足回收后的状态恢复；后台运行限制 |
| 离线与弱网 | 离线时的行为；重连后的冲突处理 |
| 崩溃报告与遥测 | 上报内容是否含个人信息（见[30](dimensions.md#30-隐私数据治理与合规)）；用户能否关闭 |

## 4.36 嵌入式、固件与实时约束

适用：运行在微控制器、固件、驱动中，或有实时截止要求的代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **中断上下文** | 中断处理函数里的操作是否可重入、是否有界；与主循环共享的数据如何保护；编译器是否知道这些变量会被异步修改 |
| 栈与静态内存 | 最坏栈深度算过没有；禁止或限制动态分配时是否遵守 |
| 时序 | 最坏执行时间与截止时间；优先级反转；忙等与看门狗 |
| **掉电与写入** | 写闪存时掉电；写入寿命与磨损均衡；配置区有没有双份与校验 |
| 固件更新 | 更新包签名；A/B 分区与回滚；更新中断后能否启动 |
| 外设与寄存器 | 寄存器访问的顺序与内存屏障；外设超时；硬件勘误的规避 |
| 调试接口 | 发布产品是否关闭调试口与调试输出；读保护是否开启 |
| 环境极限 | 内存、存储、电量极限下的行为；低电压、温度等环境异常 |
| **功能安全** | 涉及人身或设备安全时：有没有危害分析；出错时能否进入安全状态；冗余、看门狗与自检；适用的功能安全标准要求是否满足 |
| **防回滚** | 已签名、但有已知漏洞的旧镜像、引导程序、驱动能否再次被接受；安全版本号是否只增不减、存在攻击者改不了的位置；吊销列表是否随修复一起更新 |
| 内存保护与锁定位 | 内存保护单元或页表的区域是否重叠、顺序是否让低优先级区域盖住受保护区域；锁定位是否在配置完成后设置，复位、休眠唤醒后是否仍然有效；安全相关寄存器复位后的初值是否安全 |

## 4.37 数据处理、批处理与机器学习

适用：批处理作业、数据管道、流处理、分析笔记本、模型训练与推理代码。

| 检查点 | 什么算问题 |
| --- | --- |
| **重跑幂等** | 作业失败后重跑、部分成功后重跑，会不会重复写入或重复计数；输出是否先写临时位置再发布 |
| 数据契约 | 输入 schema 变化、字段缺失、类型漂移时，是报错、跳过，还是静默产出错误结果 |
| 迟到、重复与乱序 | 流处理的时间窗口、水位线与去重 |
| 规模与倾斜 | 数据量增长和键倾斜时的内存与耗时；一次性载入全量 |
| 训练数据泄漏 | 训练集与测试集之间的泄漏；特征用到了预测时刻拿不到的信息 |
| 可复现 | 随机种子、数据版本、依赖版本、硬件差异是否记录 |
| 模型与数据文件 | 加载模型或数据文件是否会执行代码（见[4.22](#422-子进程动态执行与解码器副作用)）；来源是否可信 |
| 笔记本隐藏状态 | 单元格乱序执行留下的状态；输出里夹带的数据或凭据 |
| 个人数据 | 管道中个人信息的最小化、脱敏与删除传播（见[30](dimensions.md#30-隐私数据治理与合规)） |
| 推理边界 | 输入超出训练分布时的行为；置信度被当成事实使用 |
| 公平性与偏差 | 模型或规则对不同人群的结果差异是否评估过；训练数据是否有代表性 |

## 4.38 智能合约与链上交互

适用：部署在任何区块链上、用任何合约语言写的合约，以及调用合约或被合约回调的链模块（如 Cosmos SDK 模块）。DeFi 经济机制见[4.41](#441-defi-经济机制与预言机)，跨链见[4.42](#442-跨链桥与跨链消息)，钱包、签名与链下组件见[4.43](#443-钱包签名与链下组件)，零知识证明见[4.44](#444-零知识证明与电路)，节点与共识见[4.45](#445-区块链节点共识与协议实现)，账户抽象与合约钱包见[4.50](#450-账户抽象与合约钱包)；各合约语言的陷阱见附录 A 的 [Solidity 与 Vyper](lang-solidity.md)、[Solana](lang-solana.md)、[Move](lang-move.md) 表；只给了合约地址时见[非源码目标](targets.md#链上合约地址)。

| 检查点 | 什么算问题 |
| --- | --- |
| 规格与不变量 | 协议的核心不变量（总量守恒、偿付能力、份额与资产对应）写明了吗；有没有不变量测试、模糊测试或形式化验证覆盖 |

| 算术与精度 | 溢出检查、除法取整方向、代币精度换算 |
| **访问控制** | 管理、初始化、升级函数是否受保护；初始化能否被别人抢先调用 |
| 预言机与价格 | 使用能在单笔交易内被操纵的价格；数据过期 |
| 交易排序 | 抢跑与夹击；滑点和截止时间参数 |
| 外部调用结果 | 返回值没检查；向拒收的地址转账导致整体回滚，形成拒绝服务 |
| **任意调用** | 合约是否替调用方执行对方指定的目标地址和调用数据（路由、聚合器、批量执行、跨链适配器）；用户给这个合约的代币授权，能否借这类调用执行 `transferFrom` 转走别人的资产；调用目标和函数有没有白名单 |
| 升级与存储布局 | 代理升级后存储槽冲突；初始化函数与构造函数的差异 |
| **升级流程** | 升级时是否执行了新版本需要的全部初始化（如 `reinitializer`），漏掉的变量会停在零值；新实现是否还保留升级入口；升级前后的存储布局是否逐项对比；升级交易是否先在分叉环境里演练 |
| 升级模式 | UUPS：`_authorizeUpgrade` 是否有权限检查，新实现是否仍带升级函数；信标代理：一次升级影响所有代理，信标归谁；Diamond（EIP-2535）：`diamondCut` 的权限、切面之间的函数选择器冲突、`diamondCut` 的初始化参数会用 `delegatecall` 执行任意地址的代码 |
| 代理与构造函数 | 实现合约的构造函数写的存储，代理看不到；`immutable` 值写在实现合约的代码里，所有代理共用同一个值；实现合约是否在构造函数里调用 `_disableInitializers` |
| 存储布局演进 | 升级前后变量的顺序与类型、继承顺序、预留的存储间隙（`__gap`）是否一致；是否改用按命名空间划分的存储（ERC-7201） |
| **部署脚本与参数** | 每条链上的依赖地址（预言机、代币、路由）是否对应正确；部署和初始化是否在同一笔交易里完成；部署后所有权和各角色是否移交给多签或时间锁；测试网和主网参数是否不同 |
| **部署版本与审计版本** | 链上字节码是否对应审计过的提交；审计后新增或改动的代码、新上线的模块和路由有没有审计；审计范围外却被调用的合约 |
| Gas 与循环 | 随用户数增长的循环；超过区块 gas 上限后永久无法执行 |
| **签名与重放** | 链下签名（许可、元交易、订单）是否绑定链标识、合约地址、随机数与截止时间，是否采用带域的结构化签名（如 EIP-712）；签名可延展性；验签返回零地址或空结果时是否拒绝；密钥与签名流程见[4.43](#443-钱包签名与链下组件) |
| 重组与确认 | 链下服务按尚未最终确认的区块改业务状态；链重组后是否回滚；验证者较少的链可能在事后经协商回滚已确认的区块 |
| 代币的非标准行为 | 转账收手续费、余额会自动变化、没有返回值、带回调、有黑名单或可暂停、精度不是 18 位的代币，是否都按实际收到的数额计算 |
| 更多非标准代币 | 额度从非零改成非零时回滚（要先清零）；零额转账或零额授权回滚；数额超过 `uint96` 就回滚；同一余额有多个合约入口，按代币地址做的防护会被另一个入口绕过；可升级、可闪电铸造的代币；原生币同时有 ERC-20 形式；传最大值时只转全部余额 |
| **权限持有者** | 管理员、所有者、升级者、暂停者是单个外部账户、多签还是时间锁；多签门限与签名者分布；权限能否被放弃或转移，转移是否两步确认 |
| **权限移交** | 部署者、开发者、测试用的地址是否还保留某个角色、代理管理权或升级权；是否按角色授予和撤销的事件逐个核对，而不是只看 `owner()` |
| 紧急机制 | 暂停、限额、断路器是否存在；谁能触发、谁能解除；暂停期间用户能否取回资产；升级出错时有没有不必等完整时间锁的止损手段，它本身的权限是否受限 |
| 跨链地址假设 | 同一地址在另一条链上不一定属于同一个人：多签、合约钱包在目标链上还没部署时，别人能否抢先部署到这个地址；向这类地址转账前，是否确认它已部署且所有者一致 |
| 链上随机数服务 | 使用可验证随机函数（如 Chainlink VRF）时：请求与结果是否按请求标识对应；确认块数是否足以抵抗重组；是否允许重新请求或取消；请求发出后是否还接受用户输入；回调会不会回滚（服务不会重试） |
| 链上数据公开 | 链上所有存储、调用数据和事件都能被任何人读取，`private` 变量也不例外；提交—揭示中的明文、口令、答案不能直接上链 |
| 默克尔空投与领取 | 领取状态按什么去重（序号、地址还是叶子）；多重证明用的库版本是否受已知缺陷影响；默克尔根由谁生成、能否被替换 |
| 分叉代码 | 从知名协议分叉的代码，是否与上游逐处对比改动；改了一个常数，是否同步改了依赖它的所有地方；上游后来修的漏洞是否同步 |
| 测试环境真实性 | 测试是否在主网分叉上用真实的代币、预言机和依赖协议状态跑过；模拟对象会不会掩盖非标准代币和外部合约的真实行为；是否在目标链的测试网跑过 |
| 验证的前提 | 形式化验证和不变量测试的前提（循环展开上限、被简化的外部调用、排除的输入范围）是否写明；前提条件互相矛盾时规则在任何实现下都通过（空洞规则），是否做过这类检查 |
| 外部依赖合约 | 依赖的预言机、路由、代币和其它协议的地址是写死还是可改；它们被升级或被攻破时本协议会怎样 |
| 账户模型假设 | 用 `tx.origin`、代码长度判断「对方是外部账户」；EIP-7702 之后外部账户也能带代码，这类判断不再可靠 |
| 编译器与目标链 | 编译器版本是否固定，是否受已知编译器缺陷影响；编译出的操作码目标链是否支持；同一份代码部署到多条链时的差异 |
| 链上可观测 | 关键状态变化有没有事件；事件字段是否足以让监控和索引还原状态；异常大额流出有没有告警 |

## 4.39 支付、账务与计费

适用：处理付款、退款、余额、积分、账单、发票或计费的代码。金额的数值与舍入见[14](dimensions.md#14-边界数值与文本)，流程绕过见[9](dimensions.md#9-业务逻辑与流程完整性)。

| 检查点 | 什么算问题 |
| --- | --- |
| **账本不变量** | 是否采用复式记账或等价的守恒约束；每笔交易借贷是否平衡；余额能否由流水重新算出 |
| 流水不可改 | 已入账的记录是否只追加、不修改、不删除；更正是否通过冲正记录完成 |
| **扣款幂等** | 调用支付渠道时是否带幂等键；超时或响应丢失后重试会不会重复扣款；回调和主动查询的结果冲突时以谁为准 |
| 对账 | 与支付渠道、银行流水是否定期对账；差异如何发现、记录和处理 |
| 金额与币种 | 金额用整数的最小单位或定点小数；币种随金额一起存；汇率的来源、时间和取整规则 |
| 价格快照 | 下单时的价格、优惠、税率是否快照保存；之后调价或改规则会不会改变已成交的订单 |
| 退款与拒付 | 部分退款、多次退款、拒付的累计是否可能超过原支付；退款是否原路返回；退款与发货、积分的联动 |
| **余额并发** | 并发扣减会不会透支；冻结、解冻、过期的状态是否一致（见[23](dimensions.md#23-事务原子性与一致性)） |
| 账单与发票 | 编号是否连续且不重复；开具后能否被改；税额按行还是按总额取整 |
| 订阅与计量 | 续费、升降级、试用到期、按用量计费的边界与时区；计量数据丢失或重复时怎么处理 |

## 4.40 通知与外发消息

适用：发送邮件、短信、语音、推送、站内信，或向外部地址回调的代码。模板与转义见[4.17](#417-模板与文本输出)，外发目的地见[4.21](#421-出站请求与服务端请求伪造)。

| 检查点 | 什么算问题 |
| --- | --- |
| **短信与话费欺诈** | 攻击者能否批量触发发往高价号码或大量号码的短信、语音验证码，让费用失控；有没有按号码、国家、账号、来源的限额 |
| 被当成垃圾中继 | 能否向未验证的任意地址发送带用户可控内容的邮件或消息，被人用来发垃圾或钓鱼 |
| 头部与内容注入 | 收件人、主题、发件人名里的换行能否注入邮件头；消息里的链接与内容是否转义 |
| 发送时机 | 事务回滚后通知已经发出；重试导致重复通知；消息里的状态与最终状态不一致 |
| 退订与同意 | 营销类消息有没有退订入口并被遵守；同意记录见[30](dimensions.md#30-隐私数据治理与合规) |
| 退信与失效地址 | 退信、投诉、失效的推送令牌是否被处理，避免持续发送、损害发信信誉 |
| 发信身份 | 发信域名的 SPF、DKIM、DMARC 是否配置；推送与短信通道的凭据存放 |
| 内容泄漏 | 通知里是否带了不该带的敏感信息；锁屏预览、转发、抄送时会暴露什么 |

## 4.41 DeFi 经济机制与预言机

适用：借贷、交易所（自动做市商与订单簿）、收益聚合、稳定币、衍生品、质押等链上金融协议。合约通用检查见[4.38](#438-智能合约与链上交互)。

| 检查点 | 什么算问题 |
| --- | --- |
| **价格操纵** | 价格来自可被单笔交易操纵的来源（自动做市商的即时储备、薄市场的最新成交）；闪电贷能否在一笔交易内借入、操纵、获利、归还 |
| **预言机数据** | 预言机价格是否检查了更新时间与有效性；二层网络上是否检查排序器在线；多个价格源不一致或失效时怎么处理 |
| 时间加权价格 | 时间加权平均价的窗口是否足够长；低流动性时能否在多个区块内被持续操纵 |
| **份额与取整** | 存入、取出时份额计算的取整方向是否偏向协议；首个存款人能否通过直接捐赠抬高份额价格，让后来者的份额取整为零（金库通胀攻击） |
| **新市场与空池** | 新的借贷市场、金库或交易池在总量为零或极小时上线：创建、开放存借、设置抵押系数是否在同一笔交易里完成；上线前是否先存入无法取回的初始份额；份额价格或汇率被直接捐赠抬高后，会不会被当成抵押品的价格 |
| **资产上架与风险参数** | 低流动性资产（尤其是协议自己的代币）作抵押时，抵押系数、供应上限、借款上限是否按市场深度设定；价格能否被少量资金推高；能否循环存借把抵押份额放大 |
| **喂价选择与换算** | 喂价的交易对是否正是被估值的资产（包装资产、流动性质押代币、锚定币不能直接套用标的的价格）；各喂价的精度与更新间隔不同，是否分别处理；应用自己是否设了合理的价格上下限，而不是依赖预言机合约里已不再使用的最小值、最大值 |
| 拉取式预言机 | 用户自带价格更新的预言机（如 Pyth）：用户能在允许的时间范围内挑一个对自己有利的价格提交；是否限制价格的新鲜度；是否检查置信区间；指数换算是否正确 |
| 价格更新抢跑 | 交易、衍生品按当前预言机价格立即成交时，能否看到待上链的价格更新后抢先下单；是否采用两步下单（先提交请求，再按之后的价格执行） |
| 清算 | 清算的触发条件、奖励与折扣；价格剧烈波动或网络拥堵时能否及时清算；坏账如何处理 |
| 清算的边界 | 还款、补仓被暂停时清算仍在进行；小仓位的清算奖励不够付 gas，无人清算而累积坏账；刚借款就能被清算；清算人能否只清算对自己有利的部分 |
| 利率与累计 | 利息指数的累计精度与更新时机；长时间未更新后一次性结算是否溢出或失真 |
| 治理 | 投票权能否用闪电贷临时借来；提案到执行之间有没有时间锁；紧急提案通道的权限 |
| **法定人数与收购成本** | 通过提案所需票数按总供应还是实际参与计算；参与率低时一个地址能否单独过线；在市场上买入或借入这些票的成本，是否远低于提案能动用的金库和权限；有没有否决、守护者或大额转出上限兜底 |
| **时间锁** | 所有特权操作是否都经过时间锁，有没有能绕过它的角色；延迟能否被改成 0；用户能否在变更生效前退出；排队的操作谁能执行，拆成多笔的操作能否被别人按别的顺序先执行 |
| 提案内容核对 | 投票时审阅的代码是否就是执行时的代码；提案指向的合约能否在投票后被升级或换代码；提案的调用数据是否被独立解码核对 |
| 抢跑与交易排序 | 滑点保护、截止时间、提交—揭示；公开内存池里的交易能否被夹击；私有交易通道的信任假设 |
| 滑点参数的来源 | 最小成交量是否由调用者在链下给出；在合约里用同一个可被操纵的池子现算报价、写成 0，或把截止时间设为 `block.timestamp`，等于没有保护 |
| 交易池钩子 | 带钩子的池子（如 Uniswap v4）：钩子回调是否只允许池管理器调用；任何人都能用你的钩子创建池子时，是否按池子标识区分状态、限制允许的池子；钩子地址里的权限位与实际实现是否一致；可选的外部调用失败会不会堵住用户退出；多个池子共用一个钩子时的状态串扰 |
| 无许可接入 | 允许任何人注册的市场、池子、代币或金库，它们返回的数据（奖励代币列表、价格、余额）是否被当成可信；注册进来的外部合约在回调时能否重入 |
| 质押与验证者 | 质押池的提款队列与罚没如何按份额分摊；替用户向信标链存款时，节点运营者能否抢先用自己的提款凭证存款，把押金归到自己名下 |
| 激励与经济攻击 | 奖励能否被刷量、自我交易，或在一个区块内存入取出套取；参数改动有没有经过经济模拟 |
| 可组合风险 | 依赖的外部协议（代币、借贷池、路由）失效、暂停或被攻破时的连锁影响；只读重入读到中间状态的价格 |

## 4.42 跨链桥与跨链消息

适用：在链之间转移资产或传递消息的合约（含一层与二层之间的消息），以及链下的中继者和验证者。

| 检查点 | 什么算问题 |
| --- | --- |
| **消息验证** | 目标链如何证明消息确实在源链发生：轻客户端、默克尔证明、验证者签名；初始化或升级后，信任根和默认值（如全零根）会不会让任意消息都被当成已验证 |
| **验证者与门限** | 验证者或多签的数量、门限、密钥分布，能否抵抗少数密钥泄漏；谁能更换验证者集合 |
| **消息层安全配置** | 使用第三方消息层（如 LayerZero、Wormhole、CCIP、Hyperlane）时，每条路径要求几个相互独立的验证方、门限多少；是否显式配置，而不是沿用消息层可能改动的默认配置；两端的发送与接收配置是否一致；谁能改配置 |
| **接收入口校验** | 接收消息的函数是否检查调用方是消息层的端点或路由，同时校验源链和源发送方在允许名单里；只查其中一项时，别人能从另一条链或另一个合约发来伪造消息 |
| 重放与唯一性 | 同一消息能否在目标链重复执行；是否绑定源链、目标链、合约地址和序号；源链消息在未最终确认时就被签发时，重组后同一序号可能对应不同内容，按序号去重不够 |
| 目标链执行失败 | 目标链上的执行因 gas 不足或回滚失败后，消息是卡住、可以重试还是丢失；谁能重试、能否改 gas 重试；有序通道里一条失败会不会堵住后面所有消息；失败的消息过期后资产怎么退回 |
| 一层到二层的地址别名 | 一层合约发到二层的消息，二层看到的发送方是加了固定偏移的别名地址；鉴权时是否按别名比较；Starknet 的一层处理函数是否检查 `from_address` |
| 排序器停摆与强制包含 | 二层排序器停摆或审查时，用户只能经一层强制提交，要等较长时间才生效；截止时间、清算、拍卖、预言机过期判断在这段时间里会怎样；恢复后有没有宽限期 |
| 二层提款延迟 | 乐观汇总的提款要等挑战期；协议是否把「已发起提款」当成「已到账」 |
| 账户与参数伪造 | 验证流程依赖的系统账户、合约地址和参数是否校验了真实身份；伪造的系统账户能让签名检查看起来已经通过 |
| 资产对应 | 锁定与铸造、销毁与释放的数量是否总能对上；有没有总量守恒的监控 |
| 最终性 | 源链尚未最终确认或发生重组时，目标链是否已经放行 |
| 限额与暂停 | 单笔与单位时间的转出上限；异常时能否暂停；暂停权限本身是否安全 |

## 4.43 钱包、签名与链下组件

适用：管理私钥、组织签名、提供前端，或运行链下服务（中继、索引、机器人、预言机节点）的代码与流程。

| 检查点 | 什么算问题 |
| --- | --- |
| **密钥托管** | 私钥或助记词存在哪里（硬件安全模块、多方计算、明文文件、环境变量）；谁能接触；备份与恢复流程；私钥和助记词由什么工具、固件生成，工具或固件有已知随机数缺陷时能否定位受影响的地址 |
| **盲签** | 签名者在签名设备上看到的是否就是真正被签的内容；前端或中间服务能否把展示的交易换成另一笔（例如把转账换成委托调用来升级合约） |
| 多签流程 | 签名前是否在独立环境核对交易的调用数据、目标与操作类型；有没有交易模拟与目标白名单；签名者是否在独立设备上自己算出交易哈希，与硬件钱包显示的哈希对照 |
| **预签名与长期有效的签名** | 签好但还没执行的交易、授权或委托多久后仍然有效（Solana 的持久随机数交易、截止时间很远的许可、链标识为 0 的委托授权、链下收集的多签签名）；能否撤销；有没有要求签名者提前签下「以后才执行」的管理操作 |
| 前端与托管 | 前端代码、DNS、CDN、存储桶被篡改后，用户会不会签下恶意授权；前端资源的完整性与部署权限；前端引用的第三方库（如钱包连接库）被投毒后能否直接弹出签名请求，这些依赖是否固定版本并校验完整性 |
| 地址展示与投毒 | 界面是否只显示地址的首尾几位；历史记录里别人伪造的相似地址、零额转账会不会被用户复制；有没有地址簿和相似地址提示 |
| 授权与许可 | 请求用户授予的代币额度是否最小；无限授权、离线许可签名被钓鱼后的影响；用户能否查看与撤销 |
| 节点与数据来源 | 依赖的 RPC 节点、索引服务是否可信；返回数据被篡改或落后时的后果；有没有多源交叉核对 |
| 链下机器人与中继 | 热钱包额度与补充方式；交易卡住、费用上限、随机数冲突的处理；被抢跑时的行为 |
| 看护程序 | 清算、结算、喂价更新依赖的链下程序停摆或延迟时协议会怎样；任何人都能触发的看护入口，能否被人选择对自己有利的时机、顺序和参数 |

## 4.44 零知识证明与电路

适用：零知识电路、证明系统与验证器的实现，包括隐私交易、零知识 rollup、zkVM、链上验证合约和链下证明服务。电路语言的具体陷阱见附录 A 的[零知识电路](lang-zk.md)表，密码学通用检查见[4.4](#44-加密与凭据)。

| 检查点 | 什么算问题 |
| --- | --- |
| **欠约束** | 电路里每个见证值是否都被约束绑定到公开输入、常量或其它已约束的值；只赋值不约束的单元格，让恶意证明者可以自由选值而验证照样通过（Zcash Orchard 2026 年即因标量乘法的基点只赋值未约束，可无限伪造 ZEC） |
| **恶意证明者测试** | 测试是否只用诚实证明者生成的正确见证；有没有「改掉任意一个见证值或换一个绑定值，验证必须失败」的反面测试；有没有用欠约束检测工具或形式化方法检查约束集是否完整 |
| **唯一标识的派生** | 防双花用的唯一标识（nullifier、key image 等）是否由电路完整约束地从秘密与票据派生；同一张票据能否算出多个都合法的唯一标识 |
| **价值守恒** | 电路或共识层是否约束了输入与输出的金额守恒；金额是否有范围约束（防止有限域回绕把负数变成巨额）；有没有独立于证明的总量计量（如按池统计流入流出）作为兜底 |
| **公开输入绑定** | 证明绑定了哪些公开输入；验证方是否自己计算或校验这些输入，而不是照单全收证明者给的值；同一个证明能否配另一组公开输入复用 |
| 输入的规范形式 | 公开输入、域元素、曲线点在验证前是否规约到唯一表示；值 x 和 x 加上域模数能否都通过验证，让同一个标识有两种写法 |
| **挑战与转录** | 每个挑战派生之前，证明者已经发出的每一个值是否都吸收进了转录：承诺、声称的求值结果、证明里由证明者自选的子挑战（如或证明的分支挑战），以及全部公开输入和系统参数；按轮列出「证明者发了什么、此时转录里有什么」，少一项，证明者就能先看挑战再选这个值（缺项导致可伪造证明，即 2022 年多个证明系统实现中的 Frozen Heart 问题） |
| **可信设置与参数** | 需要可信设置的方案，参数生成仪式的参与方与「有毒废料」如何销毁；参数与验证密钥是否可验证、是否与电路版本对应（Zcash 2019 年披露的 CVE-2019-7167 即因参数中多出的元素可伪造证明） |
| 证明可延展性 | 证明本身能否被变换成另一个同样有效的证明；不能把证明当作唯一标识或防重放键 |
| 验证器实现 | 链上验证合约与链下验证实现：配对与点运算的输入校验、预编译调用的返回值、验证密钥是否写死且与电路对应 |
| 递归与聚合 | 递归或聚合验证时，内层证明的验证密钥、公开输入与电路身份是否被外层约束 |
| zkVM 与执行跟踪 | 执行跟踪的约束是否覆盖每条指令的全部语义；内存读写一致性检查；系统调用与预编译的约束 |
| 编译器与工具链 | 电路编译器、约束生成器、证明库的版本与已知缺陷；优化后的约束与源码语义是否一致 |
| 证明者与验证者一致 | 证明端、验证端、各客户端使用的电路版本、参数与哈希实现是否一致；升级电路时旧证明怎么处理 |

## 4.45 区块链节点、共识与协议实现

适用：区块链节点、共识引擎、交易验证、点对点网络，以及钱包核心、轻客户端等协议实现。合约层见[4.38](#438-智能合约与链上交互)，零知识部分见[4.44](#444-零知识证明与电路)。

| 检查点 | 什么算问题 |
| --- | --- |
| **共识确定性** | 所有节点对同一输入必须算出同一结果：浮点运算、无序容器的遍历、依赖库版本、本地时间、并发顺序都可能造成分歧；不同客户端实现之间的差异会导致链分叉 |
| **总量与双花校验** | 交易内、区块内的重复输入；金额相加溢出；手续费与出块奖励的计算；这些检查是否在所有验证路径（交易池、区块、重组后重放）都执行（比特币 2010 年 CVE-2010-5139 金额溢出凭空产生约 1840 亿 BTC；2018 年 CVE-2018-17144 为了性能跳过了区块内重复输入检查） |
| 交易池与区块路径一致 | 进入交易池时的校验与打包进区块、接收区块时的校验是否相同；有没有只在一条路径上的检查 |
| 对等网络消息 | 对等节点消息的大小、数量、计算成本是否有上限；恶意节点能否耗尽内存、CPU、连接或磁盘；能否把节点与诚实网络隔开（日蚀攻击） |
| 升级与激活 | 分叉的激活高度或条件、新旧规则切换的边界；未升级节点的行为；紧急软分叉的开关与权限 |
| 签名与编码规范性 | 签名、交易、区块的非规范编码能否被接受，造成交易标识可延展；重放保护（链标识） |
| 时间与难度 | 区块时间戳规则、难度调整能否被操纵（时间扭曲）；依赖本地时钟的逻辑 |
| 重组处理 | 深度重组时状态、索引、交易池与钱包余额的回滚 |
| **隐私池的总量计量** | 金额被隐藏的池子有没有独立的流入流出计量（如 Zcash 的 turnstile），在证明系统出错时限制伪造的损失；有没有持续的总量监控 |
| 轻客户端与证明 | 轻客户端依赖的头部链、默克尔证明、签名是否完整校验 |
| 状态与存储 | 状态树的一致性、修剪与快照恢复；损坏数据能否让节点停在错误状态 |
| **验证结果缓存** | 签名、证明、脚本的验证结果被缓存时，键是否覆盖全部验证上下文且编码无歧义（变长字段要有长度前缀）；命中缓存会不会跳过本应重新检查的条件 |

## 4.46 联合身份与单点登录

适用：作为客户端、资源服务或签发方使用 OAuth 2、OpenID Connect、SAML 的代码，接受 NTLM、Kerberos 这类质询式认证的服务，以及为账号签发证书、票据的代码。会话与令牌的通用检查见[4.5](#45-认证会话与令牌)，验签见[4.4](#44-加密与凭据)。

| 检查点 | 什么算问题 |
| --- | --- |
| **回调地址** | 授权服务是否按预先登记的完整地址逐字比较回调地址；通配、前缀、子路径匹配，或允许的域名上有开放重定向，都会把授权码或令牌送到别处 |
| **state、PKCE 与授权码** | 授权请求是否带与当前会话绑定的 state 或 PKCE；请求带了 `code_challenge` 时，换令牌缺 `code_verifier` 是否拒绝；是否拒绝 `plain` 方法；授权码是否只能用一次、绑定客户端与回调地址，重复使用时是否吊销已签发的令牌 |
| 多个身份提供方 | 对接多个授权服务时，是否核对响应里的签发方（`iss`），或按提供方区分回调地址，防止把一方的授权码交给另一方 |
| **ID 令牌与访问令牌** | ID 令牌是否校验签发方、受众等于本客户端、有效期和 nonce；能否拿签给别的客户端的令牌登录本应用；资源服务是否校验访问令牌的受众是自己 |
| 账号定位与关联 | 本地账号是否按签发方加主体标识（`iss` + `sub`）定位；「绑定第三方账号」流程有没有防跨站，攻击者能否把自己的外部账号绑到受害者名下 |
| 已弃用的流程 | 是否仍用隐式流程或口令直传流程；令牌是否出现在地址片段、浏览历史或 Referer 里 |
| 客户端类型与凭据 | 移动端、单页应用这类公开客户端里是否带着客户端密钥；机密客户端在令牌端点是否用抗重放的方式认证 |
| **SAML 断言** | 是否要求业务实际读取的那个断言带有效签名，拒绝未签名的；受众、接收方、目的地址、有效期、`InResponseTo` 是否都校验；断言标识是否记录以防重放 |
| **XML 解析一致** | 验签和读取属性是否用同一个解析器、同一份解析结果；DOCTYPE、注释、命名空间、重复元素在两次解析中是否一致（另见[4.24](#424-webhook-与外部事件)「验证对象」） |
| **质询认证的中继** | 接受 NTLM 或同类质询响应认证的服务，是否要求签名，或把认证绑定到 TLS 通道和目标服务名（扩展保护）；否则被诱导发起的认证可以转手登录这个服务 |
| 签发凭据时的身份来源 | 签发证书、票据或令牌时，主体名是否取自申请者自己能改的属性（主机名、显示名、邮箱）；按名字查不到时是否回退到加后缀、去域名等变体，落到另一个主体；被信任的字段是否都在签名保护内 |

## 4.47 本机特权组件与本地提权

适用：以高于调用者的权限运行，又接受本机其它用户或进程的请求、或处理它们碰得到的文件的代码，例如 Windows 服务、macOS 特权助手与 XPC 服务、Linux 的 setuid 程序、D-Bus 与 polkit 服务、安装与更新程序、带系统权限的代理与安全软件。本机控制口的开放范围见[4.35](#435-客户端应用扩展与自动更新)，子进程的环境继承见[4.22](#422-子进程动态执行与解码器副作用)，系统调用本身见[4.30](#430-操作系统接口系统调用与描述符)。

| 检查点 | 什么算问题 |
| --- | --- |
| **调用方身份** | 命名管道、本地套接字、XPC、D-Bus、ALPC 的服务端靠什么认调用方：内核随消息给出的凭据（审计令牌、`SO_PEERCRED`、代码签名要求），还是进程号、自报的名字或路径；先取进程号再查询有竞争，进程号会被复用 |
| **在低权限可写位置操作文件** | 特权进程在用户可写的目录（临时目录、日志、用户配置、共享数据目录）里创建、移动、删除或改权限时，路径的任一级能否在中途被符号链接、目录联接、硬链接或机会锁换成系统文件 |
| **可执行路径与加载顺序** | 服务或计划任务的程序路径含空格却没加引号；特权执行的程序、脚本、插件、库所在的文件或目录对低权限用户可写；库的搜索顺序会先找当前目录、应用目录或 `PATH` 里的可写目录 |
| 调用方可控的环境 | 特权组件是否按调用方可控的环境变量（`HOME`、`TMPDIR`、`PATH`、区域设置）或用户可改的配置，去定位自己的安全数据库、辅助程序和日志 |
| 借用权限的注入 | 持有系统隐私授权、特殊权利或提权能力的程序，是否允许加载未签名的库或被注入代码（动态库环境变量、关闭库校验、调试权利、Electron 的 `RunAsNode` 开关）；允许时，本机任何程序都能借它的权限 |
| 模拟调用者 | 服务模拟客户端身份后，每个退出路径是否都恢复自身身份；服务作为客户端去连低权限用户能创建的管道或路径时，是否禁止对方模拟自己 |
| 降权 | 放弃权限的顺序是否正确（先附加组，再组，最后用户）；每一步的返回值是否检查；降权后是否确认拿不回原权限 |
| 安装、修复与卸载 | 以高权限运行的安装、修复、更新流程，是否从用户可写的目录加载文件或执行脚本；卸载后特权助手、服务、计划任务和驱动是否一并删除 |

## 4.48 内核驱动、设备仿真与虚拟化

适用：内核模块与驱动（包括 GPU、显示、存储、安全软件的驱动），以及虚拟机监控器、设备仿真、半虚拟化后端这类以高权限处理低信任方请求的底层代码。系统调用与描述符的一般问题见[4.30](#430-操作系统接口系统调用与描述符)，内存安全见[16](dimensions.md#16-语言与运行时陷阱)。

| 检查点 | 什么算问题 |
| --- | --- |
| **设备入口的访问控制** | 设备节点或设备对象是否允许普通用户打开；每个控制码（IOCTL）是否按调用者权限单独检查，而不是「能打开就能调」 |
| **危险原语** | 是否向用户态提供读写任意物理内存、内核地址、MSR、I/O 端口，或映射任意内存段的能力；这类驱动签名发布后，会被别人带到其它机器上提权 |
| 用户指针与长度 | 来自用户态的指针、长度、偏移是否在访问前校验（范围、对齐、是否落在对象开头），并一次复制进内核；直接访问用户缓冲的方式是否先探测；同一数据是否读两次（见[4.30](#430-操作系统接口系统调用与描述符)「重复读取不可信内存」） |
| 内核信息泄漏 | 复制给用户态的结构是否先清零（填充字节、没写满的数组）；错误路径和日志是否带出内核地址 |
| **映射的生命周期与权限** | 把内核、设备或 GPU 内存映射给用户态后，页面释放、迁移或权限变更时映射是否同步撤销；只读页面能否经设备侧的映射被写 |
| 对象与并发 | 控制码处理与关闭、释放、设备移除并发时，引用计数和锁是否覆盖；用户态能否用多线程、缺页之类手段把竞争窗口拉长 |
| **客户机控制的设备仿真** | 虚拟设备的寄存器值、DMA 描述符、环形队列下标都由客户机控制：是否校验后只读一次再用；默认启用、实际用不到的遗留设备是否扩大了攻击面 |
| 签名与阻止列表 | 发布的驱动出现漏洞后，是否吊销签名或提交到系统的漏洞驱动阻止列表；加载第三方驱动的一方是否执行阻止列表 |

## 4.49 移动应用组件与进程间通信

适用：Android、iOS 应用的源码，包括原生代码、跨平台框架和内嵌网页。只有安装包时见[非源码目标：移动应用包](targets.md#移动应用包)；通用的客户端检查见[4.35](#435-客户端应用扩展与自动更新)。

| 检查点 | 什么算问题 |
| --- | --- |
| **导出组件** | 导出的活动、服务、广播接收器、内容提供者是否有权限保护，或在代码里核对调用方；以系统或高权限身份运行的组件能被任意应用调用 |
| **意图转发** | 收到的 Intent 里嵌着另一个 Intent、组件名或 URI，被原样拿去启动或授权，让外部应用借本应用的身份打开未导出的组件、读取私有文件 |
| 待定意图 | PendingIntent 是否用显式意图并设为不可变；可变或隐式的 PendingIntent 交出去后，目标和数据能否被改写 |
| 内容提供者与文件共享 | FileProvider 暴露的目录是否过宽（根目录、整个数据目录）；`openFile` 与查询是否挡住路径穿越和 SQL 注入；是否信任对方给的文件名 |
| **深链接与网页容器** | 深链接参数能否让应用内 WebView 加载任意网页；原生桥（`addJavascriptInterface`、`WKScriptMessageHandler`）是否只对可信来源开放；WebView 的文件访问开关 |
| 登录回调 | 授权回调用自定义 scheme 时，其它应用能否注册同一个 scheme 截获授权码；是否改用经验证的应用链接或通用链接，并配合 PKCE |
| 本地生物识别 | 生物识别结果只是一个真假回调，还是绑定到硬件密钥库里的密钥（Android 的 `CryptoObject`、iOS 钥匙串的访问控制）；回调被篡改成「通过」时会怎样 |
| 敏感数据外溢 | 剪贴板、后台快照与截屏、系统备份、日志、键盘缓存、外部存储里是否留下令牌与个人数据 |
| 覆盖层与任务劫持 | 敏感按钮能否被透明覆盖层诱点；任务亲和性配置能否让恶意应用冒充本应用的界面 |

## 4.50 账户抽象与合约钱包

适用：合约账户（智能钱包）及其模块，账户抽象的入口合约与支付方（paymaster），EIP-7702 的委托目标合约，以及需要验证合约账户签名（ERC-1271）的代码。私钥、前端与签名流程见[4.43](#443-钱包签名与链下组件)，合约通用检查见[4.38](#438-智能合约与链上交互)。

| 检查点 | 什么算问题 |
| --- | --- |
| **入口限制** | 执行与验证函数（如 ERC-4337 的 `validateUserOp`、`execute`）是否只允许可信的入口合约或账户自己调用；别人能否直接调用、绕过签名验证 |
| 验签结果与随机数 | 签名不匹配时是按规范返回失败码，还是直接回滚；生效时间与过期时间是否写进返回值并被检查；随机数的键与序号能否被重用 |
| **反事实地址** | 账户还没部署时预先算出的地址，是否由所有者和初始配置决定；别人能否抢先在同一地址部署一个所有者不同的账户 |
| **支付方** | 替用户付 gas 的合约是否校验它同意赞助的内容（调用目标、额度、有效期、链标识与入口合约地址都要在签名里）；每个用户有没有额度；执行后收费失败时会不会白付；押金能否被刷空 |
| 验证阶段的限制 | 验证阶段是否用了打包方禁止的操作码或存储访问（ERC-7562），导致操作被拒、账户无法使用 |
| 模块与会话密钥 | 可安装的验证、执行、钩子模块有多大权限；安装和卸载由谁批准；会话密钥是否限定目标、函数、额度和期限；卸载后残留的状态和授权 |
| **合约账户签名** | 只用 `ecrecover` 验签，会拒绝合约钱包；ERC-1271 的返回值是否与魔术值精确比较；同一外部账户拥有的多个合约账户之间，签名能否互相重放（需要把账户地址放进被签内容，如 ERC-7739）；尚未部署的账户的签名（ERC-6492）怎么验；有意跨链重放的管理操作按下标还是按身份指定对象（见[4.4](#44-加密与凭据)「按位置引用的授权操作」） |
| **EIP-7702 委托初始化** | 设置委托和初始化不在同一步完成：初始化参数是否要求外部账户的私钥签名，否则别人能抢先初始化 |
| 委托切换与存储 | 外部账户换委托目标后旧存储还在，新合约按自己的布局会读到旧数据；委托目标是否使用按命名空间划分的存储（ERC-7201） |
| 委托授权的范围 | 链标识为 0 的委托授权在所有链上都有效；钱包是否把「签委托授权」当成「交出整个账户」来提示；委托目标合约自身有没有重放保护，有没有限制调用目标和金额 |
| 代付交易的中继 | 替外部账户代付的中继者，是否会被账户在上链前清空余额、改随机数或撤销授权而白付 gas；有没有押金或信誉机制 |
