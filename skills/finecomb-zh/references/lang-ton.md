# A.19 TON（FunC、Tact、Tolk）

TON 合约之间只通过异步消息交互，每条消息在各自的交易里执行。EVM 里「一笔交易要么全成功、要么全回滚」的直觉在这里不成立。

| 检查点 | 什么算问题 |
| --- | --- |
| **转入通知的来源** | 收到 Jetton 转入通知时，是否校验发送方就是本合约自己对应的 Jetton 钱包地址；要接收任意 Jetton 的合约或链下服务（桥、充值入口），是否核对发送方钱包的代码哈希和所属主合约；否则任何人都能伪造「已收到代币」 |
| **跨消息的非原子性** | 一个操作拆成多条消息后，中途某条失败不会撤销前面已经提交的状态；每一步失败后状态是否仍然一致，资产是否可追回 |
| 退回消息 | 带退回标志的消息执行失败后会退回；合约是否处理退回消息，恢复之前扣减的余额或状态 |
| 并发的消息流 | 多条消息流交错到达，状态在两条消息之间被别的流改掉；与重入类似 |
| **外部消息的接受** | 处理外部消息时，是否先验签、检查序号和有效期，再调用 `accept_message()`；否则攻击者可以反复发送同一条消息，耗尽合约余额 |
| gas 与发送模式 | 转发消息时附带的 TON 数额与发送模式（如携带全部余额的模式）是否正确；gas 估算不足让一串消息中途失败 |
| 存储费 | 合约余额被存储费扣光后会被冻结，甚至删除 |
| 代码与数据更新 | `set_code`、`set_data` 由谁触发；升级后数据格式是否兼容 |
| 整数与布尔 | FunC 里真值是 `-1`；整数是 257 位有符号数；按位非与逻辑非混用 |
| 地址格式 | 工作链不同、可退回与不可退回的地址写法不同；比较地址前是否统一成同一种形式 |
| FunC 的 `impure` | 没标 `impure` 的函数，如果返回值没被使用，调用会被编译器删掉，里面的检查也随之消失 |
