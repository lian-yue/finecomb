# A.16 零知识电路（Circom、halo2、Noir 等）

| 检查点 | 什么算问题 |
| --- | --- |
| **只赋值不约束** | Circom 用 `<--` 或 `=` 给信号赋值却没有对应的 `===` 约束（能用 `<==` 就用）；halo2 用 `assign_advice` 写入本应等于某个已有值的单元格，却没有加复制约束（`copy_advice` 或 `constrain_equal`）。Tornado Cash 2019 年与 Zcash Orchard 2026 年的伪造漏洞都属于这一类 |
| 选择器与门的启用 | halo2 自定义门的选择器没有在所有需要的行启用；查找表只约束了部分列；区域之间的相等约束是否连通到真正的来源 |
| 比较与位分解 | 电路里的「小于」没有内置意义：比较和位分解是否同时约束了每一位只能是 0 或 1，以及位数上限 |
| 除法与求逆 | 除法用见证提供商和余数时，是否约束了余数小于除数；对零求逆时的处理 |
| 条件与选择 | 电路没有真正的分支，两条路径都会被计算；用乘法做选择时，选择位是否约束为 0 或 1 |
| 下标与查表 | 用见证值做下标时的约束方式；越界下标 |
| 哈希与承诺 | 电路里的哈希与链下实现是否一致；域元素与字节之间的转换是否唯一 |
| 公开与私有 | 本应公开、需要验证方检查的值被当成私有见证；公开输入的顺序与验证方不一致 |
| 不受约束的计算 | Noir 的 `unconstrained` 函数、Circom 的 `<--` 这类只在证明端运行的计算，其结果是否被后续约束检查 |
| 工具链版本 | 电路编译器与证明库的版本及已知缺陷；可信设置文件、验证密钥与电路版本是否对应 |
