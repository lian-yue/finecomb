# 三、通用维度检查表

## 1 死代码与可达性

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 未使用的声明 | 静态检查结果结合调用图、注册机制、构建条件与外部 API 核对 | 在受支持场景中没有真实用途；不能只凭项目内没有引用判定公开 API 已死 |
| **只有测试在用的生产代码** | 先核对工具能力，再结合生产和测试调用方确认 | 仅为测试服务且没有生产职责；工具两种模式输出的差集只是线索 |
| 不可达分支 | 顺着配置约束和调用方倒推每个分支的真实取值域 | 上游校验已经排除掉的分支（例：某参数被校验为正数，代码里还留着它 ≤ 0 的整套处理） |
| 旧实现残留 | 找别名、包装、转发、旧路径、废弃标记、「曾经叫 X」的注释 | 新实现已替代旧的，旧的还在 |
| 预留设计 | 找没人传的参数、没人读的字段、没接线的开关、只有一个实现且无替换需求的接口 | 「为了以后可能需要」 |
| 死测试 | 未使用的 helper、只覆盖已删路径的用例 | 见[41](#41-测试质量) |

**判定标准**：确认真实用途、可达条件和明确的保留意图后分类。是否删除、注释保留或修改平台代码，统一按项目规范；只读审查只报告分类依据。

## 2 遗留标记与被抑制项

> 这些不是死代码，是**别人留下的未完成事项和被压住的告警**。每一条背后都是一个决定或一个欠账，审查时必须逐条判定还成不成立。

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| TODO / FIXME / XXX / HACK / 待验证 | 全文搜索 | 逐条判定：还成立吗？是谁的责任？该做、该删还是该记进文档？不能默认「留着就行」 |
| 被注释掉的代码 | 搜索连续被注释的代码行 | 有没有写明停下原因；被注释的内容和现行实现是否已经对不上 |
| **静态检查抑制** | 搜索各语言 lint、类型检查和安全扫描的抑制标记（写法见[七](tools.md)的遗留标记一行） | 每个抑制背后是一个决定或一个未修的问题；理由还成立吗、有没有随代码变化过期 |
| 空实现 / 空操作 | 找方法体为空、只返回零值、只 `pass` 或只抛「未实现」的实现 | 是有意的空实现还是没写完；有意的要写明 |
| 「不可能到达」的崩溃点 | 搜索显式终止与断言：panic、abort、assert、unreachable、fatal、进程退出调用、「不应到达」的异常 | 真的不可达吗？公开输入能到吗？发布构建里断言还在吗（见[16](#16-语言与运行时陷阱)）？ |
| 调试残留 | 硬编码开关、恒真条件、临时打印（各语言的 print、console、日志调试级别）、断点语句、写死的测试地址与账号 | 混进生产 |
| **备份与产物残留** | 源码树里的备份目录、副本、编译产物 | 应当清理或明确说明为什么留；它们会污染搜索结果和静态检查 |
| 文档里的「暂时」「以后」「待定」 | 全文搜索 | 过期的计划被当成现行契约 |

## 3 重复

| 检查点 | 怎么查 |
| --- | --- |
| 逐行重复的函数 | 对比同一概念的多个实现（例：后台任务和前台入口各写了一份一模一样的扫描） |
| 复制粘贴的内联逻辑 | 一段逻辑既有独立函数、又在别处被手抄一遍（例：某函数里手抄了另一个已存在函数的整段函数体） |
| 同一判断散落多处 | 同一个快速失败判断在三个入口各写一遍 |
| 同义入口 | 两个公开入口只是互相转发，文档措辞都一样 |
| 平行类型 | 两个结构表达同一件事 |
| 重复常量 | 同一个魔数在多处各写一份 |
| 跨模块重复 | 项目里另一个模块已经有等价能力（见[审查方法](scope.md#审查方法)的对比法） |
| 文档重复 | 同一条事实在多份文档和注释里各写一份，改了一处其它就漂移——见[43](#43-文档一致性) |

## 4 抽象与分层

| 检查点 | 什么算问题 |
| --- | --- |
| 包装层 | 只换名字、不加行为的一层 |
| 抽象的调用方数量 | 只有一个调用方、也没有替换/测试替身/依赖倒置需求的接口或抽象 |
| 接口宽度 | 接口方法没人调 |
| 配置与调用策略 | 长生命周期配置混入单次调用策略；具体参数误用见[10](#10-api-与契约)和[11](#11-易用性与误用防护) |
| 职责归属 | 只服务一个对象的逻辑被拆成游离函数；对象自身的状态/生命周期没有由自己的方法表达 |
| 层级归属 | 业务策略下沉到通用层；通用层里出现特定业务、部署或产品策略 |
| 分层责任 | 分了两层（如句柄层 / 存储层）时，每层的责任有没有被另一层越权或重复实现 |
| 文件组织 | 主流程对象没有独立成文件；出现含义模糊的兜底文件 |

> 依赖方向、循环依赖、层级倒置在[5 关联与影响面](#5-关联与影响面)查；函数与文件的规模在[7 复杂度与可维护性](#7-复杂度与可维护性)查。

## 5 关联与影响面

> 大部分「改一处坏一处」的问题不在单个函数里，而在**东西之间的关系**里。

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 调用图 | 列出目标的调用方和被调用方；项目内谁引用它 | 按「没人用」处理却其实有调用方；改动影响面没算清 |
| **同一事实的多处副本** | 列出同一份数据存在的所有位置：内存、磁盘、计数器、摘要结构、索引、远端 | 副本之间没有明确的对齐时机和对齐者；不一致窗口没定义、没文档化 |
| 关联不变量 | 找「A 改了 B 必须跟着改」的成对状态 | 存在只改一半的路径——**尤其错误路径和提前返回** |
| 隐式耦合 | 通过全局变量、文件系统布局、命名约定、执行顺序建立的依赖 | 依赖没有在代码里表达，改一处静默破坏另一处 |
| 双向映射一致性 | 同一对象的两套定位方式（如「由名字算序号」和「由名字拼路径」） | 两套算法不一致 → 写在 A 处、找在 B 处 |
| 依赖方向 | 下层是否感知上层；有没有环 | 层级倒置、循环依赖 |
| 初始化顺序 | 包/模块级初始化、全局注册表、单例、默认值装配 | 顺序依赖没写明；初始化里做 I/O 或可能失败的事 |
| 跨模块假设 | 本目标对其它模块行为的假设 | 假设没有被对方的公开契约保证 |
| 改动影响面 | 对每个改动列出：谁的行为变了、谁的文档要改、谁的测试要改 | 漏掉调用方、文档或测试矩阵 |

## 6 命名、注释与可读性

| 检查点 | 什么算问题 |
| --- | --- |
| 概念一致性 | 同一概念在不同地方叫不同名字；同一个名字在不同地方指不同东西 |
| 误导性命名 | 取值方法却有副作用；判断方法却修改状态；名字承诺的比实现多或少 |
| 名实不符 | 名字描述的是历史行为（例：字段每次写入都刷新，却叫「创建时间」） |
| 否定式命名 | 双重否定的布尔（`不禁用`、`忽略不检查`） |
| 单位与量纲入名 | 超时没说是秒还是毫秒；大小没说是字节还是条数 |
| 缩写与拼写 | 自造缩写；拼写错误固化进公开 API |
| 作用域与名长 | 短名用在长作用域；冗长名用在一行的局部 |
| 注释解释「为什么」 | 注释只复述代码在做什么，没说为什么这么做、为什么不那么做 |
| 关键约束缺注释 | 不明显的前提、副作用、并发要求、性能特性、失败语义没写 |
| 过时或误导的注释 | 注释描述的是旧实现；注释里出现不存在的名字 |
| 注释规范 | 按项目规范检查注释语言、结构、起始措辞；**多语言注释要检查每种语言是否都写全了**（常见错误：只有一种语言提到某个返回值） |
| 一眼可读 | 不熟悉这段代码的人，能不能只凭代码和注释答出「什么条件下会走到这里、失败会怎样」 |

## 7 复杂度与可维护性

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 分支复杂度 | 复杂度度量工具 | 单个函数分支过多，人无法一次读完、也无法枚举测试 |
| 嵌套深度 | 度量或人工读 | 深层嵌套的条件与循环；能否用提前返回压平 |
| 函数长度 | 度量 | 一个函数做了太多件事 |
| 文件长度与内聚 | 度量 + 人工读 | 一个文件承载多个不相关职责 |
| 出口数量 | 人工读 | 出口过多且分散，难以核对每条出口的清理是否完整 |
| 认知负担 | 人工读 | 需要同时记住多少个上下文才能读懂一段 |
| 自动约束 | 核对项目已要求的检查项与配置 | 约定的检查缺失或失效；没有自动复杂度门槛本身不算缺陷 |

> 参数个数、接口宽度、抽象层数在[4 抽象与分层](#4-抽象与分层)和[10 API 与契约](#10-api-与契约)查。

## 8 功能正确性与需求符合度

> 前面几维问「代码写得好不好」，这一维问最基本的那个问题：**它做的是不是该做的事，做全了没有，做对了没有。**

| 检查点 | 什么算问题 |
| --- | --- |
| 需求覆盖 | 声称支持的能力是不是都实现了；有没有「文档写了、代码没有」 |
| 功能适当性 | 实现的是不是真正被需要的；有没有做了但没人要的 |
| 核心正确性 | 主路径的结果对不对；有没有和权威定义、参考实现、已知向量比对过 |
| **规格来源** | 行为依据是什么——规范、标准、上游文档，还是「看起来应该这样」；无据可依的地方标出来了吗 |
| 遵循外部标准 | 实现某个标准 / 协议 / 格式时，必选项做全了吗；可选项的取舍写明了吗；**偏离标准的地方有没有记录理由** |
| 边界语义 | 空输入、单元素、极值下的行为是不是需求要的（不只是「不崩」） |
| 隐含前提 | 调用场景或上层契约实际依赖的幂等、重入、顺序和身份比较语义是否成立；无法推出的要求不能自行补造 |
| 成对能力 | 契约要求的创建与删除、获取与释放是否完整；由外部拥有者释放或明确只追加的对象按其实际职责判断 |
| 验收方式 | 每条声称的能力有没有对应的验证方式；靠什么证明它做到了 |

## 9 业务逻辑与流程完整性

> 这一维找的是**「每一步单独看都对，合起来能被绕过」**的问题。技术层面的校验全过了，业务规则还是被穿透。

| 检查点 | 什么算问题 |
| --- | --- |
| **步骤顺序** | 多步流程能不能跳步、乱序、重复执行；服务端有没有强制顺序，还是只靠界面不让点 |
| 状态前提 | 每一步对前置状态的要求在权威侧校验了吗 |
| 时序与竞态 | 同一流程并发跑两遍会怎样（重复领取、超发、双花） |
| 数量与额度 | 负数、零、超大数量；额度扣减与恢复的原子性——见[23](#23-事务原子性与一致性) |
| 计价与金额 | 金额由请求方传还是权威侧算；折扣叠加、舍入、币种 |
| 重放 | 同一请求重放会怎样；有没有一次性令牌或幂等键 |
| **反自动化** | 暴力破解、批量枚举、抢占、爬取——有没有速率限制、挑战、异常检测；限制按什么维度（账号 / 地址 / 设备 / 全局） |
| 枚举泄漏 | 通过响应差异（存在与否、快慢、错误措辞）能不能枚举出资源或账号 |
| 规则的唯一权威 | 业务规则散在多处各写一遍，还是有唯一实现；两处不一致时以谁为准 |
| 逆向操作 | 撤销、退款、回滚的路径有没有同等强度的校验 |
| 时间窗口 | 有效期、冷却期、截止时间能不能被绕过（改客户端时间、卡在边界） |

## 10 API 与契约

| 检查点 | 什么算问题 |
| --- | --- |
| 零值语义 | 返回值/参数的零值含义没定义，或定义了但没文档化 |
| **零值可用性** | 未初始化的实例直接用会怎样——能用要写明，不能用要挡住，不能既不说也不挡 |
| 构造完整性 | 构造之后对象是不是立刻可用；有没有必须再调一次的初始化；漏调会怎样 |
| 空值处理一致性 | 同类入口一半返回错误、一半静默返回零值 |
| 错误 vs 零值 | 同一种失败在不同入口一个返回错误、一个返回零值（是刻意区分就要写进文档，不是就是 bug） |
| 返回签名 | 多个返回值是否表达独立、明确的状态；是否存在矛盾组合、无法解释的状态位或不可达的错误返回 |
| 错误与资源结果 | 返回值和 error 的组合是否符合项目契约；失败前创建的资源是否由本层释放，关闭错误是否保留，调用方是否会误用失败结果 |
| 参数形状 | 参数过多、位置参数含义靠顺序记、布尔标志参数 |
| 所有权 | 返回的集合会被内部改写；接管的入参没写明「调用方不得再写」 |
| **借用的入参** | 调用方借给本层的对象（客户端、连接、配置、缓冲、回调）被本层改了字段、换了内部组件，或在返回后仍被保存使用；契约没写清是只读借用还是接管 |
| **视图有效期** | 零拷贝返回的切片、视图、迭代器、借用引用在下次调用、重置、归还池或关闭后失效；失效时机没写明，调用方越期持有会读到别人的数据 |
| 类型泄漏 | 公开签名里出现内部类型 |
| 可比较性 | 用作字典键 / 相等比较的类型是否可比较；不可比较的成员会导致运行时崩溃 |
| 自我描述方法 | 转字符串 / 转错误的方法会不会崩溃、会不会递归调用自己、会不会泄漏敏感信息 |
| 接口实现断言 | 有没有编译期检查「这个类型确实实现了那个接口」 |
| 调用方义务 | 调用顺序、并发限制、必须关闭、不得修改返回值——有没有写在文档里 |
| 幂等与重试 | 失败后重试是否安全；重复调用是否等价 |
| 兼容承诺 | 约定的兼容范围与实际不符，或留下未经要求的兼容负担；替换清理见[1](#1-死代码与可达性) |

> 命名本身在[6 命名、注释与可读性](#6-命名注释与可读性)查；「容不容易用错」在[11 易用性与误用防护](#11-易用性与误用防护)查。

## 11 易用性与误用防护

> 库的「易用性」不是界面好不好看，是**别人用错的难度有多大**。契约写清楚了，不等于难以用错。

| 检查点 | 什么算问题 |
| --- | --- |
| 最小惊讶 | 行为和名字、和同类接口的惯例是否一致 |
| **难以误用** | 有没有「很容易写错但能编译通过」的用法；能不能用类型、作用域、必填参数把错误用法挡在编译期 |
| 危险默认 | 调用方能否在不知情时触发超出预期的危险行为；具体默认值见[32](#32-配置与默认值) |
| 参数可混淆 | 相邻的同类型参数容易传反（两个字符串、两个时长、两个标识符） |
| 必须成对的调用 | 获取/释放、开始/结束、加锁/解锁——漏掉一半会怎样；能不能用作用域机制强制配对 |
| 部分初始化 | 能不能构造出一个「半成品」对象并使用它 |
| 沉默的失败 | 用错了但没有任何反馈（返回零值、忽略参数、静默降级） |
| 错误提示的可操作性 | 用错之后，报错能不能直接指出该怎么改 |
| 示例即契约 | 文档示例是不是推荐用法；照抄示例会不会踩坑 |
| 逃生舱 | 高层封装挡住了低层能力时，有没有留出口；出口有没有被滥用的风险 |

## 12 状态机与状态转移

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 状态枚举 | 列出对象实际存在的状态及表示方式 | 状态组合互相矛盾、转移条件不清；不因未使用枚举类型就判为缺陷 |
| **状态 × 操作矩阵** | 每个状态下每个公开操作的行为，列成表 | 有格子是空的——没定义、没测、没文档 |
| 非法转移 | 关闭后再打开、未初始化就用、重复启动、跳过中间状态 | 静默接受非法转移，或行为未定义 |
| 转移原子性 | 转移过程中有没有中间态被别人看到 | 中间态可观测且没定义 |
| 终态 | 进了错误态还能不能恢复；终态是不是真的终 | 卡在中间态出不来 |
| 并发转移 | 两个执行流同时触发转移 | 见[18](#18-并发与内存模型) |
| 状态与资源 | 每个状态下哪些资源是持有的；转移时谁释放 | 转移路径上漏释放 |
| 状态持久化 | 状态跨重启保留吗；重启后落在哪个状态 | 重启后状态与实际不符 |

## 13 错误处理与失败语义

| 检查点 | 什么算问题 |
| --- | --- |
| 上下文 | 错误没有包装，丢掉了原因或位置 |
| 吞错 | 被显式丢弃的错误里有真正需要处理的 |
| 错误分级 | 「预期状态」和「真实故障」混为一谈（目标不存在 vs I/O 失败；流结束 vs 超时） |
| 可判定性 | 调用方无法按类型或哨兵值区分；只能靠字符串比较 |
| 可重试性 | 错误有没有区分「重试可能成功」和「重试没用」 |
| 部分成功 | 批量操作失败一半的语义没定义；返回的计数含义模糊（删掉一个损坏残片算不算「删除了一条」） |
| 多错误 | 多个失败只报第一个还是全报，有没有说明 |
| 崩溃 | 库里主动崩溃（panic、abort、抛出不该由调用方处理的异常）；公开输入可稳定触发的隐式崩溃（越界、空引用、类型断言或转换失败、除零、不可比较或不可哈希类型的比较） |
| 崩溃恢复 | 用捕获掩盖了本该修的问题；**捕获之后对象还可用吗**；并发执行流、异步任务里的崩溃或未处理拒绝没人接，会带崩整个进程或被静默丢弃 |
| 进程级处理 | 库里直接终止进程（各语言的 exit、abort、未捕获的致命错误） |
| 异常机制的边界 | 捕获范围过宽，吞掉中断、取消或退出信号；异常穿过不支持异常的边界（回调、跨语言调用、析构）；错误返回值被忽略。语言细节见[附录 A](languages.md) |
| 面向人的可操作性 | 错误告诉了「出了什么事」，有没有告诉「该怎么办」；措辞是否一致 |
| 敏感信息 | 错误消息里带路径、凭据、用户数据、内部结构——见[30](#30-隐私数据治理与合规) |

## 14 边界、数值与文本

| 检查点 | 什么算问题 |
| --- | --- |
| 整数转换 | 宽类型转窄类型截断；平台相关宽度的整数 |
| 溢出 | 加法/乘法溢出成负数；`上限 + 1` 溢出；容量计算溢出。溢出后是回绕、抛错、饱和还是未定义行为，按语言和构建模式确认 |
| 任意精度数值 | 没有溢出但有成本：外部输入构造的超大整数、超高精度小数让运算、进制转换或序列化耗尽 CPU 和内存 |
| 双精度承载整数 | 数值统一用双精度浮点表示的语言或格式里，超过 2^53 的整数（如 64 位 ID）解析后失真 |
| 极值 | 零、负数、最大值、最小值没处理或没测 |
| 数组与切片 | 越界、长度与容量混用 |
| 空与缺失 | 空输入、空引用、空集合的处理 |
| 浮点 | 相等比较；精度累积；**金额、计量等精确值不得用浮点** |
| 非有限数值 | NaN、正负无穷和负零是否可经解析或计算进入比较、排序、额度和序列化；比较失败是否意外绕过取值约束 |
| 舍入 | 舍入规则（四舍五入 / 银行家舍入 / 截断）是否明确、是否一致、累积误差是否可接受 |
| **文本与编码** | 字节长度 / 码点数 / 字素簇 / 显示宽度混用；大小写转换的语言相关性；Unicode 规范化形式不同导致等价文本判不等；非法编码字节的处理；截断会不会切坏字符 |
| 解析中途失败 | 解析失败时是否已经改了外部状态；部分解析后的残留 |
| 领域约束 | 业务层面的取值约束（非负、单调递增、枚举闭集）在哪一层校验；有没有绕过路径 |

## 15 算法与数据结构正确性

| 检查点 | 什么算问题 |
| --- | --- |
| 比较函数 | 排序用的比较不满足严格弱序（相等元素两边都返回真、不传递）→ 结果乱序甚至崩溃 |
| 比较里的溢出 | 用相减当比较结果，两个大数相减溢出 → 顺序反了 |
| 排序稳定性 | 需要稳定排序却用了不稳定的；相等元素的相对顺序有没有承诺 |
| 取整方向 | 向上还是向下；小值会不会卡在 0（比例、配额计算的经典坑） |
| 取模偏置 | 随机数取模的偏置；用掩码取模要求容量是 2 的幂 |
| 哈希用法 | 同一个哈希同时用于两处分片时，两处取了同一段位 → 强相关，分布退化 |
| 洗牌 | 洗牌算法的区间写错 → 分布不均 |
| 二分与区间 | 开闭区间、上下界更新、终止条件 |
| **字典迭代顺序** | 依赖了语言或容器没有承诺的迭代顺序（有的随机，有的按插入，有的对部分键排序，同一语言的不同容器也不同，见[附录 A](languages.md)） |
| **序列化顺序稳定性** | 由无序容器生成的字节串（配置、查询串、校验和输入）顺序不稳定 → 身份或校验和不稳定 |
| 身份归一化 | 等价的多种输入写法有没有归一到同一身份；归一规则会不会把**不等价的错误合并**（如路径小写化，见[27](#27-安全与信任边界)） |
| 集合运算 | 去重、交并差的边界；空集合 |

## 16 语言与运行时陷阱

> 本节列的是**跨语言的陷阱类别**。每一类都要落到目标实际使用的语言上：先按[附录 A](languages.md)找该语言的具体机制；附录没有的语言，按类别自己找对应物，并在覆盖记录里写明依据。混合语言的目标每种语言各过一遍，跨语言边界另见[4.32](specialties.md#432-跨语言边界与本地扩展)。语义会随语言版本和构建模式变化，先确认目标声明并实际使用的版本。

| 类别 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| **空值与缺失** | 读返回可空值、可选值、接口、错误或字典查找结果的地方 | 空值有多种表示（空指针、装着空指针的接口、未定义与空、缺失的键）却只按一种判断，调用方永远判成有错或永远判成没错 |
| 值、引用与别名 | 赋值、传参、切片与视图、浅拷贝、默认参数、遍历变量 | 以为复制了其实共享，远处被改；截断复用后旧引用仍指向同一存储；可变默认值跨调用共享；遍历变量是副本，改它无效；不必要的大对象拷贝 |
| **同步对象被复制** | 静态检查 + 人工核对对象使用时机 | 违反同步类型的复制契约，例如首次使用后复制锁、原子量、等待组或条件变量，导致保护与真实共享数据分离 |
| **对齐、宽度与原子性** | 原子操作的字段、跨平台结构、共享内存 | 原子操作的宽度或对齐要求在某些平台不满足（如 32 位平台上的 64 位原子）；把普通读写当原子；「不会撕裂」的假设没有语言保证 |
| 整数语义 | 算术、类型转换、移位 | 溢出是回绕、抛错、饱和还是未定义行为因语言与构建模式而异，检查却按错的那种写；有符号与无符号混用 |
| 未定义行为与内存安全 | 有未定义行为或手动内存管理的语言，以及各语言的非安全块 | 越界、释放后使用、重复释放、未初始化读取、数据竞争；编译器依据未定义行为删掉看似存在的检查 |
| 分派、接口满足与继承 | 方法集、虚函数、原型链、方法解析顺序、重载与覆盖 | 以为实现了接口或覆盖了方法，实际没有（接收者形式、签名细微不同）；基类析构不是虚的；对象切片 |
| **内嵌提升与可选能力** | 内嵌、继承、混入；按能力探测的地方（类型断言、`hasattr`、特性检测） | 意外把内嵌类型的方法提升成公开 API；包装层内嵌具体类型后，调用方按可选能力探测到被提升的底层方法，**绕过包装层的逻辑**（加密、计量、限速、审计）；或包装层丢掉了底层的可选能力（半关闭、零拷贝、原始句柄） |
| **标准协议的实现者义务** | 实现语言或标准库定义的接口、协议、魔术方法 | 读写、迭代、比较、哈希、上下文管理、关闭、字符串化等协议的文档约定没做到。例：读取可以同时返回数据和错误；短写必须报错；超时错误要能被调用方识别为超时；相等的对象哈希必须相等；关闭能否重复调用要符合约定 |
| 相等、哈希与比较 | 用作键、去重、排序、比较的类型 | 不可比较或不可哈希的成员在运行时崩溃；相等与哈希不一致；可变对象作键后被改；NaN 与自身不等 |
| 隐式转换与真值 | 比较、条件判断、混合类型运算 | 宽松相等、字符串与数字自动转换、有符号与无符号比较、空集合/零/空串的真值差异让校验被绕过 |
| 闭包捕获 | 核对语言版本、变量声明位置与异步使用时间 | 闭包共享了会继续被修改的变量，实际读到的值与预期迭代不符；循环变量晚绑定 |
| 作用域结束的清理时机 | 延迟执行、析构、`finally`、`with`、`using`、try-with-resources | 循环里注册的清理要到函数结束才执行；清理顺序与所需顺序相反；清理里的错误或异常被吞 |
| 终结器与回收 | 依赖垃圾回收或终结器释放外部资源 | 释放时机不确定；终结器关掉了仍被别处使用的句柄；回收前资源已耗尽 |
| 取消与上下文的生命周期 | 取消凭据、请求上下文存进长生命周期对象；异步取消 | 生命周期错配，取消传播不可控；取消异常被当成普通错误吞掉 |
| 异常与错误机制 | 捕获范围、未捕获异常、未处理的异步拒绝、被忽略的错误返回 | 见[13](#13-错误处理与失败语义)「异常机制的边界」 |
| 异步与事件循环 | 协程、Promise、Future、事件循环 | 阻塞调用卡住事件循环；启动后不保存引用的任务被回收或错误丢失；挂起点前后的交错（见[18](#18-并发与内存模型)） |
| 断言与构建模式 | 断言、调试检查、调试与发布两套构建 | 发布构建或优化模式移除断言，用断言做输入校验在生产失效；调试与发布构建的溢出和边界检查不同 |
| 字符串、字节与编码 | 转换、长度、索引、截断 | 字节与字符混用；UTF-16 代理对被切开；以 NUL 结尾的字符串被提前截断；默认编码依赖区域设置；不必要的拷贝；零拷贝转换后原数据被改 |
| 非安全操作 | 每处 unsafe、原始指针、本地调用 | 依赖的内存布局与生命周期假设有没有写下来；对垃圾回收的可见性 |
| 反射与元编程 | 反射、动态属性、代理对象、运行时改类或原型 | 类型断言失败路径没处理；用在热路径上；可缓存的元信息没缓存；外部输入决定了被访问的属性或方法 |
| 泛型与类型擦除 | 类型参数、约束、只在编译期存在的类型 | 约束太宽导致运行时才失败；零值语义；类型参数为指针与值时行为不同；类型注解不在运行时校验却被当成校验 |
| 模块加载与初始化 | 包或模块初始化、导入时副作用、循环依赖、静态初始化顺序 | 初始化副作用、失败与执行顺序未定义；循环依赖拿到半初始化的对象；模块或库的搜索路径可被劫持 |
| 可变全局 | 包级变量、单例、模块状态、类变量 | 可变全局的所有权和并发契约不清，是否允许以项目规范为准 |
| 语言与运行时版本 | 声明的版本、构建配置、运行时开关 | 语义随版本改变（循环变量、计时器、默认编码、默认进程启动方式等）；代码按新语义写却声明了旧版本，或反过来 |

## 17 时间与时钟

| 检查点 | 什么算问题 |
| --- | --- |
| 墙钟 vs 单调钟 | 测量间隔用了墙钟 → 时钟同步调整后间隔变负或变巨大 |
| **时钟回拨** | 所有基于绝对时间戳的判定（有效期、宽限窗口、节流、租约、残片新鲜窗口）在回拨后会怎样：提前过期、永不过期、节流永久生效 |
| 精度与粒度 | 共享的粗粒度时钟下，同一格内的事件无法区分先后——依赖顺序的逻辑会失效 |
| 边界比较 | 小于还是小于等于；恰好相等时的行为与文档是否一致 |
| 超时传播 | 上游的剩余时限有没有传给下游；下游用自己的固定超时导致总时长不可控 |
| 时钟偏移 | 跨机器比较时间戳；对偏移的容忍度 |
| 时区与夏令时 | 有没有依赖本地时区；夏令时切换那天的重复小时和缺失小时 |
| 单位 | 秒 / 毫秒 / 纳秒混用；时长类型与裸整数互转时的量纲 |
| 定时器 | 按实际运行时核对回收、停止、重置和回调语义；逻辑结束后仍有定时任务持有资源或修改状态 |
| 可注入 | 测试能否控制时间与事件顺序；依赖 sleep 或调度时机的断言是否不稳定——见[40](#40-可测试性与故障注入) |

## 18 并发与内存模型

先确认公开并发契约和真实可达的并发路径，再检查以下项目；不能把调用方明确不得执行的操作组合直接当成实现缺陷。

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| **数据竞争与逻辑竞争** | 区分内存访问冲突和业务操作交错 | 动态竞态检测（Go 的 `-race`、C/C++/Rust 的 ThreadSanitizer 等）通过，只表示本次执行未检测到数据竞争，不覆盖未执行路径，也不能证明组合操作正确；依据例见 [Go race detector](https://go.dev/doc/articles/race_detector) |
| **协作式调度的交错** | 单线程事件循环、协程、生成器，在每个挂起点（await、yield、回调边界）找「挂起前读、挂起后据此写」 | 认为「单线程所以没有竞态」；挂起点之间状态已被其它任务改掉 |
| 解释器全局锁 | 有全局解释器锁的运行时 | 把全局锁当成复合操作（读改写、检查后行动）的原子保证；在没有全局锁的构建或其它实现下假设失效 |
| fork 与线程 | 多线程进程里创建子进程副本 | 子进程继承了被其它线程持有的锁而死锁；继承的描述符、随机数状态、连接被父子共用 |
| 并发契约 | 逐个公开方法确认「能不能并发调」写没写 | 契约没写，或写了但实现不满足 |
| 状态保护 | 逐字段核对拥有者、全部读写方及锁、原子或不可变发布方式 | 无保护，或保护范围没有覆盖必须整体完成的读、判断与写入 |
| 检查-然后-行动 | 找「读状态 → 放锁 → 据此写回」的形状 | 中间窗口里状态可能已变（例：从慢存储读到值 → 无锁 → 写进内存缓存，期间该键已被覆盖或删除） |
| 先做事后记账 | 找「改了真实数据 → 一段代码 → 才更新计数/索引」 | 窗口里的观察者把中间态当稳定态（例：数据已落盘、计数还没加，扫描发布绝对计数后计数再加一次） |
| 可见性 | 每处跨执行流的可见性靠什么建立（锁 / 通道 / 原子） | 靠「应该能看到」的直觉，没有同步原语支撑 |
| 原子量组合 | 两个及以上原子量需要一起判断的地方 | 合起来不原子 |
| 锁粒度与持锁行为 | 持锁期间有没有 I/O、系统调用、回调、外部代码 | 长持锁；**持锁调用回调/接口方法**，对方可能重入取同一把锁 |
| 锁顺序 | 列出所有「持 A 取 B」的位置 | 存在反向顺序 → 死锁 |
| 重入 | 同一执行流是否可能重复取不可重入锁 | 自死锁 |
| 发布安全 | 对象发布后是否还被改 | 撕裂读 |
| 通道与队列 | 关闭已关闭的、向已关闭的发送、空通道、无缓冲阻塞、非阻塞分支丢消息 | 崩溃或静默丢事件 |
| 唤醒 | 单播唤醒够不够、丢唤醒、关闭有没有唤醒全部等待方 | 永久阻塞 |
| 等待组 / 任务组 | 计数在子执行流内部增加、完成通知漏调、复用 | 计数错乱、提前返回 |
| 后台执行流 | 谁启动、谁停止、关闭等不等它、异常路径会不会漏停 | 泄漏 |
| 取消传播 | 取消之后，派生的执行流真的会退出吗 | 泄漏 |
| 关闭竞态 | 关闭与每个入口并发 | 关闭中写入、关闭后残留、计数被压到负数 |
| ABA | 无锁比较交换的值被改回原样 | 判等误判为「没变过」 |
| **无锁进展性** | 比较交换重试循环、自旋等待 | 重试没有上界也没有退避；忙等不让出处理器；多个执行流互相使对方失败形成活锁 |
| **复用槽位** | 对象池、环形槽、世代池、空闲链表的复用 | 槽位复用后旧引用仍被当成有效；世代号宽度不足，回绕后与旧值撞车；归还前没清掉会延长对象生命期的引用 |
| 饥饿与惊群 | 大量等待者同时唤醒；某类操作是否可能永远抢不到 | 尾延迟不可控 |
| 单飞 | 同一键的重复昂贵操作有没有合并 | 重复劳动、惊群 |
| 顺序承诺 | 有没有承诺先进先出 / 顺序，实现满足吗 | 承诺了但不满足 |
| 时钟粗糙度 | 用时间戳区分先后的地方——见[17](#17-时间与时钟) | 同一时间格内的两次写入无法区分 |
| 测试同步钩子 | 生产代码里只为测试存在的等待/空闲标志 | 记录并说明；能移进测试文件就移 |
| 确定性复现 | 能不能构造确定的交错来复现，而不是靠重复跑碰 | 只能碰运气 → 修了也无法证明 |

## 19 生命周期与资源

| 检查点 | 什么算问题 |
| --- | --- |
| 获取/释放配对 | 有创建没释放；**错误路径上的早返回漏掉释放** |
| 延迟释放的位置与顺序 | 注册太晚；多个延迟调用的执行顺序与所需的释放顺序相反 |
| 手工释放 | 同一函数里多处手写释放（漏一处就泄漏）——能用自动释放就用 |
| **关闭内部顺序** | 关闭时多个资源的释放顺序（先停后台再关句柄？先唤醒等待方再清状态？）有没有理由、写下来了吗 |
| **关闭是否等待** | 等不等在途操作？等多久？不等的后果（半成品、脏快照）写清楚了吗 |
| 引用计数 | 增减不配对；错误路径漏减 |
| 重复关闭 | 行为与契约不符，或再次释放已经转移给其他对象的资源 |
| 关闭之后 | 每个入口的行为有没有定义、是否一致——见[12](#12-状态机与状态转移) |
| 句柄 / 连接 / 终结器 | 有没有泄漏路径（定时器见[17](#17-时间与时钟)） |
| 临时文件与目录 | 失败路径上残留 |

> 无界增长、上界能否算出来在[20 资源上界与背压](#20-资源上界与背压)查；内存泄漏模式在[31 性能、内存与延迟](#31-性能内存与延迟)查。

## 20 资源上界与背压

| 检查点 | 什么算问题 |
| --- | --- |
| 上界可算吗 | 内存、执行流、句柄和连接的最坏占用是否受有效约束；无法确定时记录缺少的条件，已证明可持续增长时才报告无界 |
| 无界结构 | 队列、缓冲、字典、数组、等待者列表只增不减，没有淘汰或上限 |
| 放大系数 | 一次外部请求会放大成多少内部操作、多少分配、多少系统调用；放大倍数由谁的输入决定 |
| 慢消费者 | 生产快于消费时会怎样 |
| 背压策略 | 满了之后是阻塞、丢弃还是报错——行为没定义 |
| 递归深度 | 深度是否有界；能否被外部输入撑爆栈 |
| 批量入口 | 接受任意长度参数的批量入口有没有上限，一次巨量调用会怎样 |
| **哈希碰撞洪水** | 不可信字符串当哈希表 / 字典的键，碰撞让单次请求占满 CPU |
| 算法成本 | 外部输入能否触发正则回溯、组合搜索或其他超线性计算；结合实际算法与引擎判断，不能只按表达式形状报告拒绝服务 |
| 并发度上限 | 同时在飞的操作有没有上限；由谁控制 |
| 配额归属与计费 | 限额是否绑定可信的账号或租户，换地址、批量请求或换节点能否绕过；昂贵操作前是否扣占预算，取消与失败后是否正确结算 |

## 21 可伸缩性与容量

> 上一维问「会不会被撑爆」，这一维问「**长十倍会怎样，加机器有没有用**」。

| 检查点 | 什么算问题 |
| --- | --- |
| 增长维度 | 数据量 / 并发量 / 连接数 / 租户数 / 请求速率——哪一个先到瓶颈，心里有数吗 |
| **十倍增长** | 当前规模十倍时哪里先坏；是线性劣化还是断崖式 |
| 线性扩展 | 加实例 / 加分片能不能线性提升；有没有全局串行点抵消掉 |
| 状态与扩展 | 有没有本地状态挡住水平扩展；能不能做到无共享 |
| 分片与再平衡 | 分片键的选择与热点；扩容时的数据迁移与再平衡代价 |
| 冷热不均 | 热点键、热点分区、长尾；有没有打散手段 |
| 单点 | 有没有单点（全局锁、单实例组件、唯一序号发生器、单写者） |
| 容量余量与告警 | 当前留了多少余量；接近上限时有没有告警 |
| 反压向上传导 | 到达容量上限时，压力能不能正确传回上游而不是就地堆积 |
| 启动放大 | 大量实例同时启动 / 重连时会不会打垮下游（惊群、缓存全空） |

## 22 故障隔离与降级

> 上一维问「我自己扛不扛得住」，这一维问「**别人坏了，我怎么办**」。

| 检查点 | 什么算问题 |
| --- | --- |
| 依赖失败的行为 | 每个外部依赖失败时做什么：硬失败、降级、用默认值、用陈旧缓存——有没有定义 |
| 熔断 | 有没有熔断；熔断状态机（关闭 / 打开 / 半开）的转移条件、恢复条件、半开时的探测量 |
| 舱壁隔离 | 一类请求耗尽资源会不会拖垮另一类；池、队列、执行流是否按类别分离 |
| **超时预算分配** | 总预算怎么分给各阶段；下游超时是否小于上游剩余；串行多跳的超时累加会不会超过总预算 |
| **重试风暴** | 多层重试是否放大调用；预算、退避与抖动是否有效；已发生或结果未知的副作用能否安全重试，幂等判据见[23](#23-事务原子性与一致性) |
| 降级可观测 | 降级发生时有没有告知；当前是不是降级态能不能看到 |
| 自动恢复 | 依赖恢复后自己会不会恢复；要不要人工介入；恢复时会不会惊群 |
| 部分可用 | 一部分功能坏了，其它还能不能用；还是整体不可用 |
| 慢比挂更糟 | 依赖变慢（不是失败）时会怎样——超时能不能兜住；连接 / 执行流会不会被占满 |
| 缓存作为降级 | 用陈旧数据降级时，陈旧到什么程度就不能用了；有没有告知调用方数据是陈旧的 |

## 23 事务、原子性与一致性

> 这一维问的是「**哪些事必须一起成真**」。不只数据库有事务：任何「改两个地方」的代码都要回答这些。

| 检查点 | 什么算问题 |
| --- | --- |
| 原子性单元 | 哪些操作必须一起成功或一起失败；边界画在哪；写下来了吗 |
| 事务边界 | 事务开在哪、关在哪；错误路径上有没有回滚；有没有长事务把慢操作圈进去 |
| 嵌套与复用 | 嵌套事务的语义；同一个事务被多层各自提交 |
| 隔离级别 | 用的是什么级别；脏读 / 不可重复读 / 幻读会不会影响正确性 |
| **一致性承诺** | 强一致 / 最终一致 / 读己之写 / 单调读——承诺了什么，实现符不符合，写在哪 |
| 跨资源操作 | 跨两个存储 / 两个服务 / 存储加缓存的操作怎么保证原子；有没有补偿 |
| 补偿与回滚 | 补偿操作本身失败怎么办；补偿是否幂等；补偿会不会和正常路径打架 |
| 去重与幂等键 | 重复请求怎么识别；幂等键从哪来；去重窗口多长；窗口外的重复会怎样 |
| **「恰好一次」** | 声称恰好一次的地方，真实语义是不是「至少一次 + 消费端幂等」；有没有说清 |
| 可见性顺序 | 写入对其它读者可见的顺序有没有承诺；先写缓存还是先写存储 |
| 读写路径不一致 | 写走一条路、读走另一条路（如写存储读缓存），中间的窗口有多长 |

## 24 编解码与持久化格式

| 检查点 | 什么算问题 |
| --- | --- |
| 自描述 | 现有格式标识、schema 或外部约束是否足以识别数据；会把外来或不支持的格式当成有效数据处理 |
| 校验 | 没有长度或校验和，截断不可判定；校验覆盖范围是不是全部内容 |
| 保留字段 | 写入时没置零；读取时没校验 |
| 字节序 | 前后不一致 |
| 不信任输入 | 见[4.3](specialties.md#43-解码不受信任的外部数据) |
| 身份稳定性 | 键 → 存储位置的映射，改了配置会不会撞到旧数据；生成映射的输入顺序稳定吗（见[15](#15-算法与数据结构正确性)） |
| 外来数据 | 同一位置里别人的数据会不会被误删、误读、误计数 |
| 局部损坏 | 一条坏数据会不会导致整体打不开——能不能跳过继续 |
| **往返与规范形式** | 解码再编码与原数据不等价；未知字段被静默丢弃，或原样透传而契约没说；同一个值有多种编码时接受了非规范形式，而签名、哈希、去重或缓存键依赖规范形式 |
| 版本兼容 | 见[26](#26-发布升级迁移与回滚) |

## 25 崩溃与恢复

按实际故障区分正常关闭、异常、优雅终止、强杀、断电、内存耗尽和存储故障。强杀与断电不能依赖进程清理；容器停止或存储变为只读是否仍能执行清理，要核对真实信号与错误路径。恢复保证以项目承诺的故障范围为准。

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 终止方式分类 | 逐种终止方式问「这次还能执行到哪一行」 | 只考虑了正常关闭；恢复依赖只有正常路径才写的东西 |
| **持久性** | 承诺断电持久时，核对目标平台所需的文件、目录项与提交同步，以及同步失败的处理 | 将缓存写入或原子替换当成持久提交；返回成功后断电仍可能丢数据 |
| 崩溃点枚举 | 沿写入路径**逐行**问「在这里断电，进程外是什么状态？下次打开能判定吗？」 | 存在无法判定的中间态 |
| 写入顺序 | 先日志后数据？顺序能支撑恢复吗？底层会不会重排 | 顺序假设不成立就整套恢复失效 |
| 部分写 | 一次写可能只写一半（短写）；扇区/页粒度的撕裂写 | 靠「写一次就是原子」的假设；没检查写入返回的字节数 |
| 发布原子性 | 直写终态 vs 临时文件加原子替换，各自的代价写清楚了吗 | 直写的代价（覆盖写失败会丢旧数据）没写进文档 |
| 半成品识别 | 用写入所有权、提交标记、长度和完整性检查区分在途写入与残片 | 仅凭时间或长度不能证明内容已完整提交；恢复误删仍在写的数据，或接受等长损坏数据 |
| 恢复覆盖面 | 恢复流程覆盖了所有中间态，还是只覆盖了想到的那几种 | 有洞 |
| **恢复自身崩溃** | 恢复跑到一半再崩一次 | 恢复不幂等 → 第二次打开更糟 |
| 重放幂等 | 日志重放两次结果一样吗 | 不幂等 |
| 恢复代价 | 重启后要扫多少东西、耗时随数据量怎么增长 | 声称支撑的规模下，启动却要全量扫 |
| 外部干预 | 别人删了目录 / 改了数据 / 挂载点消失 / 变成只读 | 直接崩，或静默丢数据 |
| 资源耗尽 | 磁盘满、inode 耗尽、句柄耗尽、系统调用被中断 | 未处理，或处理后内存态与持久态不一致 |
| **多进程** | 核对共享写入的事务、条件写或锁机制及崩溃后的释放方式 | 缺少有效协调导致互相覆盖，或残留锁阻止恢复；不能只因没有文件锁就判为问题 |
| 进程内独占 | 同一进程重复打开同一实例 | 两套状态互相覆盖 |
| 备份与演练 | 有没有备份；**恢复流程演练过吗**；备份本身可不可用 | 有备份但从没验证过能恢复 |

## 26 发布、升级、迁移与回滚

| 检查点 | 什么算问题 |
| --- | --- |
| 向前兼容 | 旧版本读到新版本写的数据会怎样——报错、跳过还是**静默误读** |
| 向后兼容 | 项目仍要求读取的旧数据无法读取，且没有约定的迁移或明确拒绝方式 |
| 版本标识 | 格式里没有版本字段；遇到未知版本没有明确处理 |
| 迁移 | 迁移是否幂等；迁移中途崩溃能否续跑；迁移失败能否回到原状；迁移耗时与锁定范围 |
| **发布策略** | 灰度 / 金丝雀 / 分批；观察窗口多长；自动回滚的触发条件；一次全量上线的风险 |
| **回滚机制** | 回滚是不是一条命令；回滚要多久；回滚过程中新旧版本并存会怎样 |
| 回滚的数据面 | 升级后回滚到旧版本，数据还能用吗；是不是单向门（是就要写明并在发布前确认） |
| 混合运行 | 发布方式允许新旧版本并存时，共用数据和互相通信是否安全；需要停机切换的前提是否落实 |
| 特性开关 | 开关的默认值、生效范围、清理计划；多个开关的组合是否被验证过 |
| 接口破坏性变更 | 调用方是否按已确认方案迁移；是否需要兼容由项目契约决定，不自动增加过渡层 |
| 配置迁移 | 旧配置在新版本里的含义是否变化；直接替换或过渡策略是否与授权一致 |
| 双写双读期 | 仅在已采用此方案时检查：新旧数据不一致如何处理，何时停止双轨 |

## 27 安全与信任边界

| 检查点 | 什么算问题 |
| --- | --- |
| **输入来源分级** | 调用方 / 配置 / **已存在的持久化数据** / **网络对端** / 环境变量 / 命令行，各自的信任级别要区分开。把已存数据或对端数据当可信是常见错误 |
| 输入校验 | 校验缺失、发生在不同于实际使用的表示上，或校验后再次解码、拼接、规范化导致约束失效 |
| 注入面 | 按数据最终进入的解释器检查：查询见[4.7](specialties.md#47-数据库与查询)，文本输出见[4.17](specialties.md#417-模板与文本输出)，执行见[4.22](specialties.md#422-子进程动态执行与解码器副作用) |
| 二次使用 | 数据第一次保存时安全，后来被拼入查询、命令或模板时失去保护；不能因来自数据库或消息队列就免校验 |
| 解析分歧 | 网关、鉴权层与处理层对重复参数、重复 JSON 字段、编码或类型转换理解不同，导致检查的值与执行的值不一致 |
| 大小写与规范化 | 路径被规范化为小写，在大小写敏感文件系统上把两个不同目录当成同一个；大小写转换的语言相关行为 |
| 路径与本地权限 | 统一见[4.8](specialties.md#48-文件系统与路径)，同时检查校验后资源是否能被替换 |
| 密码学控制 | 哈希用途、随机性、凭据与密码学侧信道统一见[4.4](specialties.md#44-加密与凭据) |
| **信息泄漏** | 错误页 / 调试端点 / 版本与栈信息 / 目录列举 / 详细响应头 对外暴露 |
| **加固** | 默认账号与默认口令；不必要的功能、端口、端点默认开启 |
| 拒绝服务 | 检查攻击者能触发的成本和放大，资源预算见[20](#20-资源上界与背压)，解码见[4.3](specialties.md#43-解码不受信任的外部数据) |
| 默认安全 | 安全默认值统一见[32](#32-配置与默认值)，故障时的方向见[29](#29-失效安全与危险操作) |

## 28 授权与访问控制

> [27](#27-安全与信任边界) 问「这个输入可信吗」，这一维问「**这个请求者有权做这件事吗**」。两者经常被混为一谈，然后授权就漏了。

| 检查点 | 什么算问题 |
| --- | --- |
| 认证与授权分离 | 「你是谁」和「你能做什么」混在一起判断 |
| **检查位置** | 权限检查在每个入口都做了吗；有没有绕过路径（内部方法被直接调用、批量入口只查了第一条） |
| 默认拒绝 | 未知情况、未知角色、新增入口默认拒绝还是默认允许 |
| **水平越权** | 更换资源标识符是否能访问他人对象；标识符难猜不等于有授权检查 |
| **垂直越权** | 低权限能不能触达高权限操作；隐藏入口算不算保护（不算） |
| 字段级授权 | 同一个对象里有些字段不该被某些人看到 / 改动，做了吗 |
| 自动字段绑定 | 请求直接绑定内部模型或批量更新时，是否能写入角色、租户、属主、余额等服务端管理的字段；响应是否暴露无权读取的属性 |
| 多入口一致性 | 列表、搜索、导出、嵌套对象、批量、GraphQL 字段、RPC 与异步任务是否执行相同的对象授权；不能只检查详情接口 |
| 权限提升路径 | 有没有能一步步组合出更高权限的路径 |
| 授权数据来源 | 权限判断依据来自可信来源，还是来自请求本身携带的字段 |
| 粒度 | 权限粒度够不够；有没有「要么全给要么不给」 |
| 缓存与失效 | 权限、租户关系或资源属主变化后，已有会话、长连接、后台任务与缓存多久受新权限约束；执行前是否仍满足授权条件 |
| 多租户边界 | 租户之间的数据、资源、配额是否隔离；跨租户查询有没有强制过滤条件 |
| 委托与代理 | 代表他人执行时是否绑定原始主体、目标资源与允许操作；服务自身的高权限不能替代调用者授权 |

敏感操作的安全记录统一见[4.23 安全审计日志](specialties.md#423-安全审计日志)。

## 29 失效安全与危险操作

> 出错时，系统停在**安全的一侧**还是危险的一侧。这一维对「会改外部状态」的代码尤其重要。

| 检查点 | 什么算问题 |
| --- | --- |
| **失效方向** | 出错时默认拒绝还是放行；鉴权 / 限流 / 校验组件挂了是全拦还是全放 |
| 危险操作确认 | 删除、覆盖、迁移、重置这类不可逆操作，有没有二次确认 / 预览 / 干跑 |
| 不可逆性 | 哪些操作不可撤销，写明了吗；有没有软删除或保留期兜底 |
| **影响范围限定** | 批量危险操作有没有范围上限；**没有限定条件时是不是拒绝执行**（例：没有过滤条件的删除） |
| 干跑与预演 | 有没有只报告不执行的模式；预演结果和真实执行会不会不一致 |
| 操作前提 | 有没有「不该在这些条件下运行」的约束（未备份、版本不匹配、空间不足、目标非预期）；有没有检查 |
| 风险提示 | 危险路径有没有在文档、命名、日志上给出显式警告 |
| 破坏半径 | 一次误操作最多能毁掉多少；有没有分批、限速、熔断 |
| 非幂等的破坏性重试 | 重试一个非幂等的破坏性操作会怎样 |
| 恢复通道 | 做错之后有没有回头路；回头路验证过吗 |

## 30 隐私、数据治理与合规

| 检查点 | 什么算问题 |
| --- | --- |
| 数据分类 | 哪些字段是个人信息 / 敏感信息，有没有标注出来 |
| 最小化 | 收集和保存的是不是必要的；有没有「顺手多存一份」 |
| 保留期 | 数据存多久；有没有到期删除；期限从哪来 |
| **删除的真实性** | 删除之后，备份、日志、缓存、索引、派生数据、消息队列里还有没有；软删除有没有被当成真删除 |
| 匿名化 | 匿名 / 假名处理是否可逆；能不能通过关联字段重新识别 |
| 出境与地域 | 数据存放和传输的地域限制 |
| 日志与遥测 | 日志、指标标签、追踪、崩溃报告里有没有个人信息或凭据 |
| 用途一致 | 使用范围是否超出收集时声明的范围 |
| 第三方共享 | 传给第三方（含依赖库、SDK、外部服务）的数据有没有超出必要 |
| 加密要求 | 传输中和静态存储时的加密要求有没有满足 |
| 要求来源 | 适用地域、数据类别、合同或组织政策是否已确认；来源和版本不明时记录待确认要求，不把技术检查结论写成法律合规认证 |

敏感数据访问记录的完整性与保留策略见[4.23](specialties.md#423-安全审计日志)。

## 31 性能、内存与延迟

| 检查点 | 怎么查 |
| --- | --- |
| 热路径分配 | 找逃逸与临时对象：装箱、闭包、动态增长、每次调用新建缓冲、字符串拼接、极热路径上的延迟调用或异常 |
| 多余拷贝 | 能共享不可变数据却做了防御性复制（或反过来，该复制没复制） |
| 系统调用次数 | 一次逻辑操作打了几个系统调用，有没有可以短路掉的 |
| 锁竞争 | 全局锁、粗粒度锁在热路径上 |
| 复杂度与规模 | 算法复杂度是否匹配声明支撑的数据规模 |
| 预分配 | 已知长度却不预留容量 |
| 缓存行 | 高频并发字段有没有伪共享 |
| **内存泄漏模式** | 长生命周期容器持有短生命周期对象；闭包意外捕获大对象；监听器 / 回调注册后不注销；缓存无淘汰 |
| **对象池** | 归还之后是否还被使用；池化对象的重置是否完整（跨请求残留数据是安全问题） |
| 大对象与碎片 | 大块分配的频率；长期驻留导致的碎片 |
| **尾延迟** | 只看均值不看高分位；抖动来源（锁、垃圾回收、重试、缓存未命中） |
| 冷启动与预热 | 首次调用的额外成本；预热是否必要、做了没有 |
| 运行时停顿 | 垃圾回收 / 整理带来的停顿；分配速率对停顿的影响 |
| 基准 | 有没有基准覆盖热路径；改动前后有没有可比数字；有没有看分配次数 |

**报性能结论的纪律**：给出的开销要么是实测，要么把估算依据写出来（几次系统调用、几次原子操作、对照基线的量级）。**没有测过就不许写成实测数字**。

## 32 配置与默认值

| 检查点 | 什么算问题 |
| --- | --- |
| 默认值 | 不合理、没文档化、和文档不一致；默认配置是否安全 |
| 零值 vs 未设置 | 两者需要区分却没区分（「显式写 0 表示关闭」和「没写表示用默认」） |
| 硬编码策略 | 可配置的策略被写死。**本次改到或与本次改动直接相关的必须提醒调用方**；范围外的只报告 |
| 校验完整性 | 有字段没校验；校验规则和文档 / 声明标记不一致；组合校验（A 必须小于 B）缺失 |
| 校验时机 | 启动时校验还是用到才炸 |
| 合并语义 | 多份配置合并/继承的取值规则（取大、取小、取先）有没有写清 |
| 来源优先级 | 命令行 / 环境变量 / 文件 / 默认，谁覆盖谁，有没有写明 |
| 单位量纲 | 大小和数量混用；单位后缀支持范围 |
| 配置影响身份 | 哪些配置项参与实例身份，改了就是另一份数据——有没有写明 |
| 机密类配置 | 配置加载是否暴露机密或错误继承权限；凭据暴露与生命周期统一见[4.4](specialties.md#44-加密与凭据) |
| 热更新 | 支不支持运行中改；改了对在途操作和已有连接的影响；改坏了能不能回退 |

## 33 可观测性与可诊断性

| 检查点 | 什么算问题 |
| --- | --- |
| 日志位置与频率 | 热路径上打日志；失败时刷屏；无法关闭或调级 |
| 日志与错误内容 | 泄漏键、路径、凭据、用户数据——见[30](#30-隐私数据治理与合规) |
| 错误可定位 | 缺少操作类型、安全的资源标识和关联信息，无法定位失败；所需上下文仍须满足[30](#30-隐私数据治理与合规)的数据最小化要求 |
| 关联标识 | 跨组件 / 跨请求能不能串起来（请求标识、追踪标识）；有没有一路传下去 |
| 对外统计 | 暴露的计数/大小/状态**是精确还是估算**、误差来源和收敛条件有没有写明 |
| 估算被当精确 | 文档说估算，调用方（和测试）却按精确用 |
| 关键路径可见 | 出问题最想知道的那几个数（队列长度、在飞数、失败率、延迟分位）暴露了吗 |
| **服务目标** | 有没有明确的可用性 / 延迟目标；能不能被度量；超标了谁知道 |
| **告警** | 关键失败有没有告警；告警是不是可操作、会不会噪音、会不会漏报 |
| **所有权与处置手册** | 谁负责这块；出问题的处置步骤写在哪；新人能不能照着做 |
| 自检入口 | 有没有一致性校验的办法；出问题时能不能验证内部状态 |
| 现场信息 | 出问题时拿到的信息够不够重建现场 |

## 34 运行环境与部署契约

| 检查点 | 什么算问题 |
| --- | --- |
| 环境假设 | 对目录存在性、权限、网络可达性、时区、语言环境、临时空间的假设，写下来了吗；不满足时是明确报错还是诡异失败 |
| 环境变量 | 读取时机（启动时 vs 每次用）、缺失时的行为、默认值、大小写与命名约定 |
| **资源限制感知** | 并发度、内存池、缓冲大小是按实际配额算，还是按宿主机总量算——容器里按总量算会严重超配。运行时是否感知容器限额因语言和版本而异，见[附录 A](languages.md) |
| 容器特性 | 作为 1 号进程时的信号转发与僵尸回收；只读根文件系统；可写目录在哪；临时目录大小 |
| 句柄与端口 | 上限从哪来；超了怎么办 |
| 启动依赖 | 依赖没就绪时是重试等待还是直接失败；有没有隐含的启动顺序假设 |
| 关闭契约 | 收到终止信号后允许用多久；超时会被强杀；这个时长和内部的关闭超时匹配吗 |
| 时钟与本地化 | 依赖宿主时区 / 语言环境吗；不同宿主上行为会不会不同 |
| 单实例假设 | 多副本同时跑会怎样；有没有隐含的「只有我一个」假设（本地锁、本地缓存、本地计数） |
| 存储假设 | 本地磁盘是不是持久的；重启后还在吗；多副本共享同一份存储吗 |
| 运行身份与隔离 | 是否使用超出职责的系统或云权限；容器特权、宿主挂载、运行时 socket、服务账号与密钥挂载是否扩大被攻破后的影响 |
| 网络与管理面 | 实际监听地址、管理接口、调试接口、对象存储公开策略和入口规则是否符合部署契约；不能仅凭「在内网」假定无需身份或权限校验 |
| 配置漂移 | 实际部署制品和生效配置是否与审查输入一致；环境覆盖、旁路入口或未启用的安全配置是否改变结论 |

## 35 依赖

| 检查点 | 什么算问题 |
| --- | --- |
| 必要性 | 标准库或项目内已有等价能力 |
| 用量 | 为了一个小函数引入整个库 |
| 契约理解 | 对依赖行为的假设有没有被它的文档保证；有没有依赖它的未定义行为 |
| 失败模式 | 依赖失败 / 变慢时的行为——见[22](#22-故障隔离与降级) |
| 上游 fork | 边界是否还是「上游镜像 + 最小本地补丁」；补丁是否仍必需、有无公开替代；同步方法是否仍可用 |
| 传递依赖 | 传递依赖的体积、许可证、冲突版本 |

## 36 供应链与制品完整性

| 检查点 | 什么算问题 |
| --- | --- |
| 来源可信 | 依赖来源是否可信；有没有名字近似的冒名包；有没有从非官方渠道拉取 |
| **依赖混淆** | 内部包名在公网注册源也能解析到；构建有没有锁死只走内部源 |
| 锁与校验 | 锁文件是否提交；有没有校验和验证；依赖能不能被静默替换 |
| **已知漏洞** | 结合实际锁定版本、传递依赖、fork 补丁、构建条件、可达路径和厂商公告判断是否受影响；记录工具与漏洞库日期，不能把包名命中直接等同可利用漏洞，也不能把空结果当安全证明。默认联网查询公开漏洞库和官方公告（允许范围见[目标项目的硬边界](scope.md#目标项目的硬边界)）；无法联网时，写明离线漏洞库的日期和没有核对到的范围 |
| **安全修复版本** | 锁定版本落后于上游已发布的安全修复；查注册表和发布说明，确认修复所在的最低版本、最新的受支持版本，以及升级是否跨过破坏性变更 |
| 维护状态 | 依赖是否已弃坑、长期未更新、单一维护者、近期换手 |
| 构建可复现 | 同样的输入能不能产出同样的制品；有没有嵌入时间戳、绝对路径、构建机信息 |
| 版本可追溯 | 制品里的版本标识从哪来；能不能和源码对上 |
| 签名与分发 | 制品有没有签名；分发渠道可信吗 |
| 构建期代码执行 | 构建时会不会执行依赖里的任意代码（安装脚本、生成步骤、插件） |
| 构建与发布权限 | 不可信提交、依赖脚本或工作流输入能否读取发布凭据、写制品或部署；构建任务、执行器和发布身份之间是否隔离 |
| 构建缓存与制品替换 | 不可信任务是否能污染可信任务使用的缓存或中间产物；最终验签的身份与摘要是否绑定实际部署制品，标签或下载地址能否被替换 |
| 组件清单 | 是否能从实际制品追溯运行时、基础镜像、依赖与插件；已有组件清单（SBOM）是否与制品一致，动态下载是否绕开锁定和完整性检查 |
| 许可证 | 依赖许可证与本项目分发方式是否兼容；声明文件是否齐全 |

## 37 互操作性与共存

> 一个是「能不能和别人对话」，一个是「能不能和别人在同一台机器上相处」。

| 检查点 | 什么算问题 |
| --- | --- |
| 标准符合 | 与外部交换的格式、协议、编码是否符合公开标准；偏离处有没有记录理由 |
| 版本协商 | 与对端的版本 / 能力协商；不匹配时的行为；降级协商能不能被强制 |
| 宽进严出 | 对收到的数据宽容、对发出的数据严格——尺度是否合适，会不会变成掩盖问题 |
| 与其它实现互通 | 只和自己的实现互通过，还是和第三方实现验证过 |
| **资源共存** | 与同机其它进程 / 实例共享资源（端口、目录、锁文件、缓存、临时空间、共享内存）时会不会互相干扰 |
| **命名空间冲突** | 全局命名（环境变量名、文件名、指标名、注册键、锁名）会不会和别人撞车 |
| 副作用外溢 | 修改共享的系统状态（网络配置、系统设置、全局单例）会不会影响别人；退出时还原了吗 |
| 多版本共存 | 同一依赖的多个版本、本程序的多个版本同时在场会怎样 |
| 资源礼让 | 占用共享资源时有没有超时和让步；会不会长期独占 |

## 38 可移植性与构建上下文

| 检查点 | 什么算问题 |
| --- | --- |
| 路径 | 硬编码分隔符；文件系统路径与 URL 路径的处理函数混用 |
| 文件系统差异 | 大小写敏感性、权限模型、原子替换保证、最大文件名长度、链接支持、文件名规范化形式 → 同一逻辑名可能映射到两个文件 |
| 字长 | 依赖平台整数是 64 位；**32 位平台上原本不可达的溢出分支变成可达**；原子对齐见[16](#16-语言与运行时陷阱) |
| 字节序与对齐 | 依赖特定字节序；结构体布局假设 |
| 系统调用与网络栈差异 | 套接字选项、端口复用、路由与接口枚举、名字解析路径在各平台的差别 |
| 构建条件与本地代码 | 构建标签、条件编译宏、平台后缀文件、可选依赖与特性开关（如可选安装组、编译特性）让同一份源码有多种构建结果；静态检查只覆盖当前平台和默认条件，**其它构建上下文里的入口要单独说明未覆盖** |
| 交叉编译 | 声称支持的平台是否都能编过 |
| 平台专属代码 | 不能仅因当前环境无法验证就判为死代码或改写；任务确实涉及该行为时按授权修改，并说明未验证的平台 |
| **独立构建上下文** | 仓库级工作区和本地覆盖（如 Go 工作区与 `replace`、npm/pnpm/yarn 的 workspace 与 link、pip 可编辑安装、Cargo 的 `[patch]` 与路径依赖、CMake 子目录）掩盖了单独构建时的缺失；要发布或被外部引用的单元，脱离工作区后能否构建和测试 |
| 最低运行时版本 | 声明支持的语言、运行时或编译器最低版本低于代码实际用到的语法、标准库或语义；或声明的版本让新语义没有生效 |

## 39 生成产物与工具链

| 检查点 | 什么算问题 |
| --- | --- |
| 产物新鲜度 | 生成产物落后于生成源 |
| 手改产物 | 有人直接改了会被覆盖的生成文件 |
| 生成可复现 | 生成器版本没固定，不同机器产物不同 |
| **维护边界** | 生成源、生成产物、上游镜像与本地补丁是否被区分；写入、文档和受影响路径的验证统一按项目规范，不机械要求扫描或测试整份上游代码 |

## 40 可测试性与故障注入

> 这一项审的不是「测试写得好不好」，而是「**这段代码有没有办法测**」。

| 检查点 | 什么算问题 |
| --- | --- |
| 依赖注入点 | 时钟、文件系统、网络、随机数、外部服务硬编码成全局，行为不可控 |
| 故障注入 | 存储错误、短写、连接中断、部分失败、空间不足、依赖超时无法构造 → 错误路径永远测不到 |
| 确定性交错 | 并发问题只能靠重复跑碰运气，没有确定性复现手段 |
| 结果可观测 | 无法通过返回值、状态或副作用验证声称的行为；可用公开结果验证时，不因看不到私有字段判为问题 |
| 环境依赖 | 必须有真实数据库 / 网络 / 特权才能测 |
| **代价约束** | 优先用已有输入和依赖构造分支；是否允许内部调整按项目规范，不能为测试增加无关抽象、公开开关或热路径成本；无法稳定验证时说明边界 |

## 41 测试质量

| 检查点 | 怎么查 | 什么算问题 |
| --- | --- | --- |
| 恒真断言 | 静态检查 + 人工读 | 永远不会失败的判断 |
| 实现细节测试 | 读断言对象 | 只验证内部实现、不验证外部行为 |
| 冗余 | 对比用例覆盖的行为 | 多个用例验证同一条行为的同一个分支 |
| 未使用 helper | 静态检查 | 没人调的测试辅助函数 |
| 断言精度 | 读断言 | 只判「有错」不判具体错误；只判「有值」不判值对不对 |
| flake | 先读已有失败证据与同步条件，必要执行按项目测试策略 | 间歇失败被重跑掩盖，或失败条件没有记录 |
| **测试真的能抓到 bug 吗** | 对照触发输入、关键断言和修复前证据；隔离对照见[审查执行边界](scope.md#审查执行边界) | 用例虽通过，但没有到达问题路径或断言实际影响 |
| **测试执行上下文之外的断言** | 搜索测试里启动的线程、协程、回调、未等待的 Promise 或任务 | 在这些地方断言失败，很多框架不会让测试失败，或在测试结束后才报；有的框架规定「立即失败」只能在测试自己的执行流里调（如 Go 的 `FailNow`），子执行流要改用「记录失败并返回」 |
| **替身偏差** | 对照真实依赖的契约核对 fake、mock、stub | 替身比真实依赖更宽松或行为不同（不报错、不超时、顺序固定、无并发、不校验参数），测试全绿但真实环境出错 |
| 测试方法与问题类型 | 按目标类型核对 | 解析器与解码器缺模糊语料；有参考实现的引擎或协议缺差分对照；算法缺性质测试；与外部实现交换数据缺互通样本。只报告缺口，是否补测和跑测按项目测试策略 |
| 并行与清理顺序 | 读父子测试 | 父测试的延迟清理可能在并行子测试**之前**执行；共享资源要用框架提供的清理钩子 |
| 并行与共享状态 | 并行用例之间有没有共享目录、全局注册表、端口 | 相互干扰 |
| 泄漏 | 用例结束后的执行流、临时文件、连接、后台任务 | 泄漏 |
| 随机与种子 | 随机化的用例有没有固定种子 | 失败无法复现 |
| 环境依赖 | 网络、真实路径、固定睡眠、当前时间、时区 | 不可复现 / 慢 / flaky |
| 基准正确性 | 结果有没有被编译器优化掉；准备工作有没有算进计时 | 数字没有意义 |
| 规模 | 有没有在真实数量级上验证过（大数据量基准里带断言是个便宜办法） | 只在几条数据上测过就声称支撑很大规模 |
| 竞态检测 | 核对并发验证的路径、交错与工具记录 | 将未执行的交错或逻辑原子性当成已证明；结论边界见[18](#18-并发与内存模型) |
| 负面用例 | 看有没有「不该发生的事确实没发生」的断言 | 只测成功路径 |
| 拒绝后的副作用 | 检查未授权、无效签名、非法输入等失败断言 | 只检查错误码，没有验证数据未写入、额度未扣减、外部调用未发生或敏感字段未返回 |

测试的维护范围见[39](#39-生成产物与工具链)。

## 42 覆盖率

有有效覆盖率记录，或本次已获准采集时，再分析范围内的未覆盖行为。覆盖率只描述执行覆盖，不能证明断言有效或安全性；没有记录时如实说明，不自动生成全量基线。

| 类别 | 处理 |
| --- | --- |
| 能测但没测 | 只读审查报告行为缺口；已授权修改时按项目测试策略补本次受影响行为的测试 |
| 不可达 | 归入[死代码](#1-死代码与可达性)处理，不要为它写测试 |
| 只有注入故障或特定平台才能到达 | 记录为未验证边界，说明原因；能不能注入见[40](#40-可测试性与故障注入) |

优先考虑真实成功、拒绝和失败语义，测试实现的代价约束见[40](#40-可测试性与故障注入)。

## 43 文档一致性

| 检查点 | 怎么查 |
| --- | --- |
| 文档是否存在 | 按项目规范，该有定位说明 / 流程文档 / 测试矩阵的目录有没有 |
| 入口映射 | 按授权选择已有定向工具或人工核对，范围内入口应无缺失、重复与多余映射 |
| 流程真实性 | **工具通过不代表画对了**：逐入口人工对照源码，看参数怎么影响分支、出口画全没有、动态错误的来源与透传规则写没写 |
| 不变量 | 每条是否说明了拥有者、成立条件、保证内容、破坏后的结果、关联流程 |
| 陈旧事实 | 文档提到已删除、未实现、改过名的东西 |
| 权威位置唯一 | 同一事实有没有两处都只剩指引、哪里都没真正写下来 |
| 契约是否成文 | 并发契约、调用方义务、一致性承诺、失败语义、资源所有权、安全假设——这些最该写的有没有写 |
| 示例代码 | 文档里的示例还能编译/运行吗；用的是不是已删的入口 |
| 测试矩阵 | 矩阵里的用例名和代码里的是否双向对得上 |
| 链接与可渲染性 | 相对链接、锚点、交叉引用是否指向存在的文件和标题；图表语法（如 mermaid）能否解析渲染 |

> 注释本身的质量在[6 命名、注释与可读性](#6-命名注释与可读性)查。

## 44 项目规则合规

对照**目标项目自己的规范**逐条自查。至少覆盖这几类，具体条款以该项目的规范文件为准：

| 类别 | 查什么 |
| --- | --- |
| 目录与职责 | 新增内容是否放在职责所属的位置；有没有越界修改别的模块 |
| 修改范围 | 有没有超出本次授权的范围；范围外的问题是不是只报告没动手 |
| 维护边界 | 是否遵守[39](#39-生成产物与工具链)的生成与上游边界，以及[38](#38-可移植性与构建上下文)的平台验证限制 |
| 命名与风格 | 命名规则、注释规则、格式规则 |
| 兼容层 | 替换旧实现时旧名是否删干净 |
| 工具与命令边界 | 命令、读取、写入和外部访问是否符合项目规范与本次授权，不能用本清单的示例代替授权 |
| 缓存与临时目录 | 位置与命名是否合规 |

## 45 常驻与长时运行

> 前面各维大多在看「一次调用」或「一次突发」。这一维看两种情况：**没事做的时候**，以及**跑了很久以后**。适用于服务、守护进程、常驻客户端、长连接组件和长期运行的批处理。

| 检查点 | 什么算问题 |
| --- | --- |
| **空闲开销** | 没有请求时仍有周期唤醒、轮询、全量扫描或过密心跳；唤醒频率与实际工作量不相称；在电池设备或按量计费环境里的持续成本 |
| **持续错误热循环** | 本地一个持续存在的错误（已存在、权限不足、配置损坏、依赖不可达）让重试或事件循环不退避地空转，日志与指标随之刷屏 |
| 自激 | 自己的动作再次触发自己：监听自己写的文件、捕获自己发出的流量、在配置变更回调里改配置 |
| **计数与标识回绕** | 计数器、序号、世代号、连接或会话 ID、自增主键在运行期内能否回绕；回绕后是否与仍在使用的旧值撞车（与[18](#18-并发与内存模型) ABA 同源） |
| 缓慢增长 | 几天或几周后才显现的增长：缓存、映射表、日志文件、临时文件、句柄、监听器、指标序列；有没有轮转、淘汰或上界（上界判据见[20](#20-资源上界与背压)） |
| **运行中过期** | 内嵌或启动时加载的证书、公钥固定、令牌、根证书、日期常量、依赖接口的弃用截止日；到期时是自动更新、提前告警，还是突然失败 |
| 状态漂移 | 长时间运行后，内存里的状态与外部真实状态（路由表、文件、远端配置、名字解析结果）逐渐偏离；有没有周期对账 |
| 周期维护任务 | 压实、清理、轮转、续期这类任务失败一次后是否就再也不跑；失败有没有被发现 |
| **休眠与唤醒** | 宿主休眠、进程挂起、容器冻结后恢复：定时器集中补发形成洪峰；租约与连接已失效但本地仍当有效；单调钟在休眠期间是否计时（按平台核对） |
| 长时验证 | 声称常驻的组件有没有长时间运行或加速时间的验证手段；只运行过几分钟不能证明长期稳态 |
