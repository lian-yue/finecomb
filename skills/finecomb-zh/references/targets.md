# 非源码目标

审查目标不一定是源码。本文件说明目标是编译产物、安装包、扩展、镜像、已发布的包、线上地址、主机、集群、账号与租户状态、配置、数据、日志、合约地址、文档或智能体配置时，能拿到什么证据、先查什么、哪些看不到。各检查点的详细判据仍在[通用维度](dimensions.md)和[专项](specialties.md)里，这里只写这类目标特有的取证方式和检查点；[根因面](facets.md)照样对每个对象过一遍。

## 通用原则

- **先问能不能换成源码。** 能拿到源码、符号、构建配置、SBOM 或设计文档时，优先换成更强的证据；链上合约优先用区块浏览器上已验证的源码。.NET 与 JVM 字节码、打包的 Python、源映射、Electron 的 asar 包能还原到接近源码时，还原后按源码审，并写明还原方式和缺失的部分。
- **固定目标身份。** 记录制品的摘要（如 SHA-256）、版本与签名；线上目标记录地址与访问时间；链上目标记录链标识、合约地址与读取时的块高；账号、集群、租户记录其标识与读取所用的身份。这些写进报告的「结论与范围」。
- **保全证据。** 收到制品、导出或数据时先算摘要，记下来源、交付人、取得方式和时间（带时区，建议统一用 UTC）。原件只读，分析在副本上做。每条结论依据的原始输出（响应、截图、命令输出、抓包）也记下摘要、时间和保存位置。
- **结论有时效。** 线上服务、账号、集群、DNS 的状态随时会变，结论只对读取时刻成立。报告写明读取时间；复查时重新读取，不沿用旧结论。
- **取证方式分等级。** 静态查看制品默认可做；运行制品只在隔离环境里做；对线上目标的主动探测、登录尝试、模糊测试，以及任何链上交易，都要书面授权（见[审查执行边界](scope.md#审查执行边界)）。逆向工程受许可协议或当地法律限制时先确认。
- **看不到的维度照实记录。** 没有源码时，代码形态类维度（[1](dimensions.md#1-死代码与可达性)到[7](dimensions.md#7-复杂度与可维护性)）通常不适用或只能部分检查；内部逻辑只能从行为推断。在覆盖记录里写「部分检查」或「未检查」及原因，不能写成「未发现」。
- **证据强弱分开写。** 由版本号推断的已知漏洞、由反编译推断的逻辑，证据等级一般是「待验证」，除非有可复现的观察结果。

## 编译产物与二进制

适用：可执行文件、动态库、插件、驱动。安装程序另见[桌面安装包与桌面应用](#桌面安装包与桌面应用)。

| 检查点 | 什么算问题 |
| --- | --- |
| 身份与来源 | 摘要、版本、构建号、签名能否核对；签名者是谁；能否由源码可复现地构建出同样的产物 |
| **加固选项** | 地址随机化（PIE）、不可执行的栈与数据（NX）、只读重定位（RELRO）、栈保护、`_FORTIFY_SOURCE`、控制流保护；Linux 的完整只读重定位（`BIND_NOW`）、可执行栈（`GNU_STACK`）、CET 属性；Windows 的 ASLR（含高熵）、DEP、CFG、`/GS`、SafeSEH（32 位）、CET 影子栈兼容；macOS 的强化运行时与授权声明（entitlements） |
| **危险的授权声明** | macOS 发布版带 `get-task-allow`（可被附加调试和注入）、`disable-library-validation`、`allow-dyld-environment-variables`、`allow-unsigned-executable-memory` |
| **内嵌的秘密与地址** | 字符串、资源和配置段里的密钥、口令、令牌、内部地址、调试开关 |
| 链接的库与版本 | 静态或动态链接的库及其版本，是否有已知漏洞（按[36](dimensions.md#36-供应链与制品完整性)查） |
| 内嵌的构建信息 | Go 程序和用 `cargo auditable` 构建的 Rust 程序内嵌了完整的依赖和版本，可以直接按版本查漏洞，比特征识别可靠 |
| 调试残留 | 没剥离的符号、调试接口、测试后门、隐藏命令 |
| 危险调用 | 导入表里的命令执行、不安全的字符串函数、动态加载 |
| **库的搜索路径** | ELF 的 RPATH、RUNPATH 含相对路径或可写目录；Mach-O 的 `LC_RPATH` 和弱链接指向不存在的库；Windows 的搜索顺序会先找到可写目录里的同名 DLL |
| 更新与加载 | 自动更新、插件加载（见[4.35](specialties.md#435-客户端应用扩展与自动更新)、[4.32](specialties.md#432-跨语言边界与本地扩展)） |
| 许可与声明 | 打包进来的第三方组件的许可证义务 |

## 桌面安装包与桌面应用

适用：Windows 的 MSI 与 EXE 安装程序，macOS 的 DMG 与 pkg，Linux 的 deb、rpm、AppImage、Snap、Flatpak，以及装出来的桌面应用（含 Electron 等内嵌网页的框架）。其中的可执行文件另按[编译产物与二进制](#编译产物与二进制)查，更新机制见[4.35](specialties.md#435-客户端应用扩展与自动更新)。

| 检查点 | 什么算问题 |
| --- | --- |
| 签名与公证 | Windows 的 Authenticode 签名与时间戳；macOS 的开发者签名、公证与装订；Linux 包的仓库签名；包里每个可执行文件是否都签了；签名证书是否过期或被吊销 |
| **安装脚本与自定义动作** | MSI 的自定义动作、pkg 的 `preinstall` 与 `postinstall`、deb 与 rpm 的维护脚本通常以最高权限运行：执行了什么、下载了什么、有没有校验 |
| **修复与卸载提权** | MSI 缓存在系统目录，普通用户能触发修复；修复中以 SYSTEM 执行的动作能否被劫持（引用不存在的文件、写入普通用户可写的目录、弹出命令窗口） |
| 安装位置与权限 | 高权限服务运行的程序装在普通用户可写的目录；Windows 服务路径没加引号 |
| **库的搜索路径** | 安装程序从下载目录加载同名 DLL；macOS 的 `@rpath` 或 Linux 的 RPATH 指向可写目录 |
| **对系统的改动** | 安装根证书（私钥随安装包分发时，任何人都能签发被信任的证书）；修改 hosts、代理、防火墙规则；装驱动、服务、计划任务；卸载后是否留下 |
| 沙箱与权限声明 | Snap 的 `classic` 或 `devmode` 约束；Flatpak `finish-args` 里的 `--filesystem=host`、能访问 `org.freedesktop.Flatpak` 的会话总线权限（可逃出沙箱）；macOS 的应用沙箱与强化运行时授权 |
| 内嵌网页框架 | Electron 的 Node 集成、上下文隔离、fuse 设置（`RunAsNode`、asar 完整性校验、只从 asar 加载）；asar 包里的源码与秘密 |
| 捆绑的运行时 | 打包进来的 Java、Python、Node、OpenSSL 的版本与支持期（见[36](dimensions.md#36-供应链与制品完整性)） |

## 移动应用包

适用：APK、AAB、IPA 等安装包。组件与进程间通信的完整判据见[4.49](specialties.md#449-移动应用组件与进程间通信)；这里只列拿到安装包时先查的项。

| 检查点 | 什么算问题 |
| --- | --- |
| 清单与配置 | 可调试、允许备份、允许明文流量、网络安全配置、iOS 的 ATS 例外 |
| **导出组件与深链接** | 导出的活动、服务、广播接收器、内容提供者；URL scheme 与通用链接的参数校验（见[4.35](specialties.md#435-客户端应用扩展与自动更新)） |
| **内嵌秘密** | API 密钥、客户端密钥、私有服务地址；把本该留在服务端的秘密放进了客户端 |
| 证书校验与固定 | 是否跳过证书校验；是否做了证书固定，固定的证书到期或轮换时怎么办 |
| 本地存储 | 令牌和个人数据存在哪里（系统钥匙串、Keystore，还是明文文件、偏好设置、数据库）；截图与剪贴板 |
| **本地认证** | 生物识别只返回一个布尔值就放行，挂钩即可绕过；应把结果绑定到系统密钥库里的密钥（Android 的 `CryptoObject`、iOS 钥匙串的访问控制） |
| 平台交互 | 可变的 `PendingIntent`；把收到的 Intent 原样转发；`FileProvider` 的路径配置过宽（如 `root-path`）；敏感界面没有防遮挡 |
| 目标系统版本 | `targetSdkVersion` 过低会保留旧的不安全默认值（低于 24 时信任用户安装的证书；低于 31 时带过滤器的组件默认导出）；最低版本过低时缺少系统防护 |
| 内嵌网页 | WebView 暴露的 JavaScript 接口、文件访问、混合内容 |
| **云后端配置** | 包里的 Firebase、对象存储、身份池配置；数据库规则或存储桶是否公开可读写。验证要向服务发请求，按授权处理 |
| 动态加载 | 运行时下载并加载的代码或脚本包（热更新）是否校验签名 |
| 原生库 | 包里的 `.so` 和框架按[编译产物与二进制](#编译产物与二进制)查加固与版本 |
| 第三方 SDK | 统计、广告、崩溃报告 SDK 收集和外发了哪些数据（见[30](dimensions.md#30-隐私数据治理与合规)） |
| 隐私声明 | iOS 隐私清单（`PrivacyInfo.xcprivacy`）、商店的数据安全声明、第三方 SDK 的实际收集是否一致 |
| 签名与混淆 | 签名方案与证书；安全是否依赖混淆后的「保密」 |
| 强制更新 | 发现漏洞后，能否让旧版本停用或强制升级 |

## 浏览器扩展

适用：Chrome、Edge、Firefox、Safari 等浏览器的扩展包（CRX、XPI、ZIP），或商店里的上架版本。代码层面见[4.35](specialties.md#435-客户端应用扩展与自动更新)。

| 检查点 | 什么算问题 |
| --- | --- |
| **权限与站点范围** | `permissions`、`host_permissions`、内容脚本的 `matches` 超出功能需要；`<all_urls>`、`cookies`、`webRequest`、`debugger`、`scripting`、`nativeMessaging` 这类高权限 |
| **远程代码** | 下载并执行远程脚本、`eval`、把远程配置当代码执行；商店政策禁止，但侧载版本和旧版本仍可能有 |
| **与网页的通信** | `externally_connectable` 允许哪些网站发消息；`onMessageExternal` 和内容脚本收到的 `postMessage` 是否校验来源与结构；网页能否驱动扩展的特权接口 |
| 可被网页访问的资源 | `web_accessible_resources` 暴露的页面能被网页嵌入（点击劫持），或被用来探测用户装了哪些扩展 |
| 内容安全策略 | 扩展页面的内容安全策略被放宽 |
| 本地存储的秘密 | 令牌存在 `storage.local`，或存在会同步到账号的 `storage.sync`；网页上下文能否读到 |
| 本机程序通信 | 原生消息宿主清单里的 `allowed_origins`；宿主程序是否校验输入 |
| **更新与发布账号** | 自定义的 `update_url`；商店发布账号是否开了多因子、谁能发布。2024 年底有多个扩展因开发者被钓鱼而推送了恶意更新 |
| 数据外发 | 收集的浏览记录、页面内容、表单数据发往哪里（见[30](dimensions.md#30-隐私数据治理与合规)） |

| 检查点 | 什么算问题 |
| --- | --- |
| 提取与文件系统 | 能否解包；文件系统里的服务、启动脚本和配置 |
| **默认凭据与共享密钥** | 默认账号口令；所有设备共用同一把私钥、证书或 SSH 主机密钥 |

| **安全启动链** | 引导程序是否校验内核与文件系统的签名；U-Boot 环境变量可写、启动倒计时可被打断进入命令行；镜像里看得到校验逻辑，但芯片熔丝是否烧写要看实物 |
| 固件获取与加密 | 固件下载地址是否用 HTTPS 并校验；加密不等于签名，只加密、不验签的固件仍可被替换 |
| 更新机制 | 更新包的签名校验与防降级（见[4.36](specialties.md#436-嵌入式固件与实时约束)） |
| 程序加固 | 固件里的程序通常没有 PIE 和栈保护，按[编译产物与二进制](#编译产物与二进制)查 |
| 连云凭据 | 设备连云用的密钥、证书、消息服务账号是否每台一份（见[设备通信与物联网协议](#设备通信与物联网协议)） |
| 调试接口 | 串口、JTAG、调试服务在量产版本里是否关闭 |
| 仿真的边界 | 仿真跑起来的界面与真实设备不同；仿真失败的部分只能静态看，结论里注明 |

## 设备通信与物联网协议

适用：只拿到设备、网关，或抓到的无线与消息流量（BLE、Zigbee、MQTT、CoAP 等），或这些协议的配置。固件见[固件与设备镜像](#固件与设备镜像)。

| 检查点 | 什么算问题 |
| --- | --- |
| **BLE 配对** | 用旧式配对（LE Legacy Pairing）时，抓到配对过程就能算出密钥；「Just Works」配对不防中间人；敏感特征值不要求加密和认证就能读写 |
| BLE 隐私 | 设备用固定地址而不是可解析的随机地址，可被跟踪 |
| **Zigbee 入网** | 仍接受公开的默认信任中心链接密钥（`ZigBeeAlliance09`）；没用安装码；入网窗口开放太久；网络密钥用公开密钥加密后下发 |
| **MQTT 认证与授权** | 允许匿名连接；只在 1883 明文端口服务；主题权限没按设备隔离，任何客户端都能订阅 `#`；保留消息里有秘密；客户端 ID 冲突能把别的设备踢下线 |
| 配网过程 | 首次配网用的热点是否开放；Wi-Fi 口令是否明文传输 |
| 设备身份 | 每台设备有独立的证书或密钥，还是共用一把（见固件的「默认凭据与共享密钥」） |
| 重放与新鲜度 | 开锁、开关等命令能否被录下后重放 |
| 空中升级 | 升级包在无线链路上是否签名并校验（见[4.36](specialties.md#436-嵌入式固件与实时约束)） |
| 放大与暴露 | CoAP、SSDP 等基于 UDP 的服务对外开放时能被用来反射放大 |

## 已发布的包

适用：从注册表或下载页拿到的 npm 包、Python 的 wheel 与 sdist、JAR、gem、crate、NuGet 包、Go 模块等。审的是使用方实际装到的内容，不是仓库。库本身的发布检查见[4.34](specialties.md#434-可发布的库sdk-与包)。

| 检查点 | 什么算问题 |
| --- | --- |
| **包与源码一致** | 包里的文件与对应标签或提交的源码不一致：多出构建脚本、压缩的测试数据、预编译文件，或内容被改过。xz utils 的后门只在发布的压缩包里，仓库里看不到 |
| 来源提交 | 包有没有记录来源提交（crate 的 `.cargo_vcs_info.json`、npm 注册表元数据里的 `gitHead`、来源证明里的提交）；该提交在仓库里是否存在；打包时工作区是否干净 |
| **安装与构建期执行** | npm 的 `preinstall`、`install`、`postinstall`；sdist 的 `setup.py` 与构建后端；gem 的原生扩展；crate 的 `build.rs` 与过程宏；NuGet 的 `.props`、`.targets`。它们运行什么、是否联网、是否读取环境变量 |
| 预编译内容 | 包里的原生库、压缩或混淆的脚本能否由源码重建；不能重建的按[编译产物与二进制](#编译产物与二进制)查 |
| 签名与来源证明 | npm 的来源证明、PyPI 的数字证明、NuGet 的作者签名、Maven Central 的签名文件是否存在，是否指向预期的仓库和工作流（见[签名与来源证明](#签名与来源证明)） |
| 发布者与版本历史 | 维护者或发布账号近期是否变化；版本发布后很快撤下；版本号异常跳跃；同名包出现在其它注册表 |
| 版本间差异 | 相邻版本之间新增的联网、进程、文件写入和先解码再执行的代码 |
| 元数据 | 仓库地址、许可证、声明的依赖是否与源码一致；仓库地址指向别人的项目，借别人的星标和信誉 |

## 签名与来源证明

适用：带签名、来源证明（provenance）、in-toto 证明或透明日志记录的任何制品，包括二进制、安装包、镜像、语言包和固件。

| 检查点 | 什么算问题 |
| --- | --- |
| **验签绑定身份** | 只检查「有有效签名」，没有核对签名者是预期的那一个（证书主题、OIDC 签发方、密钥指纹）。无密钥签名不限定身份时，任何人都能签出「有效」签名 |
| **证明对准制品** | 证明里的主体摘要与手上制品的摘要不同；只按文件名或标签对上 |
| **来源与构建者** | 证明里的源码仓库、分支或标签、构建工作流、构建平台与预期不符；来自分叉仓库、非保护分支或本地机器的构建 |
| 构建等级 | 声明的 SLSA 构建等级没有证据：L1 只要求有来源证明；L2 要求由托管构建平台签发；L3 还要求各次构建相互隔离、签名密钥不被构建步骤拿到 |
| 透明日志 | 签名和证明是否记入透明日志（如 Rekor）；离线验证时有没有带上包含证明 |
| 证书与时间 | 签名时证书是否有效；有没有可信时间戳；密钥轮换与吊销后旧签名怎么处理 |
| 构建输入 | 证明里列出的构建输入（依赖、基础镜像、工具）是否固定到摘要 |
| in-toto 布局 | 有布局时，每一步的执行者和前后产物链是否都通过验证；布局本身由谁签 |

## 依赖清单、锁文件与 SBOM

适用：只有依赖清单、锁文件、组件清单（SBOM）或漏洞可利用性声明（VEX）的目标。

| 检查点 | 什么算问题 |
| --- | --- |
| 已知漏洞与修复版本 | 按[36](dimensions.md#36-供应链与制品完整性)的「已知漏洞」「安全修复版本」查 |
| 支持期与维护状态 | 组件是否过了支持期、是否已无人维护 |
| 许可证 | 许可证与分发方式是否兼容 |
| 私有包名 | 私有包名在公共注册表上是否已被别人注册（依赖混淆） |
| 完整性 | 锁文件是否带校验和；清单与锁文件是否一致 |
| **清单与制品一致** | SBOM 按源码、构建过程还是最终制品生成；与实际发布的制品比对，漏掉静态链接的库、复制进来的代码、运行时下载的组件 |
| 最小要素 | 组件名、版本、生产者、唯一标识（purl 或 CPE）、依赖关系、组件哈希、许可证、生成工具与生成时机、清单作者与时间是否齐全；缺唯一标识的组件查不了漏洞 |
| 格式有效 | 能否通过 CycloneDX 或 SPDX 的格式校验；版本号或 purl 写错时，扫描器会静默跳过该组件 |
| **VEX 结论有依据** | 标「不受影响」的条目是否写明理由（组件不存在、漏洞代码不存在、不在执行路径、攻击者控制不了输入、已有内联缓解），理由是否与代码和配置相符；谁签发、何时签发；制品升级后是否已过期 |
| 清单的签名 | SBOM 和 VEX 是否签名，或以证明形式绑定到制品摘要 |

## 线上服务

适用：只给了地址、域名或 URL 的目标。这是黑盒审查，结论只覆盖外部能观察到的部分。

| 检查点 | 什么算问题 |
| --- | --- |
| **授权与范围** | 目标归属、允许的地址与时间窗、允许的操作（只被动观察，还是可以主动测试）是否书面确认；没有确认时只做被动观察 |
| 暴露面 | 开放的端口与服务、子域名、证书透明日志里的主机名、公开的管理界面与调试接口 |
| 传输层 | 协议版本、证书链与有效期 |
| 响应与头部 | 安全响应头（含 HSTS）、Cookie 属性；泄漏版本与内部信息的响应头和错误页 |
| 公开的敏感文件 | 版本库目录、环境变量文件、备份文件、源映射、目录列表 |
| 公开的接口描述 | `openapi.json`、`swagger.json`、GraphQL 内省、`/.well-known/` 下的配置是否对外；拿到后按[接口规格文件](#接口规格文件)查 |
| 跨源访问 | 带一个外部 `Origin` 头的普通请求，就能看出是否反射任意来源并允许凭据（见[4.14](specialties.md#414-服务端请求处理与中间件)） |
| 前端资源 | 页面引用的第三方脚本及其完整性校验；打包的脚本按[前端包与源映射](#前端包与源映射)查 |
| **悬挂 DNS 与子域名接管** | DNS 记录指向已经释放的云资源、存储桶或第三方服务，别人认领后就能以你的域名提供内容 |
| 域名与邮件 | 按[域名、DNS 与邮件配置](#域名dns-与邮件配置)查 |
| 安全联系方式 | 有没有 `/.well-known/security.txt`，`Expires` 是否已过期 |
| 版本与已知漏洞 | 能识别出的产品与版本对应的已知漏洞；结论注明是按版本推断的 |
| 主动测试 | 登录尝试、扫描、模糊测试、漏洞验证只在授权范围内进行；不做拒绝服务，不读取真实用户数据 |

需要映射 OWASP ASVS 时，只凭外部观察能验证的主要是 5.0 版 V3（网页前端安全）、V12（安全通信）、V13（配置）中的部分条目；有测试账号时，再加上 V6（认证）、V7（会话）、V8（授权）的部分条目。其余章节需要源码或内部证据，在覆盖记录里写「未检查」。

| 调试残留 | 生产包里的调试日志、测试账号、模拟接口 |

## 接口规格文件

适用：只有 OpenAPI、AsyncAPI、GraphQL schema、protobuf 或 gRPC 定义、Postman 集合等接口描述的目标。规格与实现是否一致见[43](dimensions.md#43-文档一致性)。

| 检查点 | 什么算问题 |
| --- | --- |
| **认证覆盖** | 哪些操作没有声明安全要求；全局要求被单个操作用 `security: []` 去掉，或数组里含空对象 `{}`，变成认证可选；认证方式本身不合适（如 API 密钥放在查询参数里） |
| **对象标识** | 路径和参数里的对象 ID 可枚举（如自增整数）；这些操作都需要对象级授权（见[28](dimensions.md#28-授权与访问控制)），规格本身证明不了有没有做 |
| 输入约束 | 字符串、数组、数字没有 `maxLength`、`maxItems`、`maximum`、`pattern`；对象允许多余字段（`additionalProperties`），可能被批量赋值；上传大小与类型没有限制 |
| 输出暴露 | 响应模型里有口令哈希、令牌、内部 ID、个人信息；错误响应模型带内部信息 |
| 服务器地址 | `servers` 里的 `http://` 地址、内部地址、测试环境地址 |
| 回调地址 | `callbacks`、`webhooks` 或参数里的地址会被服务端请求（见[4.21](specialties.md#421-出站请求与服务端请求伪造)、[4.24](specialties.md#424-webhook-与外部事件)） |
| 分页与批量 | 列表接口没有分页上限；批量接口一次能处理的条数没有上限（见[20](dimensions.md#20-资源上界与背压)） |
| 版本与废弃 | 标了废弃却仍在规格里的操作；多个版本规格之间的差异（影子接口见[4.14](specialties.md#414-服务端请求处理与中间件)） |
| 示例里的秘密 | `example` 字段和 Postman 环境变量里的真实令牌、账号 |
| GraphQL 与 gRPC | 查询深度与复杂度限制在规格里看不出来，标成「待验证」；变更操作的授权；gRPC 反射是否开启 |

## 域名、DNS 与邮件配置

适用：只给了域名，或给了 DNS 区域文件、邮件服务配置的目标。子域名接管见[线上服务](#线上服务)。

| 检查点 | 什么算问题 |
| --- | --- |
| **SPF** | 记录不唯一或语法错；结尾是 `+all` 或 `?all`；DNS 查询次数超过 10 次，超过后整条失效；`include` 了共享发信平台，平台上的其它客户也能用你的域名发信 |
| **DMARC** | 没有记录；策略长期停在 `p=none`；子域策略；报告地址是否在自己控制下；对齐方式；按现行标准核对已废弃的标签（新版标准已去掉 `pct`） |
| DKIM | 在用的密钥不足 1024 位（建议 2048 位）；仍用 `rsa-sha1` 签名；旧选择器和测试密钥没有撤掉 |
| 不发信的域名 | 不发邮件的域名和子域没有声明 `v=spf1 -all` 和 `p=reject`，容易被冒用 |
| 传输加密 | MTA-STS 策略是否为 `enforce`，策略里的 MX 与实际是否一致；TLS 报告；有 DNSSEC 时的 DANE |
| **DNSSEC** | 未签名；DS 与 DNSKEY 链条断开；算法过旧；签名快过期；使用 NSEC 时区域内容可被遍历 |
| **CAA** | 没有限制可签发证书的机构；通配证书的 `issuewild`；`iodef` 通知地址 |
| 委派与注册 | 名称服务器指向已不再使用的托管商（名称服务器接管）；域名快到期；没有注册商锁 |
| 区域传送与开放解析 | 权威服务器允许任意来源做区域传送；对外提供递归解析，可被用来放大攻击。这两项要发主动查询，按授权处理 |
| 记录里的泄漏 | TXT 记录里的内部信息和验证令牌；解析出的内网地址 |

## 主机与操作系统

适用：用只读账号登录的服务器、虚拟机、工作站，或它们的配置导出与基线检查结果。容器运行时所在的宿主也按本节查。

| 检查点 | 什么算问题 |
| --- | --- |
| 补丁与支持期 | 系统和内核版本已过支持期；有未安装的安全更新 |
| 远程登录 | SSH 允许 root 登录或口令登录、算法过旧；远程桌面没有网络级认证；管理端口对外开放 |
| **本地提权路径** | 免口令的 sudo 规则；带 SUID 的程序；普通用户可写的服务文件、定时任务脚本、`PATH` 目录；Windows 未加引号的服务路径、可写的服务程序、`AlwaysInstallElevated` |
| 账号与口令 | 空口令、共享账号、长期不用的账号；口令哈希算法过旧（如 `/etc/shadow` 里的 `$1$`） |
| 监听服务 | 监听在所有地址但不需要对外的服务；没用的服务仍在运行 |
| 主机防火墙与内核参数 | 防火墙没启用或全部放行；地址随机化、转发、源地址校验等内核参数 |
| 强制访问控制与加密 | SELinux、AppArmor 被关闭；磁盘没加密；安全启动没开 |
| 文件权限与完整性 | 全局可写的文件和目录；私钥、凭据文件权限过宽；系统文件与包管理器记录的校验和不一致 |
| 日志、审计与时间 | 审计规则、日志转发与保留；时间同步 |
| **容器运行时** | Docker 远程接口不加认证；`docker` 组成员等同 root；守护进程配置（用户命名空间、容器间通信） |

适用：用只读身份查看的云账号或平台配置。集群另见[Kubernetes 集群](#kubernetes-集群)。

| 检查点 | 什么算问题 |
| --- | --- |
| 身份与权限 | 过宽的角色和策略、长期不用的密钥、没开多因子的管理员、跨账号信任 |
| 公开暴露 | 公开的存储桶、快照、镜像；对全网开放的安全组和负载均衡 |
| **实例元数据服务** | 是否强制使用要会话令牌的版本（如 AWS 的 IMDSv2）；工作负载一旦被 SSRF，能否拿到云凭据（见[4.21](specialties.md#421-出站请求与服务端请求伪造)） |
| **联合身份信任条件** | 信任外部身份（如持续集成的 OIDC 令牌）的角色是否限定了仓库、分支和受众；只信任签发方、不限主体时，别人的工作流也能扮演这个角色 |
| 跨账号信任 | 给第三方的跨账号角色是否要求外部 ID，防止被冒用（混淆代理） |
| 根账号与应急账号 | 根账号有没有访问密钥、有没有多因子、最近有没有被使用 |
| 组织级护栏 | 组织策略、禁止公开共享、地域限制；只读身份看不到上层策略时记为「未检查」 |
| 托管服务里的秘密 | 函数和容器服务环境变量里的秘密；函数执行角色的权限；公开的函数地址 |
| 日志与监控 | 审计日志是否开启，保留期多长，能否被篡改 |
| 加密与密钥 | 静态加密、密钥轮换、谁能使用密钥 |
| 与声明的差异 | 实际状态与基础设施代码的漂移（见[4.33](specialties.md#433-构建脚本持续集成与基础设施即代码)） |

## Kubernetes 集群

适用：用只读身份查看的 Kubernetes 集群，自建或托管都算。托管集群的控制面由厂商管理，相关基线条目记为不适用，改用该厂商的 CIS 基线。只有清单文件时按[配置、部署清单与基础设施代码](#配置部署清单与基础设施代码)查。

| 检查点 | 什么算问题 |
| --- | --- |
| **RBAC 过宽** | 绑定到 `cluster-admin` 的主体；通配的动词与资源；`escalate`、`bind`、`impersonate`；能创建 Pod、读 Secret 或执行 `exec` 的主体，实际等于拿到了节点或凭据 |
| **未认证入口** | API 服务器允许匿名访问；kubelet 未认证或只读端口开放；管理面板、etcd 对外可达或不用证书认证 |
| 工作负载隔离 | 各命名空间的 Pod 安全级别（privileged、baseline、restricted）；特权容器、宿主目录挂载、宿主网络或进程命名空间、多余的能力、以 root 运行 |
| 服务账号令牌 | 默认自动挂载令牌；长期有效的令牌 Secret；工作负载使用默认服务账号 |
| **网络隔离** | 没有默认拒绝的网络策略；所用网络插件不执行网络策略，写了也不生效；Pod 能访问云元数据服务 |
| Secret 保护 | Secret 没有开启静态加密；秘密放在 ConfigMap 或环境变量里；谁能列出 Secret |
| 准入与镜像 | 有没有准入策略；镜像是否固定到摘要、是否只来自可信仓库、是否验签 |
| 审计日志 | API 服务器的审计策略是否开启，记录级别和保留期 |
| 版本与支持期 | 集群和节点版本是否仍在上游或托管厂商的支持期内 |

## 配置、部署清单与基础设施代码

适用：只有配置文件、部署清单、Helm chart、Kustomize、基础设施代码、Terraform 状态与计划文件的目标。按[32](dimensions.md#32-配置与默认值)、[34](dimensions.md#34-运行环境与部署契约)、[4.33](specialties.md#433-构建脚本持续集成与基础设施即代码)检查。

| 检查点 | 什么算问题 |
| --- | --- |
| 秘密 | 配置里明文的凭据 |
| 暴露与权限 | 监听地址、公开端口、特权、宿主挂载 |
| 默认值与环境差异 | 与生产环境的差异；没有覆盖掉的危险默认值 |
| **渲染后再查** | Helm chart 和 Kustomize 覆盖要用实际的取值文件渲染后再查；只看模板和默认值会漏掉条件分支，默认值本身也常常不安全 |
| chart 来源 | chart 仓库是否用 HTTPS；是否有来源文件（`.prov`）或签名并已验证；依赖的子 chart 是否锁定版本 |
| 安装钩子与集群读取 | Helm 钩子任务的权限；模板里的 `lookup` 会读集群里的 Secret，而且渲染时返回空，渲染结果与实际安装不同 |
| **状态与计划文件** | Terraform 的状态文件和计划文件以明文保存所有资源属性，包括数据库口令和生成的私钥；`sensitive` 只影响显示 |
| 状态后端 | 状态存储是否加密、是否开启版本与锁、谁能读写；存储桶是否公开 |
| 状态的时效 | 状态只是上次应用或刷新时的快照，可能已与真实环境不同（见[云账号](#云账号与基础设施状态)「与声明的差异」） |

## 网络设备与防火墙配置

适用：路由器、交换机、防火墙、负载均衡、VPN 网关的配置导出或规则集。

| 检查点 | 什么算问题 |
| --- | --- |
| **管理面暴露** | Telnet、HTTP、SNMP 对外网或用户网段开放；管理访问没有限定来源地址；管理界面对互联网开放，近年大量网关漏洞从这里进来 |
| 口令与密钥 | 本地口令的存储方式（如 Cisco 的 type 7 可逆，type 5 是 MD5，应使用 type 8 或 9）；SNMP 仍用 v1 或 v2c，团体字是 `public`、`private`；预共享密钥强度 |
| **过宽的规则** | `any any` 的放行规则；规则被前面的规则遮住，或永远不会命中；临时规则长期留着；出站不设限制（见[4.29](specialties.md#429-规则与策略匹配)） |
| 认证与记账 | 是否走集中认证（TACACS+、RADIUS）；应急本地账号；命令记账 |
| 加密协议 | SSH 版本与算法；VPN 的 IKE 版本、加密套件，用证书还是预共享密钥 |
| 路由与二层 | 路由协议是否认证；未用端口是否关闭；DHCP 侦听、ARP 检测 |
| 日志与时间 | 日志发往哪里；NTP 是否配置并认证 |
| 固件版本 | 版本对照厂商安全公告（按[36](dimensions.md#36-供应链与制品完整性)的「已知漏洞」查），结论注明是按版本推断的 |

## SaaS 租户与第三方集成

适用：只给了办公套件、代码托管、客户管理等 SaaS 平台的管理员只读身份，或要审查接入这些平台的第三方应用与集成。

| 检查点 | 什么算问题 |
| --- | --- |
| **第三方应用授权** | 已授权的 OAuth 应用和集成拿到的权限范围（读写全部邮件、全部文件、全部仓库）；普通用户能否自行授权；发布者是否经过验证；长期不用的授权没有撤销 |
| **长期令牌与密钥** | 个人访问令牌、API 密钥、服务账号密钥没有有效期或长期不轮换；集成专用账号权限过大 |
| **登录与多因子** | 是否强制单点登录；管理员和所有用户是否强制多因子；绕过单点登录的本地账号和旧式认证协议（如基础认证的 IMAP、POP）是否关闭 |
| 管理员 | 超级管理员数量；应急账号的保管与监控；测试租户或旧租户是否与正式环境相连 |
| 外部共享 | 「任何知道链接的人」共享；访客与外部协作者；公开的仓库、看板、表单 |
| 数据外流通道 | 自动转发到外部邮箱的规则；Webhook 与数据导出连接器的目的地（见[4.24](specialties.md#424-webhook-与外部事件)） |
| 审计日志 | 是否开启、保留多久；关键事件是否因许可等级不够而记录不到 |
| 离职与回收 | 离职人员的账号、令牌、授权是否随身份源一起回收 |
| 代码托管平台 | 组织的默认权限；分支保护或规则集；持续集成默认令牌的权限；部署密钥；秘密扫描与推送保护（见[4.33](specialties.md#433-构建脚本持续集成与基础设施即代码)） |

## 智能体配置与 MCP 服务器

适用：只拿到智能体的系统提示词、规则文件（如 `AGENTS.md`、`CLAUDE.md`、`.cursor/rules/`）、技能与工具清单、MCP 客户端配置（如 `.mcp.json`、`.vscode/mcp.json`、`claude_desktop_config.json`）或 MCP 服务器声明的工具，而不审其实现代码。代码层面见[4.26](specialties.md#426-大模型与工具调用)。

| 检查点 | 什么算问题 |
| --- | --- |
| **配置里的秘密** | `env`、`headers`、命令参数里写死的令牌和密钥；配置文件被提交进仓库或同步到云端 |
| **服务器来源与固定** | 用 `npx -y`、`uvx`、`docker run` 拉起的服务器没有固定版本或摘要，每次启动都可能换成别的代码；包名是否冒名；远程服务器由谁运营 |
| **工具描述投毒** | 工具名、描述、参数说明里夹带给模型的指令；隐藏的 Unicode 字符（零宽、双向控制、标签字符）；描述在用户批准后被悄悄改掉 |
| 同名遮蔽 | 多个服务器提供同名或相近的工具；一个服务器的描述改变另一个工具的用法 |
| **权限与自动批准** | 免确认的工具清单、允许的命令通配（例如允许任意 shell）、可读写的目录范围；执行命令、写文件、发消息、付款等高危工具是否仍要人工确认 |
| **危险组合** | 同一会话里既能读私有数据、又会接触不可信内容、还能向外发送时，外部内容可以把数据带出去；按工具组合判断，不只看单个工具 |
| 远程服务器认证 | 远程服务器是否要求认证；服务器是否把客户端的令牌原样转给下游服务；OAuth 授权范围是否最小 |
| 本机服务器暴露 | 本机 HTTP 型服务器是否只绑定回环地址、校验 `Origin` 并要求认证；否则网页可经 DNS 重绑调用它 |
| 提示词承担的安全 | 安全规则只写在提示词里，没有在工具执行层落实；提示词里的密钥和内部地址（见[4.26](specialties.md#426-大模型与工具调用)） |
| 可写的上下文 | 长期记忆、检索库、规则文件、技能目录谁能写；别人提交的规则文件能否改变智能体行为 |
| 调用记录 | 工具调用和批准有没有记录，能否追溯谁批准了什么 |

## 数据库与数据集

适用：数据导出、只读连接或数据文件。

| 检查点 | 什么算问题 |
| --- | --- |
| 访问权限 | 账号与角色的权限；谁能读敏感表 |
| 敏感数据清点 | 个人信息、凭据、支付数据在哪些表和字段；是否加密或脱敏 |
| **口令与令牌的存储形式** | 用户表里的口令哈希格式（`$argon2id$`、`$2b$`，还是无盐的 MD5、SHA-1 十六进制串）；明文保存的令牌、API 密钥、找回问题答案（判据见[4.5](specialties.md#45-认证会话与令牌)） |
| 数据库自身配置 | 监听地址、传输加密、默认或空口令账号、没开认证、审计开关；有只读连接时查，只有导出文件时记为「未检查」 |

| 约束与完整性 | 应有的唯一、外键、非空、检查约束是否存在；数据里是否已有违反业务规则的记录 |

| 导出文件本身 | 这份导出放在哪里、是否加密、谁拿得到；它本身也按敏感数据处置 |

## 日志、流量与运行数据

适用：日志导出、抓包（pcap）、HAR 文件、监控数据等。

| 检查点 | 什么算问题 |
| --- | --- |
| **证据完整** | 收到时算摘要，记下来源、时间范围和时区；在副本上分析；记下抓包的采集点在哪里 |
| 覆盖与断档 | 时间线有没有断档（轮转、采样、丢弃、时钟跳变）；断档期间的结论只能写「无法确定」 |
| 敏感数据 | 日志和流量样本里的个人信息、令牌、口令（见[30](dimensions.md#30-隐私数据治理与合规)、[4.4](specialties.md#44-加密与凭据)） |
| **会话材料** | HAR 文件和调试抓包里带着 Cookie 和令牌，本身就是凭据。2023 年有客服系统里的 HAR 文件被窃，导致会话被劫持 |
| 明文协议与凭据 | HTTP 基本认证、FTP、Telnet、明文 SMTP 登录；内部服务之间没有加密 |
| 传输参数 | 协商出的 TLS 版本与套件；证书链（TLS 1.3 下证书已加密，抓包里看不到）；证书出错后客户端是否继续连接 |
| 异常外联 | 意外的出站目的地；固定间隔的回连；DNS 查询里很长的随机子域名 |
| 审计事件完整性 | 应有的安全事件是否都有记录（见[4.23](specialties.md#423-安全审计日志)） |
| 日志注入 | 伪造的换行和字段、伪造的事件（见[4.23](specialties.md#423-安全审计日志)） |
| 攻击迹象 | 明显的探测、利用尝试、异常认证；发现疑似入侵时按项目的事件响应流程上报，本清单不替代取证 |

## 事故报告与事后复盘

适用：只拿到事故报告、复盘文档、工单或时间线，没有原始证据的目标。所有结论默认是「待验证」，除非附有原始证据。

| 检查点 | 什么算问题 |
| --- | --- |
| 时间线完整 | 最早入侵、发现、控制、恢复的时间是否都有，并注明来源和时区；潜伏期是怎么确定的 |
| **根因与触发分开** | 写的是根因，还是只写了触发点；为什么防护没挡住，为什么监控没发现（检测缺口）；按[根因面](facets.md)归类 |
| 影响范围的依据 | 「未发现数据外泄」依据的是什么日志，日志保留期是否覆盖整个潜伏期；日志缺失时结论应是「无法确定」 |
| **处置完整** | 泄露或可能泄露的凭据、令牌、密钥是否全部轮换；持久化手段（后门账号、计划任务、OAuth 授权、SSH 公钥）是否清除；同批主机和同类系统是否都修了 |
| 同类排查 | 同一机制在其它系统、仓库、环境里是否也存在（对照[历史漏洞模式](history.md)） |
| 改进项 | 每项是否有负责人、期限和验收方式；只写「加强意识」的不算 |
| 通报义务 | 适用法规和合同要求的通报时限是否满足；法律判断交给法务（见[30](dimensions.md#30-隐私数据治理与合规)「要求来源」） |
| 证据保全 | 原始日志、镜像、内存是否已保全并记录摘要，现在还能不能复核 |

## 链上合约地址

适用：只给了合约地址（或协议名）的目标。只做只读的链上查询和本地分叉模拟；不发送交易、不签名、不接触私钥。

| 检查点 | 什么算问题 |
| --- | --- |
| **源码与字节码一致** | 区块浏览器上有没有已验证的源码；编译器版本、优化设置、构造参数是否与链上字节码一致；没有验证源码时只能反编译，结论注明基于字节码 |
| **代理与实现** | 是否是代理合约（按 EIP-1967 等标准槽位读取）；当前的实现合约地址；实现合约自身是否已被初始化 |
| 初始化版本 | 可升级合约记录的已初始化版本号，是否与当前实现要求的一致；升级后新增的变量是否仍是零值 |
| **权限持有者** | 所有者、管理员、升级者、暂停者、各角色成员的实际地址；它们是外部账户、多签还是时间锁；多签门限与签名者；时间锁的延迟；按角色授予和撤销的事件还原全部成员，重点看部署者和开发者地址 |
| 待执行的变更 | 时间锁队列、多签待执行队列、治理提案里已排队但还没执行的操作，逐条解码调用数据 |
| 升级与参数历史 | 历史上的升级、参数变更、权限转移事件；最近有没有异常变更 |
| 当前参数 | 费用、上限、预言机地址、白名单等当前值是否合理，是否与文档一致 |
| 资产与授权 | 合约持有的资产；合约对外给出的代币授权；用户给合约的授权规模 |
| 依赖的合约 | 调用的预言机、路由、代币和其它协议的地址，以及它们自身的权限与升级状态 |
| 多链部署 | 同一协议在各条链上的地址、代码版本、参数与权限是否一致 |
| **跨链消息配置** | 跨链应用在消息层上的实际配置：每条路径的验证方数量与门限、是否沿用默认配置、对端地址是否正确；桥的限额与暂停权限 |
| 账户类型 | 相关地址是不是通过 EIP-7702 委托了代码的外部账户；合约钱包的模块与支付方配置 |
| 交易历史 | 异常调用、失败交易；疑似攻击的前置动作（小额试探、与新部署合约的交互） |

有源码时再按[4.38](specialties.md#438-智能合约与链上交互)、[4.41](specialties.md#441-defi-经济机制与预言机) 到 [4.43](specialties.md#443-钱包签名与链下组件)和对应语言表审查代码；验证零知识证明的合约再看[4.44](specialties.md#444-零知识证明与电路)；合约钱包与委托看[4.50](specialties.md#450-账户抽象与合约钱包)。

## 设计、规格与架构文档

## 办公文档与 PDF

适用：Word、Excel、PowerPoint、RTF、PDF 等文件本身是审查目标，例如对外发布的文件、产品生成的报表模板、收到的可疑文件。服务端解析这些文件的代码见[4.3](specialties.md#43-解码不受信任的外部数据)、[4.22](specialties.md#422-子进程动态执行与解码器副作用)。

| 检查点 | 什么算问题 |
| --- | --- |
| **宏与自动执行** | VBA 宏、Excel 4.0（XLM）宏；自动运行入口（`AutoOpen`、`Workbook_Open`）；调用外部命令、下载文件 |
| **外部引用** | 远程模板（关系文件里指向外部地址的模板）、外部 OLE 对象、DDE 字段、协议处理器链接（如 `ms-msdt:`） |
| 嵌入对象 | 内嵌的可执行文件、OLE 包、其它文档 |
| PDF 动作 | `/OpenAction`、`/AA`、`/JavaScript`、`/Launch`、`/EmbeddedFile`、`/URI`、XFA 表单 |
| **隐藏内容与元数据** | 作者、机器名、本地路径、修订记录、批注、隐藏的工作表和行列、被裁掉的图片原图；PDF 增量更新里保留的旧版本；「涂黑」只是盖了黑框，底下的文字还在 |
| PDF 签名 | 签名是否覆盖整个文件；签名之后追加的增量更新是否改变了显示内容 |

## WebAssembly 模块

适用：只拿到 `.wasm` 模块的目标，浏览器端和服务端插件都算。宿主如何隔离模块见[4.27](specialties.md#427-解释器编译器与虚拟机)、[4.32](specialties.md#432-跨语言边界与本地扩展)。

| 检查点 | 什么算问题 |
| --- | --- |
| 导入与导出 | 模块导入了哪些宿主函数（文件、网络、进程、WASI 能力），导出了什么；宿主给的能力是否超出需要 |
| 来源语言与编译器 | 自定义段 `producers`、名字段、调试信息；C 或 C++ 编译出的模块保留了原语言的内存错误 |
| **线性内存里的缺陷** | 模块内部没有栈保护、没有地址随机化、没有保护页；越界写能改到模块内的其它数据和间接调用表的索引。「隔离得住宿主」不代表模块内部数据安全 |
| 内嵌秘密 | 数据段里的密钥、地址、许可证校验逻辑；编译成 wasm 不等于别人看不到 |
| 资源上限 | 内存最大页数、表大小；宿主是否限制执行时间或燃料（见[20](dimensions.md#20-资源上界与背压)） |
| 完整性 | 加载前是否校验摘要或签名；从哪个地址加载 |

## 游戏客户端与反作弊

适用：游戏客户端、反作弊组件及其驱动，以及只能从客户端观察的联网游戏协议。在测试服或私服上做，不在正式服测试：会影响其他玩家，也违反服务条款。

| 检查点 | 什么算问题 |
| --- | --- |
| **客户端说了算** | 位置、伤害、货币、物品、冷却时间由客户端计算并上报，服务端直接采信 |
| 协议 | 消息没有完整性保护和序号；能重放、加速、乱序；服务端不校验频率和物理上限 |
| 内购与奖励 | 收据没在服务端向平台核验；奖励发放不幂等（见[4.39](specialties.md#439-支付账务与计费)） |
| **反作弊驱动** | 内核驱动暴露的控制接口不校验调用者；已签名的驱动被别人拿去当「自带漏洞驱动」关闭安全软件（2022 年勒索软件滥用 mhyprot2.sys）；卸载后是否残留 |
| 隐私与权限 | 反作弊收集的进程、文件、硬件信息的范围和外发去向（见[30](dimensions.md#30-隐私数据治理与合规)） |
| 反调试与混淆 | 只提高成本，不是安全边界；不能因此省掉服务端校验 |
| 模组与脚本 | 加载用户模组、脚本、地图时拿到的执行能力（见[4.27](specialties.md#427-解释器编译器与虚拟机)） |
