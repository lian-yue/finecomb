# A.13 Solidity 与 Vyper（EVM）

| 检查点 | 什么算问题 |
| --- | --- |
| **重入** | 外部调用（包括转账和代币回调，如 ERC777 的钩子、ERC721 的 `onERC721Received`、ERC1155 的接收回调）发生在状态更新之前；跨函数、跨合约重入；只读重入：回调期间别的合约读到尚未更新的视图函数（如价格）；没有按「检查—生效—交互」排序，也没有重入锁 |
| **委托调用** | `delegatecall` 在调用方的存储上下文里执行：目标地址可控时能改写任意槽位；代理与实现合约的存储布局冲突；透明代理的函数选择器冲突 |
| **未受保护的初始化** | 可升级合约的 `initialize` 没有防重入初始化的保护，或实现合约本身没有被初始化，别人可以抢先初始化、成为所有者，甚至让实现合约自毁（在未实施 EIP-6780 的链上） |
| **回调来源** | 闪电贷、交换、铸造回调（如 `uniswapV3SwapCallback`、`onFlashLoan`）是否校验调用方就是预期的池子或贷方，并确认这次回调来自本合约自己发起的调用；否则任何人都能直接调用回调，让合约按伪造的参数付款或记账 |
| **元交易发送者** | 支持 ERC-2771 的合约从调用数据末尾取真实发送者，只能对可信转发器这样做；合约同时提供用 `delegatecall` 调用自身的 `multicall` 时，攻击者能在每个子调用末尾拼上任意地址，冒充任何人 |
| 瞬时存储 | EIP-1153 的瞬时存储在整笔交易内有效，不只在当前调用内：同一交易里后续调用会读到遗留值，用它做锁或临时参数时退出前是否清理；`TSTORE` 只要 100 gas，`transfer`、`send` 的 2300 gas 已不能阻止对方改状态 |
| 幻影函数 | 对没实现某函数但有 fallback 的合约调用该函数不会回滚（如对 WETH 调用 `permit`）；随后的 `transferFrom` 会直接用掉用户早先给的授权 |
| 余额与内部记账 | 用 `balanceOf(address(this))` 或 `address(this).balance` 当账本；攻击者可以直接转入代币或强制发送 ETH（自毁、提前向预算出的地址转账）改变计算结果 |
| ETH 收付 | 缺少 `receive` 或 `fallback`，收不到退款；向用户推送 ETH 时对方回滚卡住整个流程；`payable` 函数里没用掉的 `msg.value` 留在合约里 |
| 账户判断 | 用 `tx.origin` 做权限判断；用 `extcodesize` 或 `code.length` 判断对方是不是外部账户（构造函数执行期间为 0；EIP-7702 之后外部账户也能带代码） |
| 低级调用 | `call`、`delegatecall`、`send` 的返回值没检查；调用没有代码的地址也返回成功；对方返回超大数据，复制时耗尽 gas（返回数据炸弹） |
| 整数 | Solidity 0.8 之前默认不检查溢出；`unchecked` 块里的运算；类型转换截断（如 `uint256` 转 `uint128`）；有符号与无符号互转 |
| **精度与取整** | 先除后乘丢失精度；取整方向对谁有利；不同代币精度之间的换算 |
| 哈希碰撞 | 对多个动态类型用 `abi.encodePacked` 拼接后取哈希会碰撞（`("a","bc")` 与 `("ab","c")` 结果相同） |
| 签名 | `ecrecover` 对无效签名返回零地址；签名可延展（高 s 值）；签名里缺少随机数、链标识、截止时间；应使用经过审计的签名库 |
| `msg.value` 复用 | 在循环或批量调用（multicall）里多次使用同一个 `msg.value` |
| 随机数 | 用区块时间戳、区块哈希、`prevrandao` 当随机源，出块者或同一区块里的合约可以预测或影响结果 |
| 时间与区块 | 依赖 `block.timestamp` 的精确值；二层网络上 `block.number`、`block.timestamp` 的语义与主网不同 |
| **拒绝服务** | 无界循环；逐个转账给一组地址时，一个接收方回滚导致全部失败（应改为用户自取）；流程依赖某个外部调用成功才能继续 |
| gas 转发 | 外部调用最多转发剩余 gas 的 63/64：调用者可以故意少给 gas，让内层调用因 gas 不足失败而外层继续执行，不检查返回值或用 `try/catch` 吞掉失败的地方会把这当成正常分支；固定 2300 gas 的 `transfer`、`send` 在操作码调价（如 EIP-1884 提高 `SLOAD` 成本）后可能不够用，接收方是合约钱包时会失败 |
| 自毁与代码替换 | EIP-6780 之后，`selfdestruct` 只在创建合约的同一笔交易里执行时才删除代码和存储，其它情况只转走余额，依赖旧语义的逻辑失效；在同一笔交易里创建并销毁的合约，以及未实施 EIP-6780 的链上，`CREATE2` 配合销毁仍能在同一地址重新部署不同代码 |
| 可见性与继承 | 函数可见性写错；多重继承的线性化顺序与重写；状态变量遮蔽 |
| 存储与数据位置 | `storage` 与 `memory` 引用混用，改的不是预期对象；`delete` 映射或结构体后残留数据；旧版本里未初始化的存储指针 |
| 代币接口 | 假设所有 ERC20 都返回 `bool`（部分主流代币不返回）；`approve` 修改额度时的竞争；没有用安全封装 |
| `permit` 与离线授权 | 许可签名可被抢先提交，导致原交易回滚（应容忍已生效的许可）；被钓鱼签下的许可 |
| 结构化签名编码 | EIP-712 的类型字符串是否与结构体字段一致（名称、顺序，嵌套的结构体类型按名称排序附在后面）；动态类型与数组的编码；域分隔符是否包含链标识和合约地址，链分叉后是否按当前链标识重新计算 |
| Permit2 与签名授权 | 用户对 Permit2 的授权让一个签名就能转走所有已授权的代币；合约替用户提交 Permit2 签名时，签名里的接收方、金额、期限、随机数是否都校验，附加数据（witness）是否绑定了本次操作的内容 |
| 事件 | 关键状态变化缺少事件；事件参数与实际状态不一致 |
| **编译器** | `pragma` 没有固定版本；使用有已知缺陷的编译器版本（如 Vyper 0.2.15、0.2.16、0.3.0 的重入锁缺陷曾导致 2023 年 Curve 多个池子被盗）；优化器相关缺陷；编译目标的 EVM 版本产生的操作码（如 `PUSH0`）目标链不支持 |
| 内联汇编 | 汇编绕过了类型与边界检查；内存指针与空闲内存指针的管理 |
| 常量与不可变量 | 构造参数、不可变量写错后无法修改；写死的地址在另一条链上指向别的合约 |
