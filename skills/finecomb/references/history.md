# Historical vulnerability patterns

This file turns high-severity, widely exploited vulnerabilities from the past into general mechanisms. Use it during a review to "go over the code once more with history's lessons in mind" and avoid repeating old mistakes.

How to use it:

- After [establishing the factual baseline](baseline.md), pick the groups that match the mechanisms the target uses and compare row by row. The "Where it lands" column points to the dimension or specialty that holds the detailed criteria.
- Each row is a generalized **mechanism**. The historical cases only help you recognize it; they are not a complete list. The same mechanism still holds in another language, framework or product.
- Matching a pattern does not mean a vulnerability exists. You still need to check reachable paths and blocking points per [Threat model and attack chains](baseline.md#threat-model-and-attack-chains), and record the result with an [evidence level](report.md#part-v-evidence-levels-and-report-format).
- Many historical vulnerabilities come from **combinations**: each step alone looks like "just a small issue". When you find one pattern, look in the same group and nearby groups for the other half that can be chained with it.
- Incomplete fixes, fixes that are later bypassed, and regressions are common (see the last row of [14 Supply chain, build and release](#14-supply-chain-build-and-release)).

## 5 Parsing and normalization differentials

| --- | --- | --- | --- |

| **Authentication exemption rules matched as strings** | TeamCity (CVE-2023-42793, paths ending in a specific suffix skipped authentication) | Whether authentication exemptions match the raw path by prefix, suffix or regular expression; whether an attacker can build a path that hits both an exemption and a protected handler | [28](dimensions.md#28-authorization-and-access-control) ("Matching of authentication exemptions"), [4.14](specialties.md#414-server-request-handling-and-middleware) |
| **Backend trust after a proxy rewrites headers** | F5 BIG-IP (CVE-2022-1388, the `Connection` header made the proxy drop the authentication header, and the backend trusted requests from the local machine by default); Next.js (CVE-2025-29927, an external request carrying the internal subrequest header skipped the whole middleware) | Hop-by-hop headers, and headers the proxy deletes or rewrites; backend assumptions such as "requests from the local machine are trusted" or "a request with a certain header is trusted" | [4.14](specialties.md#414-server-request-handling-and-middleware) ("Proxy trust", "Header handling"), [34](dimensions.md#34-runtime-environment-and-deployment-contract) |
| **Validation and use rely on different parsers** | Go `net.ParseIP` leading zeros (CVE-2021-29923); npm netmask (CVE-2021-28918); SSRF bypasses caused by differences between URL parsers | Whether the parser used to validate an address, URL or IP is the same one used to send the request or do the matching | [4.21](specialties.md#421-outbound-requests-and-server-side-request-forgery), [4.29](specialties.md#429-rule-and-policy-matching) |
| **A single-value field receives an array or repeated parameters** | GitLab (CVE-2023-7028, passing an array of emails in a password reset request sent the reset link to an unverified second address) | Whether a field expected to hold one value can receive an array, repeated parameters or repeated JSON keys; validation looks only at the first one, while execution uses all of them or the last one | [27](dimensions.md#27-security-and-trust-boundaries) ("Parser differentials"), [4.5](specialties.md#45-authentication-sessions-and-tokens) ("Account recovery") |
| **Case folding and Unicode normalization collisions** | GitHub password reset in 2019: characters such as the Turkish dotless i became identical to someone else's email after case conversion | What case conversion and normalization happen before comparing accounts, emails and usernames; whether different raw values can map to the same identity | [14](dimensions.md#14-boundaries-numbers-and-text), [4.5](specialties.md#45-authentication-sessions-and-tokens) |
| **What is shown differs from what is used** | WinRAR (CVE-2023-38831, a space at the end of a file name made the user open a different file); Trojan Source (CVE-2021-42574, bidirectional control characters in source code) | Whether the names and content shown to people are the same as what the program actually uses | [27](dimensions.md#27-security-and-trust-boundaries) ("What is shown differs from what is used") |
| **Writing out and reading back are not symmetric** | Git (CVE-2025-48384, when writing config, a value ending in a carriage return was not quoted; on reading back the carriage return was stripped, so the submodule path pointed elsewhere, and a hook was written through a symbolic link) | Whether a value that this component writes out and reads back is still the original value; whether the escaping and whitespace trimming rules match on both sides | [24](dimensions.md#24-encoding-and-persistent-formats) ("Round trip and canonical form") |
| The signed object differs from the object used | SAML comment truncation (CVE-2017-11427); XML signature wrapping; ruby-saml (CVE-2024-45409, XPath picked the wrong signature node; CVE-2025-25291, CVE-2025-25292, REXML and Nokogiri parsed different trees) | Whether the node and canonicalized result that signature verification covers are the same as the node the business logic reads; whether both places use the same parser | [4.24](specialties.md#424-webhooks-and-external-events) ("What is verified"), [4.46](specialties.md#446-federated-identity-and-single-sign-on) ("SAML assertions", "Consistent XML parsing") |
| **The signature does not cover the bytes actually used** | Android "Master Key" (CVE-2013-4787, duplicate ZIP entry names: signature verification read one, installation used the other); Janus (CVE-2017-13156, v1 signatures do not cover the bytes at the start of an APK, so a DEX could be prepended); Authenticode (CVE-2013-3900, data can be appended to the signature area; the 2023 3CX attack used it to hide a payload in a Microsoft-signed DLL) | Whether the range that signature verification covers is exactly the range the loader or unpacker actually reads | [36](dimensions.md#36-supply-chain-and-artifact-integrity) ("What a signature covers"), [4.35](specialties.md#435-client-apps-extensions-and-auto-update) ("Auto-update") |
| Request smuggling | CL.TE and TE.CL smuggling across many proxy and backend combinations | Whether the two HTTP implementations in front and behind agree on length and chunking | [4.14](specialties.md#414-server-request-handling-and-middleware) |
| Smuggling in email and other non-HTTP protocols | SMTP smuggling (Postfix CVE-2023-51764, sendmail CVE-2023-51765, Exim CVE-2023-51766: two servers in a row disagreed on whether `<LF>.<CR><LF>` ends the data, which let an email with a forged sender slip through) | In text protocols you implement or forward, whether the terminator, line breaks and lengths are understood the same way as upstream and downstream | [4.2](specialties.md#42-protocols-and-frame-parsing) ("Coexisting with another parser"), [4.40](specialties.md#440-notifications-and-outbound-messages) |
| Spliced into an internal line-based protocol | Zimbra (CVE-2022-27924, line breaks in external input entered memcache commands and poisoned the cached authentication routing, which sent users' mail connections to the attacker and captured their passwords) | Whether line breaks are rejected before external values are spliced into memcache, Redis, SMTP or IMAP commands | [4.17](specialties.md#417-templates-and-text-output) ("Line breaks and encoding"), [4.6](specialties.md#46-caching-and-storage) |

## 6 Authentication, sessions and identity

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |

| Default passwords and hardcoded credentials | Unitronics PLC (CVE-2023-6448); the Mirai botnet | Factory default passwords; credentials hardcoded in code or firmware | [27](dimensions.md#27-security-and-trust-boundaries) ("Hardening"), [4.4](specialties.md#44-cryptography-and-credentials) |
| **A missing value or a failed lookup falls back to a privileged default** | OMI "OMIGOD" (CVE-2021-38647, a request without an Authorization header ran as root); polkit (CVE-2021-3560, after failing to get the caller's uid, it treated the uid as 0); macOS Gatekeeper (CVE-2021-30657, a script app missing Info.plist was misclassified and skipped notarization and signature checks; exploited in the wild) | The initial value of identity, tenant and permission objects; which branch runs when getting the identity fails, a field is missing or metadata is missing | [28](dimensions.md#28-authorization-and-access-control) ("Defaults when identity is missing"), [29](dimensions.md#29-fail-safe-behavior-and-dangerous-operations) ("Failure direction") |

| **Coerced authentication, then relay** | PetitPotam (CVE-2021-36942, tricked a domain controller into NTLM authentication to the attacker, then relayed it to the AD CS web enrollment interface to request a certificate) | Whether services that accept challenge-response authentication require signing or channel binding | [4.46](specialties.md#446-federated-identity-and-single-sign-on) ("Relay of challenge-response authentication") |
| **Issued identity taken from a changeable attribute or a name fallback** | Certifried (CVE-2022-26923, a machine account changed its `dNSHostName` and then obtained a certificate bearing a domain controller's name); noPac (CVE-2021-42278, CVE-2021-42287, a machine account was renamed to a domain controller's name without the `$`; when the KDC could not find it, the KDC appended `$` and issued a ticket for the domain controller); Bronze Bit (CVE-2020-17049, anyone holding the service key could tamper with the forwardable flag in a ticket) | Where the name comes from when issuing credentials, and whether the requester can change it; whether a failed lookup falls back to a variant; whether trusted fields are protected by a signature | [4.46](specialties.md#446-federated-identity-and-single-sign-on) ("Identity source when issuing credentials"), [4.4](specialties.md#44-cryptography-and-credentials) ("Binding and context") |
| OAuth redirect URIs loosened | Keycloak (CVE-2023-6927, wildcard redirect URIs combined with the `form_post.jwt` response mode leaked authorization codes); Expo AuthSession proxy (CVE-2023-28131, accounts that used social login through the proxy could be taken over) | Whether redirect URIs are matched exactly; whether an intermediate proxy can pass the authorization result to someone else | [4.46](specialties.md#446-federated-identity-and-single-sign-on) ("Redirect URIs") |

| Email parsing differentials | PortSwigger 2024 "Splitting the email atom": encoded words, quotes and comments made addresses that seemed to end in `@company-domain` get delivered elsewhere, bypassing authorization by domain | When authorizing by email domain, whether validation and delivery derive the same domain from the same address | [4.5](specialties.md#45-authentication-sessions-and-tokens) ("Identity granted by email domain"), [27](dimensions.md#27-security-and-trust-boundaries) ("Parser differentials") |

## 9 Resource exhaustion and protocol-level denial of service

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |

## 19 Blockchain protocols and zero-knowledge proofs

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **Values assigned in a circuit but not constrained** | Zcash Orchard (CVE-2026-54496, disclosed in 2026: the base point of a scalar multiplication was written with `assign_advice` but had no copy constraint, so a malicious prover could swap the base point and compute any number of valid nullifiers for the same note, forging unlimited ZEC; it went unnoticed for four years); Tornado Cash (2019, the MiMC circuit used `=` instead of `<==`, so a Merkle root could be forged to withdraw deposits) | Whether every witness value is bound by constraints to its real source; whether tests use only honest provers | [4.44](specialties.md#444-zero-knowledge-proofs-and-circuits) ("Under-constrained circuits", "Malicious-prover tests"), [Zero-knowledge circuits](lang-zk.md), [8](dimensions.md#8-functional-correctness-and-fitness-for-requirements) ("Completeness of verification") |
| **Missing items in the non-interactive challenge** | Frozen Heart (2022, the Fiat–Shamir challenges in several PlonK, Bulletproofs and Girault proof implementations did not include all public inputs, so proofs could be forged) | Which items the hash for the challenge value includes | [4.44](specialties.md#444-zero-knowledge-proofs-and-circuits) ("Challenges and transcripts"), [4.4](specialties.md#44-cryptography-and-credentials) ("Custom schemes and proof structure") |
| **Flaws in parameter generation** | Zcash (CVE-2019-7167, extra elements in the parameters of the original scheme let a cheating prover turn a proof of one statement into a proof of another, allowing unlimited forgery) | How trusted setup parameters are generated and verified, and which version they belong to | [4.44](specialties.md#444-zero-knowledge-proofs-and-circuits) ("Trusted setup and parameters") |
| **Curve subgroups give one secret several valid identifiers** | Monero and other CryptoNote coins (2017, key images were not checked to lie in the prime-order subgroup; the cofactor of 8 let the same funds produce several valid key images, allowing unlimited double spending) | Subgroup checks on curve points; whether identifiers that "can be used only once" are unique | [4.4](specialties.md#44-cryptography-and-credentials) ("Completeness of verification", "Uniqueness and single use"), [4.44](specialties.md#444-zero-knowledge-proofs-and-circuits) ("Deriving unique identifiers") |
| **An optimized path skipped the double-spend check** | Bitcoin (CVE-2018-17144, for performance, block validation skipped the check for duplicate inputs within a transaction, which could both crash nodes and allow double spending) | Whether the fast path leaves out checks that the slow path does | [31](dimensions.md#31-performance-memory-and-latency) ("Optimized paths that skip validation"), [4.45](specialties.md#445-blockchain-nodes-consensus-and-protocol-implementations) |
| **Adding amounts overflows and creates coins from nothing** | Bitcoin (CVE-2010-5139, adding two huge outputs overflowed into a negative number, bypassed validation, and produced about 184 billion BTC) | Range and overflow checks before amounts are summed and compared | [14](dimensions.md#14-boundaries-numbers-and-text), [9](dimensions.md#9-business-logic-and-flow-integrity) ("Conservation of totals"), [4.45](specialties.md#445-blockchain-nodes-consensus-and-protocol-implementations) |
| **Ambiguous keys in the verification cache** | Liquid Network (2026, the cache key for range proof verification results was built by directly concatenating variable-length fields, so another transaction hit the same cache entry and skipped verification, minting about 4000 L-BTC from nothing; five days after the fix commit was public, it was still not deployed) | Whether the fields of a cache key have length prefixes; the window between a fix going public and being deployed | [4.6](specialties.md#46-caching-and-storage) ("Cache keys and isolation"), [4.45](specialties.md#445-blockchain-nodes-consensus-and-protocol-implementations) ("Verification result caches") |
