# 4.74 Notebooks and interactive computing

Applies to: Jupyter-style notebook servers and hosted notebook workspaces, data science platforms, REPL servers, interactive and debug consoles, and their extensions. Apply your own knowledge of the specific notebook server, kernel protocol and framework to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Server and kernel authentication** | The server or kernel ports listen beyond loopback; they need no token or password, or the token is guessable, logged or put in URLs; any web origin can call them, including through DNS rebinding (see [4.35](4.35-client-apps-extensions-and-auto-update.md) ("Local control plane")) |
| **Code execution by design** | Anyone who reaches a kernel, terminal or console runs code as the server; nothing limits who can reach it; debug consoles stay on in production; the server runs as root or with cloud credentials and network access beyond what its users need (see [facets](../facets/validation-and-trust.md) "Authority beyond the job") |
| **Shared kernels and workspaces** | Several users share one kernel, server process, file system or service account, so one can read another's variables, files, credentials or sessions; per-user isolation depends on names, paths or proxy routes that users can influence (see [facets](../facets/state-timing-and-paths.md) "Shared state across trust levels") |
| **Rendering outputs and untrusted notebooks** | HTML, script, SVG or Markdown outputs run in the server's origin and can call its API; opening someone else's notebook runs its outputs or code without a trust decision; other apps that preview notebook files run their scripts (see [4.17](4.17-templates-and-text-output.md) ("User content")) |
| File access through the server | File and download APIs reach paths outside the workspace root or follow links; uploaded files are served inline from the server's origin (see [4.8](4.8-file-systems-and-paths.md) ("Upload publishing and download")) |
| Secrets and data saved in notebooks | Credentials, tokens and personal data typed in cells or printed in outputs are saved into the notebook file, checkpoints, exports or version control |
| Extensions and their permissions | Extensions run with the full rights of the server or the page; they come from unreviewed sources; they add HTTP handlers that skip authentication |
