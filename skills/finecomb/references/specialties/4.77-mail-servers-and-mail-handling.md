# 4.77 Mail servers and mail handling

Applies to: mail transfer agents (MTAs), mail submission, IMAP and POP servers, webmail, and code that parses, filters, forwards or acts on mail. For the DNS records of a domain, see [Targets that are not source code: Domains, DNS and mail configuration](../targets/domains-dns-and-mail-configuration.md). Apply your own knowledge of the specific mail servers, libraries and standards to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Relay and submission authentication** | The server relays mail for clients it has not authenticated, or trusts them by IP range; authenticated users can send as any sender address; passwords are accepted over unencrypted connections; commands received before a STARTTLS handshake are still processed after it |
| **SMTP parsing differences between hops** | Servers on the path disagree about end-of-data, line endings, bare CR or LF, or command boundaries, so the next hop reads one message as two and the hidden one passes as authenticated mail (see [4.2](4.2-protocols-and-frame-parsing.md) ("Coexisting with another parser")) |
| **Sender authentication results** | SPF, DKIM and DMARC are checked on a different address or header than the one shown to the user; a missing or failed result is treated as a pass; result headers added by the sender or earlier hops are trusted; forwarding and mailing lists pass on alignment they should break (see [facets](../facets.md) "What is shown versus what is used") |
| MIME, headers and encodings | The filter and the mail client parse MIME structure, folded headers, encoded words, character sets, duplicate headers or attachment names differently; nesting, part counts and decoded size have no limits (see [4.3](4.3-decoding-untrusted-external-data.md) ("Multiple formats and duplicate fields")) |
| **Webmail rendering** | Untrusted HTML and CSS in mail are cleaned in a way the browser parses differently; remote content loads without consent and reveals reads and addresses; attachments are served inline from the webmail origin (see [4.17](4.17-templates-and-text-output.md) ("User content")) |
| Mailbox access and delegation | Access checks do not cover every mailbox named in a command, shared folders, delegates, access lists or admin impersonation; older protocols or app passwords skip multi-factor authentication (see [28](../dimensions/28-authorization-and-access-control.md) ("Consistency across entry points")) |
| Automatic processing of incoming mail | Rules, forwarding, auto-replies, previews, link scanners, calendar invites and attachment handling act on mail from anyone; they fetch URLs or open attachments without the user (see [4.21](4.21-outbound-requests-and-server-side-request-forgery.md) ("Who decides the destination")); systems that act on mail, such as reply-by-email or tickets by mail, identify the user by the From address alone |
| Bounces, loops and limits | Bounces and auto-replies go to forged senders; forwarding and auto-replies loop; message size, recipients, connections and queue growth have no limits (see [20](../dimensions/20-resource-bounds-and-backpressure.md) ("Amplification factor")) |
