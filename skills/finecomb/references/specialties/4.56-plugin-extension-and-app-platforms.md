# 4.56 Plugin, extension and app platforms

Applies to: the host side of extension systems, such as plugin and extension loading in CMSs, IDEs and other applications, app marketplaces, third-party OAuth apps built on your platform, and integration directories. Apply your own knowledge of the specific host, its plugin API and its marketplace to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Privileges and isolation** | Plugins run inside the host with its full privileges, database access and secrets; plugins share global state, storage, settings, hooks and UI with each other and with the host, so one weak or malicious plugin can read other plugins' data or take over the host (see [facets](../facets/state-timing-and-paths.md) "Shared state across trust levels") |
| **Permissions enforced at run time** | The permission or capability model is only declared in a manifest or shown at install, and is not checked when the plugin calls host APIs; some APIs or older API versions skip the check; an update widens permissions without new consent |
| Sandbox boundary | Where plugins run in a sandbox (a frame, a worker, a script engine or a separate process), the host trusts messages from the plugin, or the sandbox exposes host objects (see [4.27](4.27-interpreters-compilers-and-virtual-machines.md) ("Host boundary")) |
| Manifest and metadata | Plugin-supplied IDs, names, versions, routes, hooks, file paths and publisher details are trusted without checks; one plugin can claim another plugin's ID, overwrite its files, or register over core routes and hooks |
| **Review, signing and updates** | Plugins and their updates are not signed, or the signature is not tied to the publisher; review covers only the first version, while later updates or code loaded at run time skip it; the update channel can be downgraded or redirected (see [4.35](4.35-client-apps-extensions-and-auto-update.md) ("Auto-update")) |
| Marketplace names and ownership | Plugin names, publisher accounts and namespaces can be transferred, sold, claimed after they lapse or reused after deletion, and existing installs then update from the new owner without notice; look-alike names are not caught (see [facets](../facets/resources-externals-and-observability.md) "Lifetime of referenced names") |
| Uninstall and disable | After uninstall or disable, the plugin's tokens, API keys, webhooks, scheduled jobs, hooks, files and stored data remain active or readable; a disabled plugin still loads code or receives events |
| **Consent and scopes for third-party apps** | Consent screens do not show the real scopes, publisher or redirect destination; requested scopes are broader than the app's job; an app gains new scopes, or acts for users who never consented, without fresh consent; app tokens outlive the app's removal (see [4.46](4.46-federated-identity-and-single-sign-on.md)) |
