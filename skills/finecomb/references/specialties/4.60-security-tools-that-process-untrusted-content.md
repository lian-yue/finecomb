# 4.60 Security tools that process untrusted content

Applies to: antivirus and EDR engines, code, dependency, container and web scanners, WAFs, intrusion detection systems, malware sandboxes, SIEM and log parsers, and email security gateways. Apply your own knowledge of the specific engine, its parsers and its deployment to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Privileged parsers** | Parsers for files, archives, packets, logs and mail run as root, as SYSTEM or in the kernel on content an attacker chooses, without a sandbox (see [facets](../facets/validation-and-trust.md) "Privileged code handling low-privilege input") |
| **Running or fetching what is scanned** | The tool runs build scripts, package hooks, plugins, macros or configuration found in the scanned target, loads programs from the scanned directory, or follows links and URLs in scanned content (see [4.22](4.22-subprocesses-dynamic-execution-and-decoder-side-effects.md) and [4.21](4.21-outbound-requests-and-server-side-request-forgery.md)) |
| Self-protection | Local users or malware can stop, unload, reconfigure or blind the agent; quarantine, restore and delete actions can be pointed at other files through links (see [4.47](4.47-local-privileged-components-and-local-privilege-escalation.md) ("File operations in low-privilege writable locations")) |
| **Signature and update channel** | Signature, rule and engine updates are not signed, or come over a channel that can be tampered with; a broken update silently turns protection off, or crashes hosts at scale (see [4.35](4.35-client-apps-extensions-and-auto-update.md) ("Auto-update")) |
| Exclusions and allowlists | Excluded paths, processes, hashes, hosts or signers are ones an attacker can write to, start, match or reuse; exclusions match only by name or prefix (see [4.29](4.29-rule-and-policy-matching.md) ("Normalize before matching")) |
| Findings shown in consoles | File names, log lines, headers, URLs and strings from scanned content are shown in dashboards, reports, tickets or terminals without escaping, so the attacker's content attacks the analyst; findings copy scanned secrets into places with weaker protection (see [4.17](4.17-templates-and-text-output.md)) |
| **Parser differences with the real consumer** | The tool decodes, unpacks, normalizes or reassembles content differently from the application, browser, mail client or operating system that will use it, so malicious content passes the check and is still used (see [27](../dimensions/27-security-and-trust-boundaries.md) ("Parser differentials")) |
| Limits and failures | When the engine times out, crashes or reaches a size, depth or nesting limit, the content passes unchecked and nobody is told; one crafted input stops checking for later content (see [29](../dimensions/29-fail-safe-behavior-and-dangerous-operations.md) ("Failure direction")) |
