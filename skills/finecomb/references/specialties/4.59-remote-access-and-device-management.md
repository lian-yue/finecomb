# 4.59 Remote access and device management

Applies to: remote desktop and remote support tools, remote monitoring and management (RMM), mobile and endpoint device management (MDM), and fleet agents that take commands from a central server. Apply your own knowledge of the specific product, its agent and its enrollment protocol to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Setup and admin endpoints** | Setup wizards, first-admin creation, recovery and debug endpoints stay reachable after setup, or skip authentication on some paths; the management console is exposed to the internet (see [28](../dimensions/28-authorization-and-access-control.md) ("Setup and installation entry points")) |
| **Trust between agent and server** | The agent does not verify the server's identity, or accepts commands and scripts that are not signed by, or bound to, its own server; the server trusts what an agent reports about itself or about other devices (see [facets](../facets.md) "Authenticity of identities and addresses") |
| **Remote commands** | Running commands, deploying scripts and transferring files are features, but who may use them, on which devices and with what approval is not limited or logged; one console account, technician or customer of a service provider can run code on every managed device, including other customers' devices |
| Enrollment and device identity | Enrollment tokens and profiles are long-lived, reusable or guessable; a device can enroll as another device or replace it; device certificates and IDs are not bound to the hardware and can be copied |
| Session consent and recording | Remote sessions start without the user's consent or a visible notice where policy requires them; unattended access is on by default; session recordings and logs can be edited or deleted by the operator, or keep passwords typed during the session |
| **Agent updates** | Agent updates and add-ons are not signed or not verified; the update source can be changed through the console or the network; older versions are accepted (see [4.35](4.35-client-apps-extensions-and-auto-update.md) ("Auto-update")) |
| Credentials on managed devices | Agents keep server tokens, saved passwords, Wi-Fi and VPN profiles or local admin credentials where local users or malware can read them; the agent's local service accepts commands from any local process (see [4.47](4.47-local-privileged-components-and-local-privilege-escalation.md)) |
