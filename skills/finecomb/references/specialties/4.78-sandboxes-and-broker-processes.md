# 4.78 Sandboxes and broker processes

Applies to: software split by privilege, such as renderer or content processes with a privileged broker, privilege-separated daemons, plugin and extension hosts, and sandboxed helpers for parsing or media. Apply your own knowledge of the specific sandbox mechanisms and inter-process communication (IPC) systems on each platform to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Messages from the sandbox are untrusted** | The broker trusts IDs, sizes, paths, URLs or object references from the sandboxed side; checks run in the sandboxed process or its client library instead of in the broker; the broker trusts the identity (origin, site, plugin) a message claims instead of the one bound to its channel (see [facets](../facets/validation-and-trust.md) "Privileged code handling low-privilege input") |
| **Handles and capabilities across the boundary** | Handles, descriptors and capabilities are passed with more rights than the request needs, or the sandbox can name any object (see [4.30](4.30-os-interfaces-system-calls-and-descriptors.md) ("Handles and capabilities passed across boundaries")) |
| **Acting on the sandbox's behalf** | For file access, network, clipboard, printing, downloads, opening URLs or starting apps, the broker checks what any sandbox may do rather than what this sandboxed instance may do; it resolves paths and links with its own privileges (see [28](../dimensions/28-authorization-and-access-control.md) ("Delegation and acting on behalf")) |
| **Sandbox policy actually applied** | The sandbox is weaker or missing on some platforms, OS versions, configurations or fallback modes; it is applied after untrusted input is processed; a flag, environment variable or error turns it off silently; descriptors, environment and access opened before lockdown remain (see [29](../dimensions/29-fail-safe-behavior-and-dangerous-operations.md) ("Failure direction")) |
| Shared memory | Data in shared memory is checked and then read again while the other side can change it (see [4.30](4.30-os-interfaces-system-calls-and-descriptors.md) ("Reading untrusted memory twice")); lengths and layout in shared memory are trusted |
| Size of the interface | The sandbox can reach IPC methods, services and system calls it does not need, including debug and test interfaces left in release builds; objects named in messages are freed or replaced while a request still uses them (see [facets](../facets/memory-lengths-and-parsing.md) "Lifetime and ownership") |
| Crash and restart | A crashed sandboxed process is restarted without limit, which allows repeated attempts; grants, handles or pending requests of the old process pass to the new one; the broker acts on half-finished requests from a dead process |
