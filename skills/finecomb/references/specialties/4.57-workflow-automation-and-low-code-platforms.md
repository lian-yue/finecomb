# 4.57 Workflow automation and low-code platforms

Applies to: workflow engines, integration and automation platforms, low-code and no-code builders, and rule or expression engines that users configure. Apply your own knowledge of the specific platform, its nodes and its expression language to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Who can run code** | Expressions, code nodes, scripts and formula fields run code by design, but any user who can edit a workflow can add them; their sandbox is weak or shares the platform's process, files and secrets (see [4.27](4.27-interpreters-compilers-and-virtual-machines.md) ("Host boundary")) |
| **Stored credentials** | Credentials saved for integrations can be used, exported or read back by users other than their owner; a workflow can send a credential to any destination; credentials appear in run history, errors or step output |
| **Run-as identity** | It is unclear which identity a workflow runs as; workflows run as the platform's service account, or keep running as their creator after the creator loses access; a user who can edit or trigger a workflow gets the rights of the identity it runs as (see [28](../dimensions/28-authorization-and-access-control.md) ("Delegation and acting on behalf")) |
| **External triggers** | Webhooks, forms, email and chat triggers accept input from anyone without authentication or signature checks, and that input reaches internal steps such as queries, HTTP calls or code nodes (see [4.24](4.24-webhooks-and-external-events.md)) |
| Imported templates and shared workflows | Workflows, templates and community nodes imported from others run code, use stored credentials or call external addresses without the importer seeing it; community nodes install with the platform's full privileges |
| Data between steps | Output of one step (from an external API, an email, a form or an LLM) is put into the expression, query, command or request of a later step without escaping, and loses the mark that it is untrusted (see [facets](../facets/representation-and-transformation.md) "Data turning into instructions") |
| Outbound requests | HTTP nodes and integrations can reach internal networks, metadata endpoints and the platform's own admin interfaces (see [4.21](4.21-outbound-requests-and-server-side-request-forgery.md) ("Internal network and metadata")) |
| Loops and fan-out | Loops, sub-workflows, retries and fan-out have no limits; a workflow triggers itself; one trigger starts unlimited runs (see [20](../dimensions/20-resource-bounds-and-backpressure.md)) |
