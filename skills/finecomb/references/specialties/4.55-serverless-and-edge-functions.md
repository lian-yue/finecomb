# 4.55 Serverless and edge functions

Applies to: functions and handlers that a platform runs on demand (cloud functions, edge workers, serverless containers), and the event sources, roles, routes and configuration around them. Apply your own knowledge of the specific platform to each row.

| Checkpoint | What counts as a problem |
| --- | --- |
| **Event sources are input** | Events from storage, queues, streams, schedulers, webhooks and HTTP gateways are trusted beyond whoever can produce them; fields such as object keys, headers and identity claims are used without checks, on the assumption that the gateway or trigger already checked them |
| **One role per function** | Functions share one broad role or service account, or a function's role holds more than that function needs (see [facets](../facets/validation-and-trust.md) "Authority beyond the job") |
| **State reused by warm instances** | Globals, caches, temporary directories and connections kept by a warm instance carry one caller's data or identity into another caller's request (see [facets](../facets/state-timing-and-paths.md) "Shared state across trust levels") |
| Retries and duplicates | Platform retries and at-least-once delivery repeat side effects such as payments, messages or writes; handlers are not idempotent (see [4.10](4.10-message-queues-and-async-jobs.md)) |
| Timeouts and partial work | A function stopped by its time or memory limit leaves half-done state; long work is not split or checkpointed |
| Secrets and configuration | Secrets are baked into deployments, plain environment variables or logs instead of being read from a secret store at run time; stages share secrets |
| Exposure and routing | It is unclear which functions are reachable from the internet, through which routes and with what authentication; edge rules and rewrites expose internal functions or skip authentication |
| Cost and runaway triggers | No concurrency limits; a function writes to the source that triggers it and loops; paid-resource spending has no cap (see [21](../dimensions/21-scalability-and-capacity.md)) |
