# 18 Smart contracts and on-chain

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **Reentrancy** | The DAO (2016); Curve 2023 (a compiler bug in the reentrancy lock of Vyper 0.2.15, 0.2.16, 0.3.0); many price-reading errors caused by read-only reentrancy; Penpie (2024, a fake market created through permissionless registration reentered while claiming rewards); GMX (2025, the v1 contract's average short price was manipulated through reentrancy) | Whether state is updated before external calls; whether the reentrancy lock really works; whether the view others read during a callback is correct | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md), [Solidity and Vyper](../lang-solidity.md) |
| **Unprotected initialization and library contracts** | Parity multisig (July 2017, anyone could call the initialization function of the wallet library; in November of the same year, the library contract was initialized and then self-destructed, freezing large amounts of assets) | Whether anyone can call or destroy initialization functions, implementation contracts and library contracts | [Solidity and Vyper](../lang-solidity.md) ("Unprotected initialization"), [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) |
| **Price manipulation and flash loans** | bZx (2020); Mango Markets (2022, pushed up the price in a thin market and then borrowed far too much); Beanstalk (2022, borrowed voting power with a flash loan to pass a malicious proposal); Tectonic (2026, looped deposits and borrows to inflate the collateral share of its own governance token, then pushed up that token's price and borrowed the assets away; the chain was later rolled back) | Whether prices and voting power can be borrowed or manipulated within one transaction | [4.41](../specialties/4.41-defi-economics-and-oracles.md) |
| **Cross-chain message verification** | Nomad (2022, an upgrade initialized the trusted root to all zeros, so every message was treated as proven); Wormhole (2022, a forged sysvar account made signature verification look as if it had passed); Poly Network (2021, a cross-chain message called a privileged contract and replaced the keeper public keys) | Message proofs, default values, system accounts and callable targets | [4.42](../specialties/4.42-cross-chain-bridges-and-messaging.md), [Solana](../lang-solana.md) |
| **Validator threshold keys concentrated** | Ronin (2022, 5 of the 9 validator keys were controlled by the attacker) | The actual distribution and isolation of threshold keys | [4.42](../specialties/4.42-cross-chain-bridges-and-messaging.md) ("Validators and thresholds") |
| **A new entry point misses a guard** | Euler (2023, the donation function lacked a health check and was used for self-liquidation) | Whether guards are consistent across entry points of the same kind | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md), [28](../dimensions/28-authorization-and-access-control.md) |
| **Precision, rounding and overflow checks** | KyberSwap (2023, rounding at a tick boundary made liquidity be counted twice); Cetus (2025, the threshold in the overflow check before a shift was wrong); Balancer (2025, rounding errors in batch swaps on stable pools were amplified over and over); Bunni (2025, the rounding direction in withdrawal calculations was unfavorable to the protocol) | Rounding direction, boundary values and handwritten overflow checks | [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("Shares and rounding"), [Move](../lang-move.md) |
| **Blind signing and tampered frontends** | Bybit (2025, malicious code was planted in the Safe frontend; signers saw a transfer, but what they signed was a delegatecall that upgraded the contract); Radiant (2024, malware was planted on the devices of multisig signers); BadgerDAO (2021, malicious approval requests were injected into the frontend); Ledger Connect Kit (2023, the npm package of the wallet connection library was poisoned, and many websites' frontends popped up coin-stealing signature requests) | Whether what the signing device shows is exactly what is being signed; frontend integrity and deployment permissions; whether frontend dependencies are pinned to fixed versions | [4.43](../specialties/4.43-wallets-signing-and-off-chain-components.md) ("Blind signing", "Frontend and hosting") |
| **Arbitrary calls spend user approvals** | LI.FI (2024, a new module that had been live for five days executed the call target and data supplied by the user as is); Socket (2024, a new route that had been live for three days did not validate extra call data); SushiSwap RouteProcessor2 (2023, the router accepted a forged pool address and moved approved funds away in the callback) | Whether the target and data executed on behalf of the caller are restricted; who can borrow the approvals users gave the contract | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Arbitrary calls"), [Solidity and Vyper](../lang-solidity.md) ("Callback origin") |
| **Callback entry points do not check the caller** | Cork (2025, anyone could call the `beforeSwap` of a Uniswap v4 hook directly and fake deposits); SIR.trading (2025, the transient storage slot that the callback check relied on was overwritten with a user-controlled value) | Whether callbacks and hooks accept only the real pool, lender or pool manager | [Solidity and Vyper](../lang-solidity.md) ("Callback origin", "Transient storage"), [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("Pool hooks") |
| **Forged meta-transaction senders** | TIME token (2023, combining ERC-2771 with multicall allowed forging any sender); KiloEx (2025, the forwarder contract's checks were loose, so the attacker posed as a trusted role and changed the oracle price) | The logic that takes the real sender from call data; the checks in the forwarder contract | [Solidity and Vyper](../lang-solidity.md) ("Meta-transaction sender") |
| **Phantom functions** | Multichain (2022, called `permit` on WETH, which has no `permit`; the fallback function did not revert, so the signature check did nothing, and WETH was moved away from users who had given approvals) | Whether the target contract really implements the function being called | [Solidity and Vyper](../lang-solidity.md) ("Phantom functions") |
| **Calls to addresses with no code treated as success** | Qubit (2022, the zero address was treated as a token address; the transfer call had no code to run but returned success, so it counted as a deposit and tokens were minted on another chain) | Whether low-level calls first confirm that the target has code; whether the zero address is rejected | [Solidity and Vyper](../lang-solidity.md) ("Low-level calls") |
| **The gap when a new market goes live** | Hundred Finance (2023); Radiant (2024, exploited six seconds after a new market opened); Sonne (2024, the listing operations queued in the timelock could be executed by anyone, and were front-run); Resupply (2025, a donation to an empty vault raised the share price, the exchange rate rounded to zero, and about ten million US dollars was borrowed against 1 wei of collateral) | Whether the initial state and steps are atomic when a new market or an empty vault goes live; whether the share price can be manipulated by donations | [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("New markets and empty pools", "Timelocks") |
| **Price feed stuck at a floor** | Venus, Blizz (2022, when LUNA crashed, the price feed stopped at a floor of about 0.1 US dollars; attackers bought cheaply at the market price and then borrowed against it at the floor price) | Whether prices can be clamped at upper or lower bounds; the application's own sanity checks | [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("Price feed selection and conversion") |
| **Code executed by a governance proposal is replaced** | Tornado Cash (2023, after the proposal passed, the proposal contract self-destructed and new code was deployed at the same address, and the attacker gave themselves 1.2 million votes) | Whether the code reviewed at voting time is the code that is executed | [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("Checking what a proposal executes") |
| **Upgrades or deployments miss configuration** | Ronin (2024, the upgrade called only one of the two new initialization functions, the vote threshold stayed at zero, and about 12 million US dollars was taken 48 minutes later); Yearn yUSDT (2023, a dependency address was misconfigured at deployment and was exploited about 1000 days later) | Whether an upgrade runs all the initialization it needs; whether dependency addresses and parameters are checked one by one | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Upgrade procedure", "Deployment scripts and parameters"), [Targets that are not source code](../targets/on-chain-contract-addresses.md) ("Initialized version") |
| **Unaudited code goes live** | Nemo (2025, a new feature added during the audit was deployed without review, and an upgrade needed only a single signature); LI.FI, Socket, SushiSwap (new modules or routes were exploited three to five days after going live) | Whether the on-chain version matches the audited version; whether new modules are audited on their own | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Deployed version versus audited version") |
| **Developers keep privileges** | Munchables (2024, a developer controlled the upgrade rights and wrote a huge balance for themselves before the upgrade); Infini (2025, admin privileges obtained during development were never revoked, and more than a hundred days later they were used to move about 49.5 million US dollars) | Whether deployer and developer addresses still hold roles or upgrade rights | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Handing over privileges"), [Targets that are not source code](../targets/on-chain-contract-addresses.md) ("Privilege holders") |
| A constant changed, but not everywhere | Uranium Finance (2021, when forking Uniswap V2 it changed the fee base to 10000, but the constant product check still used 1000) | Whether every change in forked code is consistent with the places that depend on it | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Forked code") |
| The fix for an upgrade bug delayed by the timelock | Compound (2021, after the upgrade in Proposal 62, reward distribution went wrong, and the fix also had to go through the seven-day governance process) | Whether there is a limited way to stop losses when an upgrade goes wrong | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Emergency mechanisms", "Upgrade procedure") |
| Behavior differences between chains | Gemholic (2023, sending ETH with `transfer` on zkSync Era failed because it needed more than 2300 gas; about 921 ETH was locked and later recovered with help from the chain team) | Differences between the target chain and Ethereum in gas metering, opcodes and address derivation; whether the code was run on the target chain's testnet | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Compiler and target chain") |
| **The same address on another chain** | Wintermute and Optimism (2022, the multisig address that was to receive 20 million OP had not yet been deployed on Optimism, and someone replayed the deployment transaction to take it first) | Whether the address is already deployed on the target chain, and who owns it | [4.38](../specialties/4.38-smart-contracts-and-on-chain-interaction.md) ("Cross-chain address assumptions") |
| **A cross-chain path with only one verifier** | KelpDAO (2026, the cross-chain configuration of rsETH required only 1 verifier; the RPC nodes that verifier relied on were poisoned, and it signed a message for a lock that did not exist) | The number and independence of verifiers on each path; where verifiers read on-chain data from | [4.42](../specialties/4.42-cross-chain-bridges-and-messaging.md) ("Messaging-layer security configuration"), [4.43](../specialties/4.43-wallets-signing-and-off-chain-components.md) ("Nodes and data sources") |
| **Pre-signed transactions executed later** | Drift (2026, after long-running social engineering, multisig members pre-signed durable nonce transactions; the attacker used them to take admin rights, removed the limits in one go, and listed fake collateral) | How long a signature stays valid and whether it can be revoked; whether admin operations have a timelock and limits that cannot be removed in one go | [4.43](../specialties/4.43-wallets-signing-and-off-chain-components.md) ("Pre-signed and long-lived signatures"), [Solana](../lang-solana.md) ("Durable nonce transactions"), [4.41](../specialties/4.41-defi-economics-and-oracles.md) ("Timelocks") |
| **Not enough randomness in key generation** | Profanity vanity address tool (2022, the private key of Wintermute's hot wallet was brute-forced, about 160 million US dollars); Coldcard (2026, some firmware versions did not use the hardware random number generator when generating seeds, and about 1800 BTC was stolen) | Which tools and firmware generated the private keys and mnemonics; whether addresses generated by affected versions can be identified | [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Randomness and unpredictability"), [4.43](../specialties/4.43-wallets-signing-and-off-chain-components.md) ("Key custody") |
