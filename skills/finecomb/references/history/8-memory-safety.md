# 8 Memory safety

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **Out-of-bounds reads driven by a length field** | Heartbleed (CVE-2014-0160, echoed back memory using the length the peer declared); Citrix Bleed (CVE-2023-4966, treated the return value of `snprintf` as the length actually written, leaking session tokens) | Reading or copying by a length the peer supplies; treating "the length that should be written" as "the length actually written" | [4.2](../specialties/4.2-protocols-and-frame-parsing.md), [4.3](../specialties/4.3-decoding-untrusted-external-data.md), [C and C++](../lang-c-cpp.md) |
| **Heap overflows after a wrong size or bounds calculation** | sudo (CVE-2021-3156, when an argument ended with a single backslash, the unescape loop went past the terminating NUL and kept writing); libwebp (CVE-2023-4863, out-of-bounds Huffman table); FortiOS SSL-VPN (CVE-2023-27997); nginx (several CVEs in 2026: the length estimation pass and the write pass disagreed) | Whether calculations of allocation sizes, indexes and table sizes can overflow or be inflated by input; loop end conditions, and the capacity check before each write | [14](../dimensions/14-boundaries-numbers-and-text.md) ("Capacity and boundary comparisons", "Parse cursors"), [C and C++](../lang-c-cpp.md) |
| Boundary assumptions at process entry | PwnKit (CVE-2021-4034, when `argc` is 0, out-of-bounds reads and writes of environment variables) | Assumptions about the count and format of `argv` and environment variables | [C and C++](../lang-c-cpp.md) ("Process entry assumptions"), [4.15](../specialties/4.15-command-line-and-process-entry-points.md) |
| Use after free | BlueKeep (CVE-2019-0708); many reference counting bugs in browsers and kernels | Reference counts, objects freed inside callbacks, double frees on error paths | [19](../dimensions/19-lifecycle-and-resources.md), [C and C++](../lang-c-cpp.md) |
| Uninitialized fields | Dirty Pipe (CVE-2022-0847, the flags of a pipe buffer were not initialized) | Whether reused structures and buffers are fully reset before reuse | [31](../dimensions/31-performance-memory-and-latency.md) ("Object pools"), [16](../dimensions/16-language-and-runtime-pitfalls.md) |
| Memory corruption caused by races | Dirty COW (CVE-2016-5195) | Races on copy-on-write, page tables and shared mappings | [18](../dimensions/18-concurrency-and-memory-model.md) |
| **Non-reentrant code in signal or timeout callbacks** | regreSSHion (CVE-2024-6387, the signal handler for the login timeout called functions that are not async-signal-safe; it is a regression of CVE-2006-5051 from 2006) | What signal handlers and timeout callbacks do | [4.30](../specialties/4.30-os-interfaces-system-calls-and-descriptors.md) ("Signals"), [C and C++](../lang-c-cpp.md) ("Signals") |
| **A computer hidden inside a decoder** | FORCEDENTRY (CVE-2021-30860, built a computer out of logic operations inside JBIG2 decoding); Stagefright (CVE-2015-1538); BLASTPASS (CVE-2023-41064) | Whether decoding of complex formats (images, fonts, documents, media) runs in a sandbox or in a memory-safe language; whether it can be triggered with zero clicks | [4.3](../specialties/4.3-decoding-untrusted-external-data.md), [4.22](../specialties/4.22-subprocesses-dynamic-execution-and-decoder-side-effects.md) |
| Parsing bugs in protocol stacks | EternalBlue (CVE-2017-0144, SMB) | Network protocol parsing in the kernel or in privileged services | [4.2](../specialties/4.2-protocols-and-frame-parsing.md) |
| **Type confusion after JIT speculative optimization** | Chrome V8 (CVE-2022-1364, CVE-2023-2033, CVE-2024-4947, all type confusion bugs exploited in the wild) | Whether the type and shape assumptions the optimizer relies on are checked again after callbacks and aliased writes | [4.27](../specialties/4.27-interpreters-compilers-and-virtual-machines.md) ("Assumptions behind speculative optimization", "Range analysis and check elimination") |
| Internal sentinel values leak to scripts | V8 (CVE-2021-38003, the exception path of `JSON.stringify` handed the internal "hole" value to script, which then led to memory corruption) | Whether special internal values of the engine can reach user code through error paths | [4.27](../specialties/4.27-interpreters-compilers-and-virtual-machines.md) ("Internal sentinel values leaking out") |
