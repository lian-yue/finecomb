# 6 Authentication, sessions and identity

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **The initialization flow can be re-entered** | Confluence (CVE-2023-22515, the setup wizard could still be called again after it finished, creating an administrator); PaperCut (CVE-2023-27350) | Whether the entry points for installation, initialization and creating the first administrator are closed once they finish | [28](../dimensions/28-authorization-and-access-control.md) ("Setup and installation entry points"), [9](../dimensions/9-business-logic-and-flow-integrity.md) |
| **Critical functions lack authentication** | Cisco IOS XE (CVE-2023-20198, a high-privilege account could be created without authentication); Juniper (CVE-2023-36846, CVE-2023-36847) | Whether admin, upload and configuration interfaces require authentication on every path | [28](../dimensions/28-authorization-and-access-control.md) ("Where checks happen") |
| Default passwords and hardcoded credentials | Unitronics PLC (CVE-2023-6448); the Mirai botnet | Factory default passwords; credentials hardcoded in code or firmware | [27](../dimensions/27-security-and-trust-boundaries.md) ("Hardening"), [4.4](../specialties/4.4-cryptography-and-credentials.md) |
| **A missing value or a failed lookup falls back to a privileged default** | OMI "OMIGOD" (CVE-2021-38647, a request without an Authorization header ran as root); polkit (CVE-2021-3560, after failing to get the caller's uid, it treated the uid as 0); macOS Gatekeeper (CVE-2021-30657, a script app missing Info.plist was misclassified and skipped notarization and signature checks; exploited in the wild) | The initial value of identity, tenant and permission objects; which branch runs when getting the identity fails, a field is missing or metadata is missing | [28](../dimensions/28-authorization-and-access-control.md) ("Defaults when identity is missing"), [29](../dimensions/29-fail-safe-behavior-and-dangerous-operations.md) ("Failure direction") |
| **Signature verification does not check the issuer, purpose or algorithm** | Storm-0558 (2023, the enterprise side accepted tokens signed with a consumer key; developers assumed the SDK checked the issuer by default); node-jsonwebtoken algorithm confusion (CVE-2015-9235, an RS or ES public key used as an HS key for verification); Java ECDSA accepting r=s=0 (CVE-2022-21449); Apple "goto fail" (CVE-2014-1266, a duplicated line skipped signature verification) | Whether the issuer, audience, purpose, algorithm and key source are all checked when verifying a signature; whether assumptions about a dependency's default behavior were verified | [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("Validation completeness"), [4.4](../specialties/4.4-cryptography-and-credentials.md), [35](../dimensions/35-dependencies.md) ("Understanding the contract") |
| **Derivation functions silently truncate** | Okta 2024: cache key = bcrypt(user ID + username + password), and bcrypt reads only the first 72 bytes, so with a long enough username the password took no part in the check | Hash, derivation and password functions with an input length limit; whether the part beyond the limit after concatenation is silently dropped | [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Key derivation and passwords") |
| External identities matched by a mutable attribute | Merging accounts by an email claim that can be changed (nOAuth, 2023); in 2020, Sign in with Apple could issue tokens for any email | Which attribute of the external identity is used to find the local account; whether the user can change that attribute or it is unverified | [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("External identity binding") |
| **Content triggers connections that carry credentials automatically** | Outlook (CVE-2023-23397, a reminder's sound file path pointed to an external UNC address, which automatically started NTLM authentication and leaked the hash) | Whether paths and addresses in external content make the system automatically start a connection that carries the current identity's credentials | [4.21](../specialties/4.21-outbound-requests-and-server-side-request-forgery.md) ("Identity carried outbound") |
| Reset links sent elsewhere | Password reset links built from the Host header (Host header poisoning) | Where the host name used to build absolute URLs comes from | [4.14](../specialties/4.14-server-request-handling-and-middleware.md) ("Host header") |
| **Coerced authentication, then relay** | PetitPotam (CVE-2021-36942, tricked a domain controller into NTLM authentication to the attacker, then relayed it to the AD CS web enrollment interface to request a certificate) | Whether services that accept challenge-response authentication require signing or channel binding | [4.46](../specialties/4.46-federated-identity-and-single-sign-on.md) ("Relay of challenge-response authentication") |
| **Issued identity taken from a changeable attribute or a name fallback** | Certifried (CVE-2022-26923, a machine account changed its `dNSHostName` and then obtained a certificate bearing a domain controller's name); noPac (CVE-2021-42278, CVE-2021-42287, a machine account was renamed to a domain controller's name without the `$`; when the KDC could not find it, the KDC appended `$` and issued a ticket for the domain controller); Bronze Bit (CVE-2020-17049, anyone holding the service key could tamper with the forwardable flag in a ticket) | Where the name comes from when issuing credentials, and whether the requester can change it; whether a failed lookup falls back to a variant; whether trusted fields are protected by a signature | [4.46](../specialties/4.46-federated-identity-and-single-sign-on.md) ("Identity source when issuing credentials"), [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Binding and context") |
| OAuth redirect URIs loosened | Keycloak (CVE-2023-6927, wildcard redirect URIs combined with the `form_post.jwt` response mode leaked authorization codes); Expo AuthSession proxy (CVE-2023-28131, accounts that used social login through the proxy could be taken over) | Whether redirect URIs are matched exactly; whether an intermediate proxy can pass the authorization result to someone else | [4.46](../specialties/4.46-federated-identity-and-single-sign-on.md) ("Redirect URIs") |
| **One-time codes can be brute-forced** | Microsoft AuthQuake (2024, the failure limit for one-time passwords was tied only to a temporary session, so creating new sessions allowed brute force in parallel; each code stayed valid for about 3 minutes) | What object the attempt counter for verification codes is tied to; whether it resets after switching sessions or addresses | [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("One-time codes") |
| Push approval bombing | Uber (2022, the attacker triggered login approvals again and again until a contractor finally tapped approve) | Rate limits and number matching for push approvals | [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("Push approvals") |
| Email parsing differentials | PortSwigger 2024 "Splitting the email atom": encoded words, quotes and comments made addresses that seemed to end in `@company-domain` get delivered elsewhere, bypassing authorization by domain | When authorizing by email domain, whether validation and delivery derive the same domain from the same address | [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("Identity granted by email domain"), [27](../dimensions/27-security-and-trust-boundaries.md) ("Parser differentials") |
