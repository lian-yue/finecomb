# 7 Authorization and privilege escalation

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **Object-level authorization bypass** | Number one in the OWASP API Top 10 (BOLA); many interfaces fetch objects by ID without checking ownership | Whether every entry point that fetches an object by identifier checks the relation between the current principal and the object | [28](../dimensions/28-authorization-and-access-control.md) ("Horizontal privilege escalation") |
| **Data binding writes internal properties** | GitHub's Rails mass assignment in 2012; Spring4Shell (CVE-2022-22965, binding to `class.module.classLoader`) | Whether request binding has an allowlist; whether it can write roles, owners or even internal framework objects | [28](../dimensions/28-authorization-and-access-control.md) ("Automatic field binding"), [4.3](../specialties/4.3-decoding-untrusted-external-data.md) |
| Prototype pollution | lodash (CVE-2019-10744) | Whether deep merge and assignment by path block `__proto__` and `constructor` | [4.3](../specialties/4.3-decoding-untrusted-external-data.md) |
| Incomplete authorization on admin functions | Confluence (CVE-2023-22518) | Whether every admin operation is authorized, rather than only hidden from the menu | [28](../dimensions/28-authorization-and-access-control.md) ("Vertical privilege escalation") |
| **A new entry point misses a check that every other entry point has** | Euler Finance (2023; details in [18](18-smart-contracts-and-on-chain.md) ("A new entry point misses a guard")) | Whether checks are consistent across entry points of the same kind; whether a new entry point reuses the same set of guards | [2.1 For each public entry point](../questions.md#21-for-each-public-entry-point), [28](../dimensions/28-authorization-and-access-control.md) ("Consistency across entry points") |
| **Declared access control does not take effect** | Spring Security (CVE-2025-41248, `@PreAuthorize` annotations on generic superclasses or interfaces were not resolved, so method authorization silently stopped working) | Whether controls written in annotations or configuration have tests proving that unauthorized requests are rejected | [28](../dimensions/28-authorization-and-access-control.md) ("Whether declared controls take effect") |
| Checks on only some request methods | JBoss JMX console (CVE-2010-0738, access control was configured only for GET and POST; any other method went straight into the handler) | When permission rules are configured per method, which methods the handler actually accepts | [4.14](../specialties/4.14-server-request-handling-and-middleware.md) ("Request methods"), [28](../dimensions/28-authorization-and-access-control.md) ("Matching of authentication exemptions") |
| Client talks directly to the database, rules missing | Sites generated by Lovable (CVE-2025-48757, insufficient row-level security policies let unauthenticated users read and write any table; the vendor disputes this) | The rules on every table and every storage bucket of data services the frontend talks to directly | [28](../dimensions/28-authorization-and-access-control.md) ("Data services the client talks to directly"), [4.7](../specialties/4.7-databases-and-queries.md) ("Data-layer permissions") |
