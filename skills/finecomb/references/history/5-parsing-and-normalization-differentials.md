# 5 Parsing and normalization differentials

| Pattern | Historical cases | What to look for | Where it lands |
| --- | --- | --- | --- |
| **Validate first, decode or normalize later** | Apache httpd (CVE-2021-41773, bypass with encoded `../`); F5 TMUI (CVE-2020-5902, `..;/`); Fortinet (CVE-2018-13379); Pulse Secure (CVE-2019-11510); Citrix (CVE-2019-19781) | Whether the path check happens before or after decoding and normalization; whether the two components before and after agree on `;`, `%2e`, backslashes and double encoding | [4.8](../specialties/4.8-file-systems-and-paths.md), [27](../dimensions/27-security-and-trust-boundaries.md) ("Parser differentials") |
| **Authentication exemption rules matched as strings** | TeamCity (CVE-2023-42793, paths ending in a specific suffix skipped authentication) | Whether authentication exemptions match the raw path by prefix, suffix or regular expression; whether an attacker can build a path that hits both an exemption and a protected handler | [28](../dimensions/28-authorization-and-access-control.md) ("Matching of authentication exemptions"), [4.14](../specialties/4.14-server-request-handling-and-middleware.md) |
| **Backend trust after a proxy rewrites headers** | F5 BIG-IP (CVE-2022-1388, the `Connection` header made the proxy drop the authentication header, and the backend trusted requests from the local machine by default); Next.js (CVE-2025-29927, an external request carrying the internal subrequest header skipped the whole middleware) | Hop-by-hop headers, and headers the proxy deletes or rewrites; backend assumptions such as "requests from the local machine are trusted" or "a request with a certain header is trusted" | [4.14](../specialties/4.14-server-request-handling-and-middleware.md) ("Proxy trust", "Header handling"), [34](../dimensions/34-runtime-environment-and-deployment-contract.md) |
| **Validation and use rely on different parsers** | Go `net.ParseIP` leading zeros (CVE-2021-29923); npm netmask (CVE-2021-28918); SSRF bypasses caused by differences between URL parsers | Whether the parser used to validate an address, URL or IP is the same one used to send the request or do the matching | [4.21](../specialties/4.21-outbound-requests-and-server-side-request-forgery.md), [4.29](../specialties/4.29-rule-and-policy-matching.md) |
| **A single-value field receives an array or repeated parameters** | GitLab (CVE-2023-7028, passing an array of emails in a password reset request sent the reset link to an unverified second address) | Whether a field expected to hold one value can receive an array, repeated parameters or repeated JSON keys; validation looks only at the first one, while execution uses all of them or the last one | [27](../dimensions/27-security-and-trust-boundaries.md) ("Parser differentials"), [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("Account recovery") |
| **Case folding and Unicode normalization collisions** | GitHub password reset in 2019: characters such as the Turkish dotless i became identical to someone else's email after case conversion | What case conversion and normalization happen before comparing accounts, emails and usernames; whether different raw values can map to the same identity | [14](../dimensions/14-boundaries-numbers-and-text.md), [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) |
| **What is shown differs from what is used** | WinRAR (CVE-2023-38831, a space at the end of a file name made the user open a different file); Trojan Source (CVE-2021-42574, bidirectional control characters in source code) | Whether the names and content shown to people are the same as what the program actually uses | [27](../dimensions/27-security-and-trust-boundaries.md) ("What is shown differs from what is used") |
| **Writing out and reading back are not symmetric** | Git (CVE-2025-48384, when writing config, a value ending in a carriage return was not quoted; on reading back the carriage return was stripped, so the submodule path pointed elsewhere, and a hook was written through a symbolic link) | Whether a value that this component writes out and reads back is still the original value; whether the escaping and whitespace trimming rules match on both sides | [24](../dimensions/24-encoding-and-persistent-formats.md) ("Round trip and canonical form") |
| The signed object differs from the object used | SAML comment truncation (CVE-2017-11427); XML signature wrapping; ruby-saml (CVE-2024-45409, XPath picked the wrong signature node; CVE-2025-25291, CVE-2025-25292, REXML and Nokogiri parsed different trees) | Whether the node and canonicalized result that signature verification covers are the same as the node the business logic reads; whether both places use the same parser | [4.24](../specialties/4.24-webhooks-and-external-events.md) ("What is verified"), [4.46](../specialties/4.46-federated-identity-and-single-sign-on.md) ("SAML assertions", "Consistent XML parsing") |
| **The signature does not cover the bytes actually used** | Android "Master Key" (CVE-2013-4787, duplicate ZIP entry names: signature verification read one, installation used the other); Janus (CVE-2017-13156, v1 signatures do not cover the bytes at the start of an APK, so a DEX could be prepended); Authenticode (CVE-2013-3900, data can be appended to the signature area; the 2023 3CX attack used it to hide a payload in a Microsoft-signed DLL) | Whether the range that signature verification covers is exactly the range the loader or unpacker actually reads | [36](../dimensions/36-supply-chain-and-artifact-integrity.md) ("What a signature covers"), [4.35](../specialties/4.35-client-apps-extensions-and-auto-update.md) ("Auto-update") |
| Request smuggling | CL.TE and TE.CL smuggling across many proxy and backend combinations | Whether the two HTTP implementations in front and behind agree on length and chunking | [4.14](../specialties/4.14-server-request-handling-and-middleware.md) |
| Smuggling in email and other non-HTTP protocols | SMTP smuggling (Postfix CVE-2023-51764, sendmail CVE-2023-51765, Exim CVE-2023-51766: two servers in a row disagreed on whether `<LF>.<CR><LF>` ends the data, which let an email with a forged sender slip through) | In text protocols you implement or forward, whether the terminator, line breaks and lengths are understood the same way as upstream and downstream | [4.2](../specialties/4.2-protocols-and-frame-parsing.md) ("Coexisting with another parser"), [4.40](../specialties/4.40-notifications-and-outbound-messages.md) |
| Spliced into an internal line-based protocol | Zimbra (CVE-2022-27924, line breaks in external input entered memcache commands and poisoned the cached authentication routing, which sent users' mail connections to the attacker and captured their passwords) | Whether line breaks are rejected before external values are spliced into memcache, Redis, SMTP or IMAP commands | [4.17](../specialties/4.17-templates-and-text-output.md) ("Line breaks and encoding"), [4.6](../specialties/4.6-caching-and-storage.md) |
