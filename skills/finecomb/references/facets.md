# Root-cause facets

Root-cause facets are questions distilled from the root causes of real vulnerabilities, independent of domain and language. The same facet shows up again and again in kernels, web servers, cryptography libraries, smart contracts and business systems, only in a different shape. The [general dimensions](dimensions.md) are organized by quality attribute and the [specialties](specialties.md) by target type, and either one can let a cross-domain root cause fall through the gaps. This file pulls the root causes out on their own: **go through them for every object**.

How to use:

- After the [per-object questions](questions.md), ask every facet in turn for each entry point, validation point, piece of shared state, buffer, parsing loop, state transition and external interaction. When a facet does not apply to an object, write down the reason in the coverage record.
- The "Detailed criteria" column of each facet points to the specific check rows. This file only gives the question to ask and why it is easy to miss.
- "Real cases" only show what the facet looks like. They are not a checklist; the same facet holds in other domains too.
- Group the issues you find by facet. This also works as a reverse check: if a facet was never seriously asked during the whole review, that is a coverage gap.
- This checklist has been tested for hits against real vulnerabilities (nginx, the Linux kernel, OpenSSL, OpenSSH, glibc, major frameworks and enterprise appliances, on-chain and zero-knowledge proof incidents), and every root cause it missed has been turned into a facet here. Check new vulnerabilities the same way: if no facet matches, a facet needs to be added.

## Validation and trust

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Completeness of verification** | Does this verification (validator, constraint, signature or proof verification, authorization rule, type check) accept only what it should? Ask the reverse: what other inputs can also pass? Does a pattern match have to cover the whole string, or does finding one piece count as passing? When the sender marks an extension or parameter as "must understand" and the receiver does not recognize it, does the receiver reject it or ignore it? | Tests only feed correct input, and correct input passing does not mean bad input is rejected; reviews only look at "whether the checks that were written are right", not "which check is missing" | One missing constraint in the Zcash Orchard circuit allowed unlimited coin forgery; "goto fail" skipped signature verification; checking only that a SAML signature exists without verifying it | [8](dimensions.md#8-functional-correctness-and-fitness-for-requirements) ("Completeness of verification"), [27](dimensions.md#27-security-and-trust-boundaries) ("Whether regex allowlists match the whole string"), [4.2](specialties.md#42-protocols-and-frame-parsing) ("Unknown must-understand items"), [28](dimensions.md#28-authorization-and-access-control), [4.44](specialties.md#444-zero-knowledge-proofs-and-circuits) |
| **Whether declared controls actually take effect** | Are the security controls written in annotations, decorators, route tables and configuration really attached to every entry point that needs them? Can inheritance, generics, interfaces, route order or request methods make the framework silently not apply them? | Once it is "written" in the code, it is treated as "in place" | Spring Security annotations on a generic parent class were not resolved; access control was configured only for GET and POST, so another method goes straight in | [28](dimensions.md#28-authorization-and-access-control) ("Where checks happen", "Whether declared controls take effect"), [4.14](specialties.md#414-server-request-handling-and-middleware) ("Request methods") |
| **What a check covers** | Which bytes, files, fields and paths do the signature, integrity check, scan or sanitizer actually cover? Does anything that is loaded, executed or used at run time fall outside that coverage? | The check "passed", and no one asks whether it checked everything | APK signatures do not cover the bytes at the start of the file; data can be appended to the Authenticode signature area; Electron's integrity check does not cover the V8 snapshot | [36](dimensions.md#36-supply-chain-and-artifact-integrity) ("What a signature covers"), [24](dimensions.md#24-encoding-and-persistent-formats) ("Integrity checks") |
| **Missing values and defaults** | Where does it land when something is missing: when the authentication header, identity, tenant, a field, metadata or an optional component in front (proxy, gateway, plugin) is absent, do the default value and the default branch deny or allow? Does the default value itself carry privilege? | Test environments are always fully configured; the zero or empty value happens to mean admin or "everything" | Requests without an authentication header ran as root (OMIGOD); failing to get the caller's identity was treated as uid 0 (polkit); AS2 validation was skipped when no DMZ proxy was deployed (CrushFTP) | [28](dimensions.md#28-authorization-and-access-control) ("Defaults when identity is missing"), [29](dimensions.md#29-fail-safe-behavior-and-dangerous-operations) ("Failure direction"), [32](dimensions.md#32-configuration-and-defaults) |
| **Where trust comes from** | Who supplied this value: the peer, a request header, upstream, configuration, environment variables, a local process, a low-privilege user, another tenant, a dependency's default behavior? Are values that seem to come from infrastructure but are actually controlled indirectly by the other side (host names from reverse lookups, fields in the peer's certificate, upstream responses, DNS records) treated as trusted? On what grounds are they trusted? | "From inside", "from the local machine" and "from configuration" are trusted by default | Local requests treated as authenticated; Next.js skipping middleware based on an internal request header; configuration injection in IngressNightmare; the nginx mail proxy putting a host name from a reverse lookup into the authentication request without validation | [27](dimensions.md#27-security-and-trust-boundaries) ("Classifying input sources"), [4.14](specialties.md#414-server-request-handling-and-middleware) ("Proxy trust") |
| **Privileged code handling low-privilege input** | Is high-privilege code (setuid programs, the kernel, drivers, privileged services, admin consoles, build machines) handling things that a low-privilege party can control: environment variables, files, paths, configuration, root directories, device requests? What can data that a low-privilege party can change (owner references, finalizers, labels, status fields, referenced names) make automation running with high privileges (controllers, garbage collection, schedulers, scheduled jobs, workflows) do on its behalf? | Authors of high-privilege code write it with the habits of ordinary programs; the privileges of automation are not counted as the requester's | glibc parsing environment variables in setuid programs; sudo loading configuration from a user-specified root directory; a privileged service led to a system file through a link in a user-writable directory | [4.47](specialties.md#447-local-privileged-components-and-local-privilege-escalation), [4.48](specialties.md#448-kernel-drivers-device-emulation-and-virtualization), [4.22](specialties.md#422-subprocesses-dynamic-execution-and-decoder-side-effects), [28](dimensions.md#28-authorization-and-access-control) ("Indirect effects of fields") |
| **Binding and context** | In what context was a result (authentication, authorization, signature, proof, cache entry, session) obtained? Can it be carried into another context and still be treated as valid? Does a result obtained in a callback or hook belong to one of the candidate objects, or to the object that finally takes effect? | It was right at the moment of verification; the problem is where it is reused later | nginx TLS sessions reused across virtual hosts, bypassing client certificate verification; an SSO token issued by one tenant accepted by another tenant | [27](dimensions.md#27-security-and-trust-boundaries) ("Whether binding chains are enforced"), [10](dimensions.md#10-apis-and-contracts) ("Callbacks versus the final result"), [4.4](specialties.md#44-cryptography-and-credentials) ("Binding and context") |
| **What a limit is bound to** | What object are counts, quotas, rates and failure counters attached to: the account or the resource, or a session, connection, source address or temporary identifier that the attacker can swap or reset at any time? | A limit that "exists" is treated as effective | The failure limit for one-time passwords was attached to a temporary session, so recreating sessions allowed brute force in parallel | [4.5](specialties.md#45-authentication-sessions-and-tokens) ("One-time codes"), [20](dimensions.md#20-resource-bounds-and-backpressure) ("Quota ownership and accounting") |

## Representation and transformation

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Multiple representations of the same fact** | Does the same value, path, identity or encoding have more than one way to write it? Is the form used for validation the same as the form finally used? Does writing it out and reading it back give the original value? | Two components are each "correct", but understand the input differently when combined | Paths validated before decoding; an array parameter sending the reset email to a second address; both x and x plus the modulus pass verification; Git writing configuration without quotes and dropping the carriage return when reading it back | [27](dimensions.md#27-security-and-trust-boundaries) ("Parser differentials"), [24](dimensions.md#24-encoding-and-persistent-formats) ("Round trip and canonical form") |
| **Transformations after validation** | After validation, does the value still go through decoding, normalization, character set conversion, command-line reassembly, template expansion or another parser? Is what validation sees the same as what finally runs? | Validation and use are in two places, and no one watches the transformation in between | Windows best-fit character set mapping turns a soft hyphen into `-` (PHP-CGI); calling a batch file with an argument array is still re-parsed by `cmd.exe` (BatBadBut) | [4.22](specialties.md#422-subprocesses-dynamic-execution-and-decoder-side-effects) ("Windows command-line reassembly", "Character set conversion rewriting arguments"), [27](dimensions.md#27-security-and-trust-boundaries) ("Input validation") |
| **Processing path chosen by input** | Is the parser, handler or branch chosen by an attribute the request controls (content type, extension, parameter, version number)? Can a different representation skip the path that does sanitizing or limiting, while still reaching the later point of use? | Each path has checks when looked at alone | Changing the content type bypassed the upload sanitizer (n8n) | [4.3](specialties.md#43-decoding-untrusted-external-data) ("Format confusion", "Handler chosen by the request"), [4.21](specialties.md#421-outbound-requests-and-server-side-request-forgery) ("Protocol restrictions") |
| **Data turning into instructions** | Which places that interpret external data will it finally reach (queries, commands, templates, expressions, protocol headers, configuration, log lookups, next-hop requests, line-based internal protocols)? Can connection strings, driver parameters or argument-parsing libraries interpret a value as a command, a script or a file read? When a value is spliced in, does it have its own boundaries, and can its first and last characters combine with the template characters before and after it into new tokens? Is it stored somewhere first along the way and later spliced in elsewhere? | The first use is safe; protection is lost on second use or forwarding | Log4Shell; a session ID becomes a file name and then goes into a shell; nginx injecting request content into upstream or mail authentication requests; newline injection into memcache commands | [27](dimensions.md#27-security-and-trust-boundaries) ("Injection surface", "Second-order use"), [4.22](specialties.md#422-subprocesses-dynamic-execution-and-decoder-side-effects), [4.17](specialties.md#417-templates-and-text-output) ("Boundaries at the insertion point"), [4.7](specialties.md#47-databases-and-queries) ("Connection strings and driver parameters"), [4.15](specialties.md#415-command-line-and-process-entry-points) ("Implicit expansion by argument-parsing libraries") |
| **Protocol and format conversion** | When converting between two protocols, two encodings or two versions, which semantics are lost and which new semantics are introduced? Is a character that is legal in the first one a delimiter in the second? Do upstream and downstream agree on terminators and lengths? | Each protocol is right on its own; no one owns the conversion layer | Injection when HTTP/2 requests are converted to HTTP/1 for the upstream; after a proxy removes hop-by-hop headers, the backend trusts the request as local; SMTP smuggling | [4.14](specialties.md#414-server-request-handling-and-middleware), [4.2](specialties.md#42-protocols-and-frame-parsing), [37](dimensions.md#37-interoperability-and-coexistence) |
| **Which attributes survive a move** | When an object is copied, unpacked, mounted, imported, converted, saved as another file, forwarded or mapped across namespaces, are **restricting attributes** (download origin marks, taint, data classification, quarantine attributes) kept, and are **privilege attributes** (setuid, capabilities, owner, signed status) stripped or checked again? Can boundary values (unmapped users, default identities) fall into a special case that "neither errors nor strips"? If a mark cannot be written, is the object still let through? In multi-step chains (redirects, forwarding, delegation, privilege dropping), does the stripping or narrowing done at an earlier step still hold at every later step? Is each step derived from the result of the previous step, or copied from the original object again? | Attributes are checked only once, at the first step; the check only compares two adjacent steps | Unpacking nested archives did not pass on the download origin mark (7-Zip); a restrictive ACL kept the quarantine attribute from being written (macOS); OverlayFS kept setuid when copying (CVE-2023-0386) | [4.35](specialties.md#435-client-apps-extensions-and-auto-update) ("Download origin marks"), [27](dimensions.md#27-security-and-trust-boundaries) ("Attributes carried across boundaries", "Narrowing across multi-step chains"), [4.21](specialties.md#421-outbound-requests-and-server-side-request-forgery) ("Credentials across redirect chains"), [4.8](specialties.md#48-file-systems-and-paths) |
| **Completeness of equivalence checks** | Does every judgment that "these two are the same, so we can skip, merge, reuse or prune" (equality comparisons, cache keys, deduplication keys, memoization, state merging, verifier pruning) include every field that affects the result and security? If two things that are not equivalent are judged equivalent, which check is skipped and whose data is returned? | Equivalence checks are written for performance and are not treated as security logic | The eBPF verifier judged states with different safety properties as equivalent and pruned a dangerous path (CVE-2023-2163); a cache key missing the tenant or permission field | [15](dimensions.md#15-algorithm-and-data-structure-correctness) ("Identity normalization"), [4.6](specialties.md#46-caching-and-storage) ("Cache keys and isolation"), [4.27](specialties.md#427-interpreters-compilers-and-virtual-machines) ("Compilation cache") |
| **Consistency of types and tags** | In how many places is the type of the same field or object declared (struct definition, encoding and decoding template, comparison, copy, free, union tag)? Do they all agree? Which one does the reader go by? Is anything used as a certain type without checking the tag? | The type "looks like" it has only one definition | OpenSSL's X.400 address had different types in the struct and in the parsing template (CVE-2023-0286); type confusion after V8 optimization | [16](dimensions.md#16-language-and-runtime-pitfalls) ("Undefined behavior and memory safety"), [4.27](specialties.md#427-interpreters-compilers-and-virtual-machines) |

## Memory, lengths and parsing

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Length, offset and size calculations** | Where do the length, offset and capacity of each read and write come from? Can addition, subtraction or multiplication overflow or underflow? Is the remaining space checked before **every** write, with delimiters, escape sequences, prefixes and the trailing NUL counted too? Does the comparison use `<` or `<=`, and what happens when one more byte is written after the buffer is exactly full? Are the "length that should be written" and the "length actually written" mixed up? Do the pass that computes the size first and the pass that actually writes walk the same set, use the same test and encode the same way (escaping, variable-length integers, worst-case compressed length)? Between the two passes, can the computed value be evaluated again or changed elsewhere? | It only goes wrong for rare input combinations, boundary values or configurations | Heartbleed; Citrix Bleed treating the return value of `snprintf` as the actual length; an off-by-one comparison in OpenSSL punycode; glibc iconv checking capacity for only some control sequences; Linux uvcvideo skipping at write time a frame that was counted when computing the size; nginx reserving a fixed 4 bytes for a variable-length integer prefix when estimating length, while an overlong field actually needs 5 bytes; the nginx script engine re-running a regular expression between length estimation and copying, changing captures whose length was already computed | [14](dimensions.md#14-boundaries-numbers-and-text) ("Capacity and boundary comparisons", "Where an offset lands"), [4.2](specialties.md#42-protocols-and-frame-parsing), [C and C++](lang-c-cpp.md) |
| **Parse cursors and input consumption** | In parsing, unescaping and tokenizing loops, how far does the cursor move at each step? On a malformed token, a repeated delimiter or a trailing escape character, can the cursor stay put, move back or run past the end? Can the same stretch of input be read twice and written into a buffer sized on the assumption that it is "read only once"? | With normal input, the cursor always moves forward by exactly the right amount | glibc `GLIBC_TUNABLES` consuming the same stretch twice when there is an extra `=` (Looney Tunables); a single trailing backslash in sudo making the loop run past the NUL | [14](dimensions.md#14-boundaries-numbers-and-text) ("Parse cursors"), [4.2](specialties.md#42-protocols-and-frame-parsing) |
| **Data layout assumptions** | Does the code assume the data is in contiguous memory, a single buffer, a single read or a fixed alignment, and is writable and owned only by itself? Could it actually be spread over several fragments, cross a boundary, be truncated, or be a shared page, a read-only page, a copy-on-write page or a duplicate mapping of the same page? Before writing in place, is it confirmed to be writable and exclusive? | Common paths are always contiguous and exclusive; only a few paths produce fragments or sharing | Linux ebtables SNAT writing into a non-linear skb fragment backed by file pages; io_uring treating duplicate mappings of the same page as physically contiguous (CVE-2023-2598) | [14](dimensions.md#14-boundaries-numbers-and-text) ("Data layout"), [4.2](specialties.md#42-protocols-and-frame-parsing) ("Message boundaries"), [4.30](specialties.md#430-os-interfaces-system-calls-and-descriptors) |
| **Lifetime and ownership** | Who creates, holds and frees this object? After it is freed, who still holds a reference (callbacks, timers, async tasks, caches, secondary indexes, another connection, pages mapped to user space, pointers in temporary buffers)? Is it allocated from a memory pool, arena or scope but attached to an object that lives longer? Do error paths free twice or miss a free? In the same batch or transaction, can a later step still get an object that an earlier step deleted or invalidated? | Normal paths are paired; async, batch or error paths are not | nginx HTTP/3 allocating a session-level buffer in a single stream's memory pool, so the buffer was freed when the stream closed while the pointer remained; use-after-free in nginx SSI and the OCSP parser; use-after-free in Linux nf_tables and kTLS; GPU mappings still usable after the pages were freed | [19](dimensions.md#19-lifecycle-and-resources) ("Objects invalidated within a batch", "Allocation ownership"), [12](dimensions.md#12-state-machines-and-transitions), [C and C++](lang-c-cpp.md) |
| **Keeping linked fields in sync** | When a group of fields that must hold together (buffer and length, array and count, pointer and valid flag, data and version number, cache and expiry time) is reallocated, reset, copied, inherited, partly fails or is truncated to a limit, are they updated together? Is there a path that changes only half of them? | Each field is maintained when looked at alone | nginx reallocating the capture array for a subrequest without clearing the capture count, then reading uninitialized memory by the old count; nginx mail authentication rewriting the data pointer before a decode failure, leaving "new data, old length"; a struct copy carrying along a pointer that should not be shared | [5](dimensions.md#5-coupling-and-blast-radius) ("Linked invariants"), [16](dimensions.md#16-language-and-runtime-pitfalls) ("Values, references and aliasing"), [19](dimensions.md#19-lifecycle-and-resources), [14](dimensions.md#14-boundaries-numbers-and-text) ("Failure midway through parsing") |

## State, timing and paths

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Concurrency and interleaving** | Can the same object be reached by two execution flows at once (two writers, a read and a write at the same time, before and after a suspension point)? Can something get in between the check and the use? Can the intermediate state of a multi-step flow be exploited by concurrent requests? | The contract did not say "only one writer is allowed", and the implementation did not block it either | Linux AF_ALG allowed two writers to interleave, hidden for 14 years; a race between the limit check and the deduction; a race in the email verification flow | [18](dimensions.md#18-concurrency-and-memory-model), [9](dimensions.md#9-business-logic-and-flow-integrity) ("Timing and races") |
| **Assumptions broken by callbacks and reentrancy** | After a check, specialization or caching, was a callback, getter, user code or external contract called in between, or was there a write through an alias? Do the earlier assumptions (type, length, balance, permission, state) still hold? Are they checked again afterwards? If the context switched in the middle of processing (switching configuration by SNI, upgrading the protocol, switching tenant or account), are sizes, counts and permissions computed under the old context still usable? When the same value is evaluated twice, are the two results guaranteed to be the same? In the other direction, when a library, framework or engine calls back into our code, does our code replace or modify the context, configuration or collection that the caller is using? Does the caller's contract allow that? | The check and the use are in the same function and look "right next to each other"; the author of a callback only looks at their own side | V8 optimized code kept running with the old type after a callback changed the object; a contract updating the balance only after an external call (reentrancy); nginx switching configuration by SNI in the TLS handshake callback, allocating the extension array by the count before the switch and processing it by the count after the switch | [18](dimensions.md#18-concurrency-and-memory-model) ("Lock granularity and behavior while holding a lock"), [35](dimensions.md#35-dependencies) ("Understanding the contract"), [4.27](specialties.md#427-interpreters-compilers-and-virtual-machines) ("Assumptions behind speculative optimization"), [4.38](specialties.md#438-smart-contracts-and-on-chain-interaction) ("Reentrancy") |
| **States and phases** | In each state, can each entry point be called? Can phases such as initialization, installation, upgrade, shutdown, reconnection, and before and after authentication be reentered, skipped or run out of order? | The design only drew the normal order | The setup wizard can still be called again after it is finished; connection protocol messages were handled before authentication finished (Erlang/OTP SSH) | [12](dimensions.md#12-state-machines-and-transitions), [9](dimensions.md#9-business-logic-and-flow-integrity) |
| **Leftovers after cancellation and interruption** | After an operation is cancelled, times out, disconnects or exits abnormally midway, what state are the shared connections, buffers, locks, pooled objects and partly written state in? Can the next user (possibly a different user) go on to read what the previous one left behind? | Cancellation paths are rarely tested | After a redis-py command was cancelled, the connection was still reused, and ChatGPT showed users the titles of other people's conversations | [4.1](specialties.md#41-networking-and-connections) ("Connection state after cancellation"), [10](dimensions.md#10-apis-and-contracts) ("View lifetime"), [19](dimensions.md#19-lifecycle-and-resources), [25](dimensions.md#25-crash-and-recovery) |
| **Interpreting failures and special values** | How does the caller interpret each failure, error code and special return value (zero, negative, empty, sentinel value)? Is a three-state result tested as true or false? When one integer encodes several things at once (bit fields, a verdict plus an error code), do the producer and the consumer agree on the value range and how it is split? Can a failure end up treated as success and carry on? Can the other side deliberately cause this failure (exhaust memory, fill a queue, trigger a timeout)? When several checks write the same result, can the success of a later step turn the failure of an earlier step back into success? | The caller only handled the few return values it thought of | GnuTLS reporting a verification failure as success; OpenSSH treating only -1 as failure, so an attacker exhausted memory to produce -2 and bypass host key verification; one verdict value in nf_tables interpreted differently by different layers | [13](dimensions.md#13-error-handling-and-failure-semantics) ("Errors read as success", "Failures overwritten by later steps"), [29](dimensions.md#29-fail-safe-behavior-and-dangerous-operations) |
| **Fallbacks and rarely taken paths** | When the main path does not apply and the code takes a fallback, catch-all, degraded path, slow path or "no match" branch, were the lengths, states and results it uses computed on every path that leads there? Or does it use initial values? Do empty values, zero-length values, single elements and the first item from a cache or queue go through the same validation and constraints as ordinary values? | Tests always take the main path and ordinary values | glibc syslog's fallback branch allocating a buffer by the initial value 0; OpenSSL reading the first item when the client list is empty (CVE-2024-5535); kTLS not setting this call's content type on a zero-length first record from the cache queue (CVE-2025-39682) | [13](dimensions.md#13-error-handling-and-failure-semantics) ("Fallback branches"), [14](dimensions.md#14-boundaries-numbers-and-text) ("Empty and missing") |

## Consistency and completeness

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Consistency across sibling branches and similar entry points** | Do the sibling branches in the same switch, table or function, and the multiple entry points of the same kind (similar APIs, newly added functions, another request method, another encoding), all do the same set of checks? Does one of them do it while another does not? | Each branch looks "reasonable" on its own | glibc iconv checking capacity for only one kind of control sequence; Euler's newly added donate function lacking the health check that all the other functions had; authorization attached only to the detail API | [28](dimensions.md#28-authorization-and-access-control) ("Consistency across entry points"), [20](dimensions.md#20-resource-bounds-and-backpressure) ("Limits that cover every branch"), [3](dimensions.md#3-duplication) ("The same check scattered in many places"), [2.1](questions.md#21-for-each-public-entry-point) |
| **Shortcuts and fast paths** | Do fast paths, caches, batch processing and defaults added for performance or convenience skip the checks on the slow path? Can the exceptions that skip checks (particular identities, values, object states, markers) be created, claimed or kept up for a long time by the party being checked? | Tests of the fast path only check whether the result is right; exception conditions are assumed to be met only by the system itself | Bitcoin skipping the duplicate input check to speed things up; authentication results cached and then reused across contexts | [31](dimensions.md#31-performance-memory-and-latency) ("Optimized paths that skip validation"), [28](dimensions.md#28-authorization-and-access-control) ("Whether the restricted side can create or claim an exemption") |
| **Combinations of configuration and features** | Does the defect appear only when certain configuration options, modules, features or platforms are combined? Which combinations do the tests cover? | Each option was tested alone; the combinations were not | nginx overflowing when map is used together with regular expressions; paths reachable only when a certain module is enabled | [32](dimensions.md#32-configuration-and-defaults), [38](dimensions.md#38-portability-and-build-context) |
| **Conservation and invariants** | What rules in the system say "the total never changes" or "this always holds"? Does every path (including optimized paths, batch paths and special types) maintain them? Is there an independent reconciliation as a backstop? | Invariants are written only in the design, with no code guarding them | A Bitcoin amount overflow created coins out of thin air; DeFi share rounding let the first depositor swallow the funds of later depositors | [9](dimensions.md#9-business-logic-and-flow-integrity) ("Conservation of totals"), [2.3](questions.md#23-for-each-invariant-written-in-flow-documents-or-claimed-in-code-comments) |
| **Uniqueness and single use** | Do things that must be "only one" or "used only once" (nonces, tokens, authorization codes, nullifiers, idempotency keys, sessions, order numbers, control streams that are unique per connection) really have only one valid value and really get used only once? After one is closed or freed, can another one be created? Can the same object be registered, queued, called back or finished twice? If the cleanup path creates new objects or allocates resources, can that trigger reclamation, timeouts or callbacks that come back and close the object that is already being closed? When a section, block, header or field that the format or protocol says appears only once appears again, is the whole thing replaced, is it rejected, or is only part of the state overwritten? | Uniqueness relies on convention, not enforcement | Several nullifiers derived from the same note; GCM nonce reuse; duplicate submissions causing duplicate charges; nginx HTTP/3 allowing another encoder stream to be opened after the first one was closed; nginx posting the same subrequest twice and finishing it twice, freeing the main request early; nginx HTTP/3 creating a new stream while closing a stream, which triggered connection reclamation, which closed the same stream again, recursing without end; the nginx mp4 module not rejecting duplicate atoms, so buffers and counts came from different instances | [4.4](specialties.md#44-cryptography-and-credentials) ("Uniqueness and single use"), [19](dimensions.md#19-lifecycle-and-resources) ("Finishing twice", "Allocation in cleanup paths"), [4.3](specialties.md#43-decoding-untrusted-external-data) ("Repeated structures"), [23](dimensions.md#23-transactions-atomicity-and-consistency) |
| **Old valid versions accepted again** | Can things with valid signatures that are out of date (old firmware, old drivers, old tokens, old messages, old protocol versions, old configuration) be accepted again? ## Resources, externals and observability

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Cost asymmetry** | When the other side does something cheap, how much does our side pay? Can cancellation, reset, retry, decompression, backtracking, hash collisions or queued replies amplify the cost? | Capacity is estimated from normal traffic | HTTP/2 Rapid Reset; OpenSSH queuing a reply for every PING during key exchange; regular expression backtracking taking down a global service | [20](dimensions.md#20-resource-bounds-and-backpressure) |
| **Lifetime of referenced names** | For external resources referenced by name in code, configuration, documents and DNS (domains, subdomains, storage buckets, package names, repository paths, the domain of a maintainer's email): after the original owner deletes them, renames them or lets them expire, can someone else register them and take over? | Once a reference is written down, no one looks at it again | Subdomains pointing to deleted cloud resources were taken over; the domain of the PyPI ctx maintainer's email expired and was registered by someone else, who reset the password and published a malicious version | [36](dimensions.md#36-supply-chain-and-artifact-integrity) ("Names re-registered after they lapse"), [Targets that are not source code: Live services](targets.md#live-services) |
| **Authenticity of identities and addresses** | How is the other side's identity or address confirmed? Can the source address, host name, certificate, signer or process ID be forged or misused? | Network-layer addresses or process IDs are treated as identity | HTTP/3 address spoofing; an XPC service identifying callers by process ID, defeated by process ID reuse | [4.1](specialties.md#41-networking-and-connections), [4.28](specialties.md#428-tunnels-proxies-and-the-network-data-plane), [4.47](specialties.md#447-local-privileged-components-and-local-privilege-escalation) ("Caller identity") |
| **Observable differences** | Can different secrets or different failure reasons cause observable differences (timing, error messages, length, caching, power use, load results that can be observed cross-site)? | Functional tests do not look at these differences | Padding oracles; the length of a signature nonce leaking through timing; cross-site leaks | [4.4](specialties.md#44-cryptography-and-credentials) ("Oracles and observable differences", "Constant time and side channels"), [4.14](specialties.md#414-server-request-handling-and-middleware) ("Cross-site leaks and request origin") |
| **Where secrets and data flow** | Where can secrets and sensitive data flow: logs, errors, responses, buffers that are not zeroed, dumps, caches, command-line arguments, bundles shipped to clients, third parties? | The leak happens in side effects, not in the main logic | An nginx module leaking memory contents into responses; uninitialized stack memory echoed back when an input field is missing (CitrixBleed 2) | [30](dimensions.md#30-privacy-data-governance-and-compliance), [4.4](specialties.md#44-cryptography-and-credentials) ("Credential exposure", "Secrets in memory") |
| **What is shown versus what is used** | Is what is shown to people the same thing that the program actually executes, signs, opens or clicks? ## Process

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Fixes and regressions** | Do fixed issues have regression tests? Does the fix only block the sample input? Is the same root cause still present at other entry points? **Which branches did the fix or refactor add, and which guards did it remove** (conditional compilation, macro switches)? Do the new branches get the same checks and tests?
