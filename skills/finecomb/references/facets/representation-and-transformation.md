# Representation and transformation

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Multiple representations of the same fact** | Does the same value, path, identity or encoding have more than one way to write it? Is the form used for validation the same as the form finally used? Does writing it out and reading it back give the original value? Do the side that escapes or validates and the side that finally interprets split the input into characters and tokens with the same character encoding and the same rules (multibyte encodings, quoting rules, dialects)? | Two components are each "correct", but understand the input differently when combined | Paths validated before decoding; an array parameter sending the reset email to a second address; both x and x plus the modulus pass verification; Git writing configuration without quotes and dropping the carriage return when reading it back | [27](../dimensions/27-security-and-trust-boundaries.md) ("Parser differentials"), [24](../dimensions/24-encoding-and-persistent-formats.md) ("Round trip and canonical form"), [4.17](../specialties/4.17-templates-and-text-output.md) ("Escaping under multibyte encodings") |
| **Transformations after validation** | After validation, does the value still go through decoding, normalization, character set conversion, command-line reassembly, template expansion or another parser? Is what validation sees the same as what finally runs? | Validation and use are in two places, and no one watches the transformation in between | Windows best-fit character set mapping turns a soft hyphen into `-` (PHP-CGI); calling a batch file with an argument array is still re-parsed by `cmd.exe` (BatBadBut) | [4.22](../specialties/4.22-subprocesses-dynamic-execution-and-decoder-side-effects.md) ("Windows command-line reassembly", "Character set conversion rewriting arguments"), [27](../dimensions/27-security-and-trust-boundaries.md) ("Input validation") |
| **Processing path chosen by input** | Is the parser, handler or branch chosen by an attribute the request controls (content type, extension, parameter, version number)? Can a different representation skip the path that does sanitizing or limiting, while still reaching the later point of use? | Each path has checks when looked at alone | Changing the content type bypassed the upload sanitizer (n8n) | [4.3](../specialties/4.3-decoding-untrusted-external-data.md) ("Format confusion", "Handler chosen by the request"), [4.21](../specialties/4.21-outbound-requests-and-server-side-request-forgery.md) ("Protocol restrictions") |
| **Data turning into instructions** | Which places that interpret external data will it finally reach (queries, commands, templates, expressions, protocol headers, configuration, log lookups, next-hop requests, line-based internal protocols)? Can connection strings, driver parameters or argument-parsing libraries interpret a value as a command, a script or a file read? When a value is spliced in, does it have its own boundaries, and can its first and last characters combine with the template characters before and after it into new tokens? Is it stored somewhere first along the way and later spliced in elsewhere? | The first use is safe; protection is lost on second use or forwarding | Log4Shell; a session ID becomes a file name and then goes into a shell; nginx injecting request content into upstream or mail authentication requests; newline injection into memcache commands | [27](../dimensions/27-security-and-trust-boundaries.md) ("Injection surface", "Second-order use"), [4.22](../specialties/4.22-subprocesses-dynamic-execution-and-decoder-side-effects.md), [4.17](../specialties/4.17-templates-and-text-output.md) ("Boundaries at the insertion point"), [4.7](../specialties/4.7-databases-and-queries.md) ("Connection strings and driver parameters"), [4.15](../specialties/4.15-command-line-and-process-entry-points.md) ("Implicit expansion by argument-parsing libraries") |
| **Protocol and format conversion** | When converting between two protocols, two encodings or two versions, which semantics are lost and which new semantics are introduced? Is a character that is legal in the first one a delimiter in the second? Do upstream and downstream agree on terminators and lengths? Do both sides agree whether a write is an incremental change or a full replacement? When only the changes are synced into a copy that gets overwritten as a whole, can the unchanged parts be lost, or deleted things come back? | Each protocol is right on its own; no one owns the conversion layer | Injection when HTTP/2 requests are converted to HTTP/1 for the upstream; after a proxy removes hop-by-hop headers, the backend trusts the request as local; SMTP smuggling | [4.14](../specialties/4.14-server-request-handling-and-middleware.md), [4.2](../specialties/4.2-protocols-and-frame-parsing.md), [37](../dimensions/37-interoperability-and-coexistence.md), [23](../dimensions/23-transactions-atomicity-and-consistency.md) ("Incremental sync into a copy that is overwritten whole"), [4.6](../specialties/4.6-caching-and-storage.md) ("Deletion and resurrection") |
| **Which attributes survive a move** | When an object is copied, unpacked, mounted, imported, converted, saved as another file, forwarded or mapped across namespaces, are **restricting attributes** (download origin marks, taint, data classification, quarantine attributes) kept, and are **privilege attributes** (setuid, capabilities, owner, signed status) stripped or checked again? Can boundary values (unmapped users, default identities) fall into a special case that "neither errors nor strips"? If a mark cannot be written, is the object still let through? In multi-step chains (redirects, forwarding, delegation, privilege dropping), does the stripping or narrowing done at an earlier step still hold at every later step? Is each step derived from the result of the previous step, or copied from the original object again? | Attributes are checked only once, at the first step; the check only compares two adjacent steps | Unpacking nested archives did not pass on the download origin mark (7-Zip); a restrictive ACL kept the quarantine attribute from being written (macOS); OverlayFS kept setuid when copying (CVE-2023-0386) | [4.35](../specialties/4.35-client-apps-extensions-and-auto-update.md) ("Download origin marks"), [27](../dimensions/27-security-and-trust-boundaries.md) ("Attributes carried across boundaries", "Narrowing across multi-step chains"), [4.21](../specialties/4.21-outbound-requests-and-server-side-request-forgery.md) ("Credentials across redirect chains"), [4.8](../specialties/4.8-file-systems-and-paths.md) |
| **Completeness of equivalence checks** | Does every judgment that "these two are the same, so we can skip, merge, reuse or prune" (equality comparisons, cache keys, deduplication keys, memoization, state merging, verifier pruning) include every field that affects the result and security? If two things that are not equivalent are judged equivalent, which check is skipped and whose data is returned? | Equivalence checks are written for performance and are not treated as security logic | The eBPF verifier judged states with different safety properties as equivalent and pruned a dangerous path (CVE-2023-2163); a cache key missing the tenant or permission field | [15](../dimensions/15-algorithm-and-data-structure-correctness.md) ("Identity normalization"), [4.6](../specialties/4.6-caching-and-storage.md) ("Cache keys and isolation"), [4.27](../specialties/4.27-interpreters-compilers-and-virtual-machines.md) ("Compilation cache"), [4.1](../specialties/4.1-networking-and-connections.md) ("Connection pools"), [36](../dimensions/36-supply-chain-and-artifact-integrity.md) ("Build cache and artifact substitution") |
| **Consistency of types and tags** | In how many places is the type of the same field or object declared (struct definition, encoding and decoding template, comparison, copy, free, union tag)? Do they all agree? Which one does the reader go by? Is anything used as a certain type without checking the tag? | The type "looks like" it has only one definition | OpenSSL's X.400 address had different types in the struct and in the parsing template (CVE-2023-0286); type confusion after V8 optimization | [16](../dimensions/16-language-and-runtime-pitfalls.md) ("Undefined behavior and memory safety"), [4.27](../specialties/4.27-interpreters-compilers-and-virtual-machines.md) |
