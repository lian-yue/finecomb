# Resources, externals and observability

| Facet | Question to ask | Why it is often missed | Real cases | Detailed criteria |
| --- | --- | --- | --- | --- |
| **Cost asymmetry** | When the other side does something cheap, how much does our side pay, and how much does a third party pay when our replies go to an address the requester chose or forged? Can cancellation, reset, retry, decompression, backtracking, hash collisions or queued replies amplify the cost? After a limit trips, does the work stop, or does the code keep reading and decoding the rest? Is input already examined scanned again each time more arrives? | Capacity is estimated from normal traffic; costs paid by others, or spread across many calls, are not counted | HTTP/2 Rapid Reset; OpenSSH queuing a reply for every PING during key exchange; regular expression backtracking taking down a global service | [20](../dimensions/20-resource-bounds-and-backpressure.md) ("Work after a limit is exceeded", "Work repeated across incremental input", "Can the bound be computed"), [4.28](../specialties/4.28-tunnels-proxies-and-the-network-data-plane.md) ("Open relay and reflection amplification") |
| **Which candidate a name resolves to** | When one name can resolve to several candidates (search paths for executables and dynamic libraries, PATH, the resolution order of modules and packages, public and private registries, layers of configuration files and environment variables, class paths, the lookup order of templates and resources, DNS search suffixes, property lookup along the prototype chain), which one is finally used? Can an attacker put a candidate with the same name in a place with higher priority? When nothing is found, does the lookup fall back to a place others can write to? | In a normal environment there is only one candidate, so "which one" never comes up | A Windows service loading a same-named DLL from a user-writable directory through the search order; a build pulling a package from the public registry with the same name as an internal package; a same-named module in the current directory imported first | [4.47](../specialties/4.47-local-privileged-components-and-local-privilege-escalation.md) ("Executable paths and load order"), [36](../dimensions/36-supply-chain-and-artifact-integrity.md) ("Dependency confusion"), [32](../dimensions/32-configuration-and-defaults.md) ("Source precedence"), [Targets that are not source code: Compiled artifacts and binaries](../targets/compiled-artifacts-and-binaries.md), [4.15](../specialties/4.15-command-line-and-process-entry-points.md) ("Configuration discovery"), [Python](../lang-python.md) ("Imports and paths"), [16](../dimensions/16-language-and-runtime-pitfalls.md) ("Module loading and initialization") |
| **Lifetime of referenced names** | For external resources referenced by name in code, configuration, documents and DNS (domains, subdomains, storage buckets, package names, repository paths, the domain of a maintainer's email): after the original owner deletes them, renames them or lets them expire, can someone else register them and take over? | Once a reference is written down, no one looks at it again | Subdomains pointing to deleted cloud resources were taken over; the domain of the PyPI ctx maintainer's email expired and was registered by someone else, who reset the password and published a malicious version | [36](../dimensions/36-supply-chain-and-artifact-integrity.md) ("Names re-registered after they lapse"), [Targets that are not source code: Live services](../targets/live-services.md) |
| **Authenticity of identities and addresses** | How is the other side's identity or address confirmed? Can the source address, host name, certificate, signer or process ID be forged or misused? | Network-layer addresses or process IDs are treated as identity | HTTP/3 address spoofing; an XPC service identifying callers by process ID, defeated by process ID reuse | [4.1](../specialties/4.1-networking-and-connections.md), [4.28](../specialties/4.28-tunnels-proxies-and-the-network-data-plane.md), [4.47](../specialties/4.47-local-privileged-components-and-local-privilege-escalation.md) ("Caller identity") |
| **Values that must not be guessable** | Which security decisions rely on "the other side cannot guess this value": session IDs, tokens, reset codes, verification codes, keys, seeds, salts, IVs, signature nonces, temporary file names, random delimiters and boundary markers, identifiers exposed to the outside, protocol transaction IDs and source ports, draw results? Does the value come from a cryptographic random source, or from the time, a process ID, a counter, a memory address, an ordinary pseudo-random generator or input the other side can influence? Is entropy lost when the value is truncated, reduced modulo, encoded or only partly used? When the random source fails or is never seeded, or after a fork, a virtual machine snapshot, a copied image or a restart, can the same sequence come out again? Can other outputs of the same random source, the generation time, the length or a time part inside an identifier let someone work it out? | Tests only check "no repeats"; nobody tests "can it be guessed"; the random value comes from a general helper, and the caller does not know it is not a cryptographic random source | Debian OpenSSL left with only the process ID as entropy; the top 9 bits of PuTTY's P-521 signature nonces always 0; the Kaminsky attack guessing DNS transaction IDs; on-chain code using the block timestamp or block hash as a random source | [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Randomness and unpredictability"), [15](../dimensions/15-algorithm-and-data-structure-correctness.md) ("Identifier generation"), [15](../dimensions/15-algorithm-and-data-structure-correctness.md) ("Modulo bias"), [4.1](../specialties/4.1-networking-and-connections.md) ("Self-implemented name resolution"), the "Random numbers" and "Randomness" rows of the language tables, [4.17](../specialties/4.17-templates-and-text-output.md) ("Boundaries at the insertion point") |
| **Observable differences** | Can different secrets or different failure reasons cause observable differences (timing, error messages, length, caching, power use, load results that can be observed cross-site)? | Functional tests do not look at these differences | Padding oracles; the length of a signature nonce leaking through timing; cross-site leaks | [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Oracles and observable differences", "Constant time and side channels"), [4.14](../specialties/4.14-server-request-handling-and-middleware.md) ("Cross-site leaks and request origin"), [4.5](../specialties/4.5-authentication-sessions-and-tokens.md) ("Account enumeration"), [9](../dimensions/9-business-logic-and-flow-integrity.md) ("Enumeration leaks") |
| **Where secrets and data flow** | Where can secrets and sensitive data flow: logs, errors, responses, buffers that are not zeroed, dumps, caches, command-line arguments, bundles shipped to clients, third parties? When a file is overwritten in place, or an image or document is edited, cropped or redacted, can old or removed content remain in the saved output? | The leak happens in side effects, not in the main logic | An nginx module leaking memory contents into responses; uninitialized stack memory echoed back when an input field is missing (CitrixBleed 2) | [30](../dimensions/30-privacy-data-governance-and-compliance.md), [4.4](../specialties/4.4-cryptography-and-credentials.md) ("Credential exposure", "Secrets in memory"), [4.8](../specialties/4.8-file-systems-and-paths.md) ("Overwriting in place") |
| **What is shown versus what is used** | Is what is shown to people the same thing that the program actually executes, signs, opens or clicks? Can UI injected into someone else's page be covered or made transparent, so that clicks land somewhere else? Can values the other side controls carry control characters or terminal escape sequences that change what a prompt or confirmation shows? | The human confirmation step is treated as the last line of defense | Bybit's signing screen showed a transfer while what was actually signed was a contract upgrade; spaces in WinRAR file names; autofill UI injected by password manager extensions made transparent by the host page | [27](../dimensions/27-security-and-trust-boundaries.md) ("What is shown differs from what is used"), [4.43](../specialties/4.43-wallets-signing-and-off-chain-components.md), [4.18](../specialties/4.18-user-interfaces-and-accessibility.md) ("Injected UI covered by the host page"), [4.17](../specialties/4.17-templates-and-text-output.md) ("Line breaks and encoding") |
