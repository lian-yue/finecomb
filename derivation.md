# Derivation round

This record lists the **derivation samples**: real vulnerabilities used to find gaps and write the root-cause facets while the skill was being written. They are not held-out samples. Every root cause they missed has since become a facet or checkpoint, and those rows were worded from these very samples. So **a hit on these samples now only shows that the gap was filled; it does not show that the skill generalizes**. For generalization, see the samples that were not used to write the skill: [Held-out round 1](holdout-1.md) and [Held-out round 2](holdout-2.md).

## What this round is

- Test date: 2026-09-24.
- The skill under test was the Chinese skill `skills/finecomb-zh/` as it stood at the time. The skill kept changing during the tests, so each group saw a different version; see the "Snapshot at the time" column in the statistics.
- Each group was run by one read-only subagent: it first took the root cause from the patch, the official advisory or a credible analysis, then judged the sample. Zcash Orchard was judged by the main agent itself.
- Row names use the corresponding names in the English skill `skills/finecomb/`. Where the original record wrote a `4.x` specialty as `dimensions.md §4.x`, it is written here as specialties by its number.

## Judging rules

- The question asked was: when reviewing this code by following the skill, does some row ask a question whose answer directly exposes the defect?
- **Hit**: a row names the specific mechanism the defect belongs to. "Hit (weak)" counts as a hit and means the row needs a small step of inference to match.
- **Partial**: only a general direction, or the right row sits where a reviewer of this kind of code would not pick it.
- **Missed**: no row points to it.
- Which columns were used: the nginx group explicitly used only the facets' "Question to ask" column and the checkpoint columns of the other tables, and no case column. The prompts of the other groups did not restrict columns, and one Linux judgment cites a history row that already listed the same case (CVE-2022-0847). In this respect the derivation round was looser than the two held-out rounds.
- "Rows hit or gap at the time" follows the original record. "Where the gap was fixed" gives the real row names in the current skill, checked with `rg` by concept.

## Using these records

When a vulnerability is missed later, first search this record and the held-out records in the same directory by ID, product or component, for example `rg -F 'CVE-2024-1086' .` in a checkout of this branch, to see how it or a similar sample was judged. Then use the "Rows hit or gap at the time" and "Where the gap was fixed" columns to find the matching rows in the skill, compare them with the root cause that was missed, and decide whether a facet is missing, a specific checkpoint is missing, or the row exists but is worded too narrowly or not linked. Derivation samples were written into the skill on purpose, so their hits cannot be used to argue that new samples will also be hit.
