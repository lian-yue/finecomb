# Held-out round 2

This record lists all 80 samples of held-out round 2, so they can be looked up later by ID, component or root-cause facet. The summary numbers are in the main README under [How coverage is validated](https://github.com/lian-yue/finecomb#how-coverage-is-validated).

## What this round is

- Held-out samples: 8 domains with 10 vulnerabilities each, none of them used to write the skill. Each sample's ID and event name was searched for in the skill directory and in the notes of earlier test rounds, and none appeared. They count toward the held-out statistics in the main README.
- Test date: 2026-09-24. The skill under test was the Chinese skill `skills/finecomb-zh/` as it stood then (the notes record file modification times between 22:47 and 23:20). Row names below use the corresponding names in the English skill `skills/finecomb/`.
- This round first included two other domains, "Network devices and embedded systems" and "Cloud native and supply chain", but the test agents for both were stopped by a safety classifier and produced no samples; the domains were then narrowed to "Open-source databases, storage and messaging" and "Open-source cloud-native components and build tools" and rerun, which are the two sections below.
- Root causes: each domain was covered by one read-only research agent working from patches, official advisories or credible post-mortems. Each root cause is one sentence at the patch or advisory level, with no exploitation steps. Links recorded in the notes are in the Sources column; where the notes kept no link, only the ID or the source name is given.
- Alternate samples: in some domains a few vulnerabilities were checked during sample selection but not chosen. They are listed after that domain's table, outside the table and the counts.

## Judging rules

- Only the "Question to ask" column of the root-cause facets (`facets.md`) and the "Checkpoint", "How to check" and "What counts as a problem" columns of the tables in `dimensions/`, `specialties/`, `targets/` and `lang-*.md` are used.
- No "Real cases" or "Historical cases" column is used, and neither is `history/`.
- Hit: following some row's question leads directly to the root cause.
- Weak hit: existing rows do reach the root cause, but the wording is not direct and the reviewer has to recognize it. Still counted as a hit, written "Hit (weak)" in the tables.
- Partial: the rows only point in the general direction; the reviewer still has to take another step on their own.
- Missed: no row leads to the root cause.
- Row names are the names at test time, written as "file + facet or checkpoint name"; all of these rows are still in the current skill under the same names.
